#难度/★★

> 把"值域大但实际只用到少数取值"的数据压缩到 $[1, n]$ 范围——让用值域作下标的算法重新可行。

## 核心思想

很多算法（权值线段树、树状数组求逆序对、值域分块……）的下标是"值"本身——若值域 $V$ 很大（如 $10^9$）就根本开不下数组。但实际上，一道题里出现的不同值往往很少（如 $n \le 10^5$ 个）。

**离散化**的核心思想：

> 数组的实际信息只取决于元素之间的"相对大小关系"，不依赖绝对值。所以可以把每个值替换为它在"排序去重"后的序列中的位置（rank）——值域瞬间从 $V$ 压到 $n$。

具体步骤：

1. 复制原数组到 `values[]`

2. 排序：$\mathtt{sort}(\mathtt{values})$

3. 去重：$\mathtt{unique}$ + $\mathtt{erase}$

4. 查询某原始值 $x$ 的离散化结果：用二分（$\mathtt{lower\_bound}$）找它在 `values` 中的位置

例如原数组 `[100, 5, 100, 200, 5]`——离散化后映射为 `[2, 1, 2, 3, 1]`。

**关键限制**：离散化只保留"$<, =, >$"关系，**不保留"差值"**。所以"求两个值的差""按值的真实距离做加权"等场景不能直接离散化（除非把"原值"也额外保存，离散化后只用作下标）。

## 适用场景

- **权值数据结构**：[[树状数组]] / [[线段树]] 维护"值域信息"时，先离散化把值域压到 $[1, n]$

- **求逆序对**：值域大时用"离散化 + BIT"经典套路

- 区间端点值域大但端点种类少的问题

- 任何"算法只依赖大小关系，不依赖差值"的场景

- **"映射"类问题**：把任意可比较的对象（字符串、坐标等）转化为整数下标

- 不适用：值域已经很小（直接当下标，省去离散化）；需要保留差值精度的问题

## 步骤拆解

1. **收集**：把所有"将作为下标的值"放入数组 `values`

2. **排序**：`sort(values.begin(), values.end())`

3. **去重**：`values.erase(unique(values.begin(), values.end()), values.end())`

4. **查询**：用 `lower_bound` 二分找原始值的下标位置，得到离散化结果（通常 $+1$ 让下标从 1 开始）

## 代码模板

**模板一：通用离散化类**

```cpp
class discretize {

private:

    vector<long long> values;

public:

    discretize(vector<long long>& a) {

        values = a;

        sort(values.begin(), values.end());

        values.erase(unique(values.begin(), values.end()), values.end());

    }

    // 查询原始值 x 离散化后的下标（从 1 开始）
    int get(long long x) {

        return lower_bound(values.begin(), values.end(), x) - values.begin() + 1;

    }

    // 离散化后的值域大小
    int size() {

        return values.size();

    }

    // 由离散化下标反查原值
    long long original(int idx) {

        return values[idx - 1];

    }

};
```

**模板二：求逆序对（最经典应用）**

```cpp
// 给定数组 a[1..n]，求逆序对数量

long long count_inversions(vector<long long>& a) {

    int n = a.size() - 1;

    discretize d(a);

    int m = d.size();

    vector<long long> bit(m + 1, 0);                // 树状数组

    auto lowbit = [](int x) { return x & -x; };

    auto update = [&](int i) {

        while (i <= m) {

            bit[i] += 1;

            i += lowbit(i);

        }

    };

    auto query = [&](int i) {

        long long sum = 0;

        while (i > 0) {

            sum += bit[i];

            i -= lowbit(i);

        }

        return sum;

    };

    long long ans = 0;

    for (int i = n; i >= 1; i--) {

        int idx = d.get(a[i]);

        ans += query(idx - 1);                      // 比 a[i] 小且在它右边的元素数

        update(idx);

    }

    return ans;

}
```

> 💡 **为什么从右往左扫**：从右往左时，BIT 中的元素都是"在 $a[i]$ 右侧的"。`query(idx - 1)` 即"右侧比 $a[i]$ 严格小"的个数——这正是 $a[i]$ 贡献的逆序对数。

**模板三：保留索引的离散化（处理重复元素时区分先后）**

某些题目需要"相同值的元素也分先后"（如逆序对要求严格小于但相同值不算）。可以把每个值打成 `(value, original_index)` 的二元组排序：

```cpp
vector<pair<long long, int>> with_idx(n + 1);

for (int i = 1; i <= n; i++) {

    with_idx[i] = {a[i], i};

}

sort(with_idx.begin() + 1, with_idx.end());

vector<int> rank_of(n + 1);

for (int i = 1; i <= n; i++) {

    rank_of[with_idx[i].second] = i;                // 第 i 小的位置 → 排名 i

}

// rank_of[i] 即 a[i] 的离散化结果，且相同值按原下标分先后
```

> ⚠️ **`unique` 的前提是已排序**：`unique` 只去除相邻重复元素，所以必须先 `sort`。

> 💡 **`lower_bound` vs `upper_bound`**：离散化查询用 `lower_bound`——它返回"第一个不小于 $x$ 的位置"。在去重数组中即 $x$ 的位置（$x$ 必然存在，因为离散化的值就是原值）。

## 复杂度分析

- 预处理：$O(n \log n)$（排序）

- 单次查询：$O(\log n)$（二分）

- 空间：$O(n)$

## 正确性证明

### 离散化保留大小关系

**核心定理**：设 `values` 是原数组排序去重后的有序序列。对任意两个原始值 $x, y$ 都有：

$$x < y \;\Leftrightarrow\; \mathtt{get}(x) < \mathtt{get}(y), \quad x = y \;\Leftrightarrow\; \mathtt{get}(x) = \mathtt{get}(y)$$

**证明**：

`values` 已严格升序（去重）。$\mathtt{get}(x) = $ "$x$ 在 `values` 中的下标"——是 `values` 中**唯一**等于 $x$ 的位置。

若 $x < y$，由 `values` 升序，$x$ 在 `values` 中的位置严格小于 $y$ 的位置——即 $\mathtt{get}(x) < \mathtt{get}(y)$。等号成立同理。$\blacksquare$

### 算法正确性的可移植性

**命题**：任何"只通过比较 $<, =, >$ 操作输入元素"的算法，对原数组 $a$ 和离散化后的数组 $a'$ 给出**逻辑等价的结果**。

**证明**：算法的所有比较操作的结果在 $a$ 和 $a'$ 上完全一致（由上述保留性）——所以算法在两个数组上的执行轨迹一致，输出"等价"（如逆序对数完全相同；如排序结果对应的位置变化完全相同）。$\blacksquare$

**这就是离散化能"无损"压缩的原因**——只要算法的逻辑只依赖比较结果。

### 何时不能离散化

**反例**：要求"求所有元素与中位数的差的绝对值之和"。

离散化后元素变成 $1, 2, 3, \ldots$，差值结构被破坏——原本相距 $100$ 的两元素离散化后可能相距 $1$。

**判断标准**：算法是否调用了"减法、乘法、除法"等运算？若是，离散化可能破坏正确性。**比较和相等**则总是安全的。

**经验**：题目中出现"权值线段树""按值映射""值域大但元素少"等关键词时，第一反应就是离散化。
