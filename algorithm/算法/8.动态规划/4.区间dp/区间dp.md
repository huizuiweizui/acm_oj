#难度/★★★

> 状态在"区间"上推进——$f[l][r]$ 表示 $[l, r]$ 的最优解，转移枚举分割点 $k$，合并两个子区间。遍历必须**按区间长度从小到大**，这是它最显著的标志。

## 核心思想

区间 dp 的标志是——状态是一**对端点** $(l, r)$，$f[l][r]$ 表示对区间 $[l, r]$ 的某种最优值。当原问题"对整段 $[1, n]$ 求解"可以通过"在某个分割点 $k$ 处把区间一分为二、分别求解再合并"得到时，区间 dp 就是天然选择。

**经典例题——石子合并**：

> 有 $n$ 堆石子排成**一排**，第 $i$ 堆有 $a_i$ 颗。每次可以合并**相邻两堆**，代价为合并后那堆的石子数（即两堆之和）。求把所有石子合并成一堆的最小总代价。

**状态怎么想**：注意"相邻"这个约束——不能像哈夫曼编码那样自由挑两堆，每次只能选相邻两堆。这意味着合并过程在序列上具有"区间不可跨越"的结构。

观察任何合法的合并过程：每次合并都会把"相邻两堆"变成"一堆"——所以**整个合并过程的某个中间状态，必然是把 $[1, n]$ 分成若干段、每段已被合并为一堆**。最终把 $n$ 个段合成 1 段，必然经过"把若干段合成 1 段"的中间过程。

聚焦到"最后一次合并"——它必然是把 $[1, k]$ 合并出的一堆与 $[k+1, n]$ 合并出的一堆合二为一。这一步的代价是 $\sum_{i=1}^{n} a_i$（两堆之和恰是整个区间之和）。在这一步之前的所有代价，分别来自"把 $[1, k]$ 合成一堆的子问题"与"把 $[k+1, n]$ 合成一堆的子问题"——**两个子问题与原问题同形**！

这激发我们定义：

$$f[l][r] = \text{把区间 } [l, r] \text{ 内所有石子合并成一堆的最小代价}$$

这个定义具有**最优子结构**——大区间的最优合并方案可以分解为两个子区间各自的最优合并方案加上最后一步合并。**无后效性**也成立——子区间内部怎么合并不影响外部，只要最终它们各合成一堆即可。

**转移怎么推**：枚举"最后一次合并的分界点 $k$"——把 $[l, r]$ 在 $k$ 与 $k+1$ 之间断开：

$$f[l][r] = \min_{l \le k < r} \left( f[l][k] + f[k+1][r] \right) + \mathtt{sum}(l, r)$$

其中 $\mathtt{sum}(l, r) = \sum_{i=l}^{r} a_i$——最后一步合并的代价。用前缀和 $O(1)$ 算。

**边界**：$f[i][i] = 0$（单堆无需合并）。

**答案**：$f[1][n]$。

> 💡 **"最后一次合并的分界点"是区间 dp 的灵魂**：和 [[线性dp]] 中"最后一步决策"一样，把"最后一步"独立出来分类讨论是 dp 设计的通用技巧——区间 dp 中"最后一步"特指**最后一次合并 / 最后一次分割**。

### 遍历顺序：按区间长度递增

$f[l][r]$ 依赖 $f[l][k]$ 和 $f[k+1][r]$——它们的区间长度都**严格小于** $r - l + 1$。这就要求遍历时**先算所有短区间、再算长区间**。

最自然的写法是**按区间长度 $\mathtt{len}$ 从 2 到 $n$ 循环**：

```cpp

for (int len = 2; len <= n; len++) {          // 区间长度

    for (int l = 1; l + len - 1 <= n; l++) {  // 左端点

        int r = l + len - 1;

        for (int k = l; k < r; k++) {         // 分割点

            f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r]);

        }

        f[l][r] += sum_range(l, r);           // 加上本次合并代价

    }

}

```

> ⚠️ **千万别按 `l` 和 `r` 的双重循环写**：若外层 $l$ 内层 $r$，访问 $f[l][k]$ 时 $k > l$ 但 $r - l + 1 > k - l + 1$ 不一定满足——总之子区间可能没算过，得到错误结果。**外层必须是 $\mathtt{len}$**。

## 适用场景

- 操作具有"区间结构"——子问题在区间上、合并需要相邻

- 经典模型：石子合并、矩阵链乘法、最长回文子序列、回文划分、字符串压缩

- 代价函数依赖整个区间（如区间和、区间最值）的最优合并/分割问题

- 不适用：操作没有"区间不可跨越"的结构（哈夫曼那种自由两两合并用 [[堆]]）；区间数量过大需更高级技巧（如四边形不等式优化）

## 步骤拆解

1. **判断是不是区间 dp**：问题在序列上、子结构是"小区间"

2. **设状态** $f[l][r]$ —— 表示对区间 $[l, r]$ 的最优值

3. **想"最后一步"**：最后一次合并/分割的位置 $k$ 是什么

4. **写转移**：枚举 $k$，合并两子区间，加上"本次"代价

5. **边界**：$f[i][i] = $ 平凡值（通常 0、1，或元素本身）

6. **遍历**：外层 $\mathtt{len}$ 从小到大，内层 $l$，再内层 $k$

7. **答案**：$f[1][n]$
## 代码模板

**模板：石子合并**

```cpp

class stone_merge {

private:

    int n;

    vector<long long> a;                                // 1-indexed

    vector<long long> presum;                           // 前缀和

    vector<vector<long long>> f;

    long long sum_range(int l, int r) {

        return presum[r] - presum[l - 1];

    }

public:

    stone_merge(int n_in, const vector<long long>& a_in) {

        n = n_in;

        a = a_in;

        presum.assign(n + 1, 0);

        for (int i = 1; i <= n; i++) {

            presum[i] = presum[i - 1] + a[i];

        }

        f.assign(n + 1, vector<long long>(n + 1, 0));

    }

    long long solve() {

        for (int len = 2; len <= n; len++) {

            for (int l = 1; l + len - 1 <= n; l++) {

                int r = l + len - 1;

                f[l][r] = LLONG_MAX;

                for (int k = l; k < r; k++) {

                    f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r]);

                }

                f[l][r] += sum_range(l, r);

            }

        }

        return f[1][n];

    }

};
```

> 💡 **`f[l][r] = LLONG_MAX` 初始化要在内循环之前、分割点循环之外**——否则若忘记初始化或在错误位置初始化，分割点的 $\min$ 会失效。

## 复杂度分析

- 时间复杂度：$O(n^3)$

  - $O(n^2)$ 个状态（所有 $1 \le l \le r \le n$ 的对）

  - 每个状态 $O(n)$ 枚举分割点

- 空间复杂度：$O(n^2)$（无法滚动——状态间依赖关系是"网"状，不是"链"状）

> 💡 **$O(n^3)$ 的常数较大**——$n = 1000$ 是石子合并 dp 的常见上限。$n$ 再大需要更高级的优化（如 GarsiaWachs $O(n \log n)$ 算法，或四边形不等式优化把 $O(n^3)$ 降到 $O(n^2)$）。

## 正确性证明

### 最优子结构

**命题**：$f[l][r]$ 的最优合并方案中，对某个分割点 $k^*$，"先把 $[l, k^*]$ 合并成一堆、再把 $[k^*+1, r]$ 合并成一堆、最后两堆合并"是该方案的等价描述；且对 $[l, k^*]$ 和 $[k^*+1, r]$ 的部分都是各自的最优方案。

**证明**：

**等价描述存在**：考察最优方案中**最后一次合并**——它必然是把某两堆合并。这两堆中靠左的一堆覆盖了 $[l, k^*]$ 中所有原始堆（$k^*$ 是其右端），靠右的覆盖 $[k^*+1, r]$（这是因为合并过程中每堆都对应一个连续区间，且"最后一步前的两堆"必是 $[l, k^*]$ 与 $[k^*+1, r]$ 这种连续划分）。

**子方案最优**：若 $[l, k^*]$ 的合并代价不是最优的（即 $> f[l][k^*]$），那把这部分替换为 $f[l][k^*]$ 对应的方案，整体代价减小——与原方案"最优"矛盾。所以 $[l, k^*]$ 的部分代价等于 $f[l][k^*]$。$[k^*+1, r]$ 同理。$\blacksquare$

### 转移方程正确

**命题**：$f[l][r] = \min_{l \le k < r} (f[l][k] + f[k+1][r]) + \mathtt{sum}(l, r)$。

**证明**：

**$\le$ 方向**：对任一 $k \in [l, r-1]$，取 $[l, k]$ 的最优方案（代价 $f[l][k]$）+ $[k+1, r]$ 的最优方案（代价 $f[k+1][r]$）+ 最后一步合并（代价 $\mathtt{sum}(l, r)$）——这是 $[l, r]$ 的一个合法方案，所以 $f[l][r] \le f[l][k] + f[k+1][r] + \mathtt{sum}(l, r)$。对所有 $k$ 取 $\min$ 即可。

**$\ge$ 方向**：由"最优子结构"的论证，$f[l][r]$ 的最优方案对应某个分割点 $k^*$，且代价恰为 $f[l][k^*] + f[k^*+1][r] + \mathtt{sum}(l, r)$。而这个值已被 $\min_{k}$ 涵盖。

两方向结合，转移正确。$\blacksquare$

### 无后效性

**命题**：$f[l][r]$ 只依赖 $f[l'][r']$（$r' - l' < r - l$）的值，不依赖更早决策。

**证明**：转移方程右侧只出现 $f[l][k]$ 和 $f[k+1][r]$（$k < r$）——两者区间长度都 $< r - l + 1$。所以按"区间长度递增"遍历时，所需子状态都已算过。$\blacksquare$

## 应用扩展

### 应用一：矩阵链乘法

> 给定 $n$ 个矩阵 $M_1, M_2, \ldots, M_n$，$M_i$ 的尺寸为 $p_{i-1} \times p_i$。它们的乘积 $M_1 M_2 \cdots M_n$ 因结合律可以以不同顺序计算，问最少需要多少次标量乘法。

定义 $f[l][r] =$ 计算 $M_l M_{l+1} \cdots M_r$ 的最少标量乘法次数。

最后一次乘法把 $M_l \cdots M_k$ 的结果（尺寸 $p_{l-1} \times p_k$）与 $M_{k+1} \cdots M_r$ 的结果（尺寸 $p_k \times p_r$）相乘，代价 $p_{l-1} \cdot p_k \cdot p_r$。

$$f[l][r] = \min_{l \le k < r} \left( f[l][k] + f[k+1][r] + p_{l-1} p_k p_r \right)$$

边界 $f[i][i] = 0$（单矩阵无乘法），答案 $f[1][n]$。结构与石子合并完全一致——只是"本次代价"从"区间和"变成"$p_{l-1} p_k p_r$"。

### 应用二：最长回文子序列

> 给一个字符串 $s[1..n]$，求最长**回文**子序列（不要求连续）的长度。

定义 $f[l][r] = s[l..r]$ 的最长回文子序列长度。

**转移**：观察 $s[l]$ 和 $s[r]$ 的关系——

- 若 $s[l] = s[r]$：把这两个字符**配对**到回文的两端，剩下问题是 $s[l+1..r-1]$ 的最长回文子序列。所以 $f[l][r] = f[l+1][r-1] + 2$

- 若 $s[l] \ne s[r]$：$s[l]$ 和 $s[r]$ 至少有一个不在最优回文子序列中——所以 $f[l][r] = \max(f[l+1][r],\, f[l][r-1])$

$$f[l][r] = \begin{cases} f[l+1][r-1] + 2 & s[l] = s[r] \\ \max(f[l+1][r],\, f[l][r-1]) & s[l] \ne s[r] \end{cases}$$

边界 $f[i][i] = 1$（单字符是长度 1 的回文）、$f[i][i+1] = 2 \text{ if } s[i] = s[i+1] \text{ else } 1$。答案 $f[1][n]$。

> 💡 **没有"枚举分割点"也是区间 dp**：最长回文子序列的转移只看端点，不枚举 $k$——所以复杂度是 $O(n^2)$ 而非 $O(n^3)$。这说明"区间 dp"的本质是**状态形态**（区间端点对），不是必须有分割点枚举。

代码（注意遍历仍是区间长度递增）：

```cpp

class longest_palindrome_subseq {

private:

    int n;

    string s;

public:

    longest_palindrome_subseq(const string& s_in) {

        n = s_in.size();

        s = " " + s_in;                                 // 1-indexed

    }

    int solve() {

        vector<vector<int>> f(n + 2, vector<int>(n + 2, 0));

        for (int i = 1; i <= n; i++) {

            f[i][i] = 1;

        }

        for (int len = 2; len <= n; len++) {

            for (int l = 1; l + len - 1 <= n; l++) {

                int r = l + len - 1;

                if (s[l] == s[r]) {

                    f[l][r] = f[l + 1][r - 1] + 2;

                } else {

                    f[l][r] = max(f[l + 1][r], f[l][r - 1]);

                }

            }

        }

        return f[1][n];

    }

};
```

## 几个常见错误

- **遍历顺序错**：用 $l, r$ 双重循环而不按 $\mathtt{len}$ 递增——是最高发的 bug，会让 $f[l][k]$ 或 $f[k+1][r]$ 未算就被用

- **`f[l][r]` 初始化遗漏**：进入 $k$ 循环前必须把 $f[l][r]$ 初始化为 $+\infty$（最小化）或 $0$ / $-\infty$（最大化），否则首次 $\min$/$\max$ 比较失败

- **本次代价加错位置**：石子合并的 $\mathtt{sum}(l, r)$ 是**整个区间和**，不是合并某两堆的代价；矩阵链乘的本次代价是 $p_{l-1} p_k p_r$，取错维度会全错

- **边界遗漏**：$f[i][i]$ 必须初始化，否则长度 2 的区间转移读到无意义的 0

- **下标 0 vs 1**：本笔记用 1-indexed，$l \ge 1$、$r \le n$，访问 $f[l-1][\cdot]$ 或 $f[\cdot][r+1]$ 时要小心数组越界
