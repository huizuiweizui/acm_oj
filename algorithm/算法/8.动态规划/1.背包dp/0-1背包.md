#难度/★★

> 每件物品**选或不选**——背包 dp 中最基础也最重要的一类，理解了它，其他背包都是它的变形。

## 核心思想

> 有 $n$ 件物品，第 $i$ 件**体积** $w_i$、**价值** $v_i$，背包总容量为 $V$，每件物品**至多选一次**，求能装入背包的最大价值。

朴素的暴力是枚举每件物品选或不选，$2^n$ 种方案——显然爆炸。但仔细观察会发现：**当我们只关心"前 $i$ 件物品在容量 $j$ 下的最优价值"时，再多的决策细节都不重要**——这就是 dp 的本质：**状态压缩**。

**状态定义**：$f[i][j]$ 表示考虑前 $i$ 件物品、在背包容量恰为 $j$（或不超过 $j$，下文统一用"不超过"语义）时能取得的**最大价值**。

**转移方程**：考虑第 $i$ 件物品选或不选——

$$f[i][j] = \max \left( \underbrace{f[i-1][j]}_{\text{不选第 } i \text{ 件}}, \underbrace{f[i-1][j - w_i] + v_i}_{\text{选第 } i \text{ 件（前提 } j \ge w_i\text{）}} \right)$$

**初始化**：$f[0][j] = 0$（不考虑任何物品时价值为 0）。

**答案**：$f[n][V]$。

> 💡 **决策的本质**：每个状态 $f[i][j]$ 只依赖**上一行** $f[i-1][\cdot]$——这种"只往前看一步"的结构是 0-1 背包能滚动数组优化的根本原因。

## 适用场景

- 经典 0-1 选择：每个物品独立决定取或不取

- 子集和 / 子集计数：$f[i][j] = $ "前 $i$ 个数能否凑出和 $j$"，把 $\max$ 换成 $\lor$

- 方案数统计：把 $\max$ 换成求和（$f[i][j] = f[i-1][j] + f[i-1][j-w_i]$）

- 最小代价覆盖：把 $\max$ 换成 $\min$，初始化 $+\infty$

- 一些"看似不像背包"的题（如恰好选 $k$ 个数和为定值），多加一维即可

- 不适用：物品有数量但不止一件（用 [[多重背包]]）；同组互斥（用 [[分组背包]]）；物品可重复选（用 [[完全背包]]）

## 步骤拆解

1. **确定状态维度**：物品维 $i$ + 容量维 $j$

2. **确定转移**：枚举第 $i$ 件物品的两种决策

3. **确定遍历顺序**：外层物品 $i$ 从 1 到 $n$，内层容量 $j$ 从 0 到 $V$（二维版顺序无关；一维版必须**倒序**，详见下文）

4. **答案提取**：$f[n][V]$（"恰好"语义需把不可达状态初始化为 $-\infty$，再判断 $f[n][V]$ 是否合法）

## 代码模板

**模板一：二维 dp（清晰但占空间）**

```cpp

class knapsack_01_2d {

private:

    int n;                                  // 物品数

    long long V;                            // 背包容量

    vector<long long> w, v;                 // 体积、价值

    vector<vector<long long>> f;            // f[i][j]

public:

    knapsack_01_2d(int n_in, long long V_in,

                   const vector<long long>& w_in,

                   const vector<long long>& v_in) {

        n = n_in;

        V = V_in;

        w = w_in;

        v = v_in;

        f.assign(n + 1, vector<long long>(V + 1, 0));

    }

    long long solve() {

        for (int i = 1; i <= n; i++) {

            for (long long j = 0; j <= V; j++) {

                f[i][j] = f[i - 1][j];                          // 不选第 i 件

                if (j >= w[i]) {

                    f[i][j] = max(f[i][j], f[i - 1][j - w[i]] + v[i]);  // 选第 i 件

                }

            }

        }

        return f[n][V];

    }

};
```

**模板二：滚动数组（一维）**

```cpp

class knapsack_01_1d {

private:

    int n;

    long long V;

    vector<long long> w, v;

    vector<long long> f;                    // 滚动数组：f[j]

public:

    knapsack_01_1d(int n_in, long long V_in,

                   const vector<long long>& w_in,

                   const vector<long long>& v_in) {

        n = n_in;

        V = V_in;

        w = w_in;

        v = v_in;

        f.assign(V + 1, 0);

    }

    long long solve() {

        for (int i = 1; i <= n; i++) {

            for (long long j = V; j >= w[i]; j--) {             // ⚠️ 必须倒序

                f[j] = max(f[j], f[j - w[i]] + v[i]);

            }

        }

        return f[V];

    }

};
```

> ⚠️ **一维必须倒序枚举容量**：原因详见下文"正确性证明"——正序枚举会让同一件物品被选多次，退化成 [[完全背包]]。

> 💡 **写法约定**：`f[j]` 滚动后的语义是"考虑过当前第 $i$ 件物品后，容量 $j$ 下的最优价值"。每外层一轮迭代，整个 `f` 数组从"前 $i-1$ 件的结果"原地变成"前 $i$ 件的结果"。

## 复杂度分析

- 时间复杂度：$O(nV)$（$n$ 件物品 × $V$ 个容量状态）

- 空间复杂度：

  - 二维版 $O(nV)$

  - 一维版 $O(V)$

## 正确性证明

### 状态定义的无后效性

**命题**：定义 $f[i][j]$ 为"考虑前 $i$ 件物品、容量不超过 $j$ 时的最大价值"，则 $f[i][j]$ 只依赖 $f[i-1][\cdot]$，**不依赖更早的决策细节**

**证明**：假设最优方案选择了集合 $S \subseteq \{1, 2, \ldots, i\}$，价值为 $\sum_{k \in S} v_k$。把 $S$ 按是否包含 $i$ 分两类——

  

- **$i \notin S$**：$S \subseteq \{1, \ldots, i-1\}$，且 $\sum_{k \in S} w_k \le j$。由 $f[i-1][j]$ 的定义，$\sum_{k \in S} v_k \le f[i-1][j]$。

- **$i \in S$**：$S \setminus \{i\} \subseteq \{1, \ldots, i-1\}$，且 $\sum_{k \in S \setminus \{i\}} w_k \le j - w_i$。由 $f[i-1][j-w_i]$ 的定义，$\sum_{k \in S \setminus \{i\}} v_k \le f[i-1][j-w_i]$。所以 $\sum_{k \in S} v_k \le f[i-1][j-w_i] + v_i$。

两种情形都被转移方程的 $\max$ 涵盖，所以 $f[i][j] \ge $ 任何合法方案的价值；反之 $\max$ 中两项分别可由具体方案达到，所以 $f[i][j]$ 也是可达的。$\blacksquare$

### 一维滚动倒序的必要性

**命题**：用一维数组 $f[j]$ 替换 $f[i][j]$，第 $i$ 轮内层循环若**正序**枚举 $j$ 从 $w_i$ 到 $V$，会导致第 $i$ 件物品被选**多次**。

**反证 / 直接构造**：考虑正序枚举的执行——

第 $i$ 轮，$j = w_i$ 时：

$$f[w_i] \leftarrow \max(f[w_i],\, f[0] + v_i)$$

此时 $f[0]$ 是上一轮（前 $i-1$ 件）的值，正确表示"选了第 $i$ 件、容量恰好 $w_i$"的状态。

但 $j = 2 w_i$ 时：

$$f[2 w_i] \leftarrow \max(f[2 w_i],\, f[w_i] + v_i)$$

此处的 $f[w_i]$ **已经被本轮更新过**——它已经包含了"选了一次第 $i$ 件"的状态。再加 $v_i$ 就等于选了两次，与"每件至多选一次"矛盾。

**倒序的正确性**：倒序枚举 $j$ 从 $V$ 到 $w_i$，更新 $f[j]$ 时所用的 $f[j - w_i]$ 还是**上一轮**（前 $i-1$ 件）的值，等价于二维转移的 $f[i-1][j-w_i]$。形式化地——

> **循环不变量**：每轮内层循环更新 $f[j]$ 之**前**，对所有 $j' < j$ 满足 $f[j'] = f_{i-1}[j']$（即旧值）；更新之**后**，$f[j] = f_i[j]$（新值）。

倒序枚举保证了"读取的 $f[j - w_i]$ 永远是旧值"——因为 $j - w_i < j$，倒序时 $j - w_i$ 还没被本轮访问到。$\blacksquare$

### 关于"不超过"vs"恰好"

代码中 $f[i][0] = 0$ 隐含了"容量为 0 时合法、价值为 0"——这是**"不超过 $j$"**的语义。若题目要求**"恰好装满"**，则需把 $f[0][j] = -\infty\ (j > 0)$、$f[0][0] = 0$，这样不可达状态自然在 $\max$ 中被淘汰。

> 💡 **常见考点**：题面"恰好装满"vs"不超过"是不同初始化的关键区别。若答案为负无穷，说明无解。

## 几个常见错误

- **忘记倒序**：一维版正序枚举会变成 [[完全背包]]，是最经典的 bug

- **`j >= w[i]` 边界写错**：写成 `j > w[i]` 会漏掉 $j = w_i$ 这个临界状态

- **价值溢出**：物品数大、单价高时，总价值会超 `int` 范围，要用 `long long`

- **"恰好"vs"不超过"语义混用**：求方案数时尤其敏感

- **物品下标 0 vs 1**：本笔记按 README 规范用 1-indexed，`w[1..n]`、`v[1..n]`

## 应用扩展

### 求方案数

把 $\max$ 换成求和——

$$f[i][j] = f[i-1][j] + f[i-1][j - w_i] \quad (j \ge w_i)$$

代表"前 $i$ 件物品装出体积恰为 $j$ 的方案数"。初始化 $f[0][0] = 1$（空方案算一种），其余为 0。

### 求方案本身

$f$ 只能告诉我们最优值——要还原选择了哪些物品，需要在 dp 完成后**反向追溯**：

```cpp

vector<int> chosen;

long long j = V;

for (int i = n; i >= 1; i--) {

    if (j >= w[i] && f[i][j] == f[i - 1][j - w[i]] + v[i]) {

        chosen.push_back(i);

        j -= w[i];

    }

}

```

这要求保留二维 $f$ 数组；滚动数组无法直接还原方案。

### 多维费用背包

物品有两种"代价"（如体积 + 重量），背包有两种"容量"——状态加一维：$f[i][j][k]$。转移依旧是"选/不选"两路。空间紧时滚动后是 $f[j][k]$，两维都倒序。
