#难度/★★

> 物品被分成若干组，**每组至多选一件**——是 [[0-1背包]] 的"互斥决策"版本，转移只多一层"组内枚举"。

## 前置知识

- [[0-1背包]]

## 核心思想

> 物品分成 $T$ 组，第 $t$ 组有若干件物品，每件物品有体积和价值，**每组至多选一件**（包括不选）。背包容量 $V$，求最大价值。

直观上每组就是一个"互斥单选题"——三重决策：选 0 件、选第 1 件、选第 2 件…… 把这种"互斥分支"作为转移的 $\max$ 来源即可。

**状态定义**：$f[t][j] =$ 考虑前 $t$ 组、容量不超过 $j$ 时的最大价值

**转移方程**：

$$f[t][j] = \max \left( \underbrace{f[t-1][j]}_{\text{第 } t \text{ 组不选}},\;\; \max_{k \in \text{group}_t,\, w_k \le j} \underbrace{f[t-1][j - w_k] + v_k}_{\text{第 } t \text{ 组选第 } k \text{ 件}} \right)$$

**初始化**：$f[0][j] = 0$。

**答案**：$f[T][V]$。

> 💡 **本质就是 0-1 背包**：把"组"看成"宏物品"，每组对外只有一种结果（选了哪件 / 没选）——但内部的具体选择由组内的 $\max$ 决定。

## 适用场景

- 物品天然分组、组内互斥的最优化问题（如同类商品中只能买一个最满意的型号）

- "依赖背包"的简化形式：每个主件加上若干附件 $\to$ 把"主件 + 附件子集"枚举出来作为分组的物品（如 [洛谷P1064 金明的预算方案](https://www.luogu.com.cn/problem/P1064)）

- 多维选择互斥（如不同方案二选一、三选一）

- 不适用：组内可同时选多件（拆成多组或用 [[多重背包]]）；无分组限制的普通背包（用 [[0-1背包]]）

## 步骤拆解

1. **状态维度**：组维 $t$ + 容量维 $j$

2. **三重循环**：

   - **外层**：枚举组 $t$

   - **中层**：枚举容量 $j$（一维滚动时**倒序**）

   - **内层**：枚举本组的物品 $k$，更新 $f[j]$

3. **顺序的关键**：容量在外、物品在内——保证同一组的不同物品不会被同时选中

## 代码模板

**模板一：二维 dp**

```cpp

class knapsack_group_2d {

private:

    int T;                                          // 组数

    long long V;                                    // 背包容量

    vector<vector<long long>> w, v;                 // w[t] / v[t] 是第 t 组的体积/价值列表

    vector<vector<long long>> f;

public:

    knapsack_group_2d(int T_in, long long V_in,

                      const vector<vector<long long>>& w_in,

                      const vector<vector<long long>>& v_in) {

        T = T_in;

        V = V_in;

        w = w_in;

        v = v_in;

        f.assign(T + 1, vector<long long>(V + 1, 0));

    }

    long long solve() {

        for (int t = 1; t <= T; t++) {

            for (long long j = 0; j <= V; j++) {

                f[t][j] = f[t - 1][j];                              // 第 t 组不选

                for (size_t k = 0; k < w[t].size(); k++) {          // 枚举组内每件物品

                    if (j >= w[t][k]) {

                        f[t][j] = max(f[t][j], f[t - 1][j - w[t][k]] + v[t][k]);

                    }

                }

            }

        }

        return f[T][V];

    }

};
```

**模板二：滚动数组（一维）**

  

```cpp

class knapsack_group_1d {

private:

    int T;

    long long V;

    vector<vector<long long>> w, v;

    vector<long long> f;

public:

    knapsack_group_1d(int T_in, long long V_in,

                      const vector<vector<long long>>& w_in,

                      const vector<vector<long long>>& v_in) {

        T = T_in;

        V = V_in;

        w = w_in;

        v = v_in;

        f.assign(V + 1, 0);

    }

    long long solve() {

        for (int t = 1; t <= T; t++) {

            for (long long j = V; j >= 0; j--) {                    // ⚠️ 容量倒序

                for (size_t k = 0; k < w[t].size(); k++) {          // 内层枚举组内物品

                    if (j >= w[t][k]) {

                        f[j] = max(f[j], f[j - w[t][k]] + v[t][k]);

                    }

                }

            }

        }

        return f[V];

    }

};
```

> ⚠️ **三重循环的顺序不能调换**：外层 $t$、中层 $j$（倒序）、内层 $k$——若把 $k$ 提到 $j$ 外面，会变成"每件物品独立做 0-1 背包"，组内可能被选多件，结果错误。

> 💡 **为什么"$j$ 倒序、$k$ 内层"能保证每组只选一件**：每个 $j$ 在处理完整个第 $t$ 组后才会被推进——所有 $k$ 共用同一份 $f[j - w_k]$（它仍是第 $t-1$ 组的旧值），所以同一个 $j$ 的更新中"选哪件 $k$"是互斥的。

## 复杂度分析

- 时间复杂度：$O(V N)$（其中 $N$ 是物品总数）

- 空间复杂度：二维 $O(TV)$；一维 $O(V)$

## 正确性证明

### 转移方程的合法性

**命题**：$f[t][j] = \max\left(f[t-1][j],\, \max_{k \in \text{group}_t} (f[t-1][j - w_k] + v_k)\right)$ 正确表示"前 $t$ 组、容量不超过 $j$ 的最大价值"。

**证明**：任何合法方案中，第 $t$ 组的决策恰好是以下之一——

- **不选第 $t$ 组任何物品**：方案剩余在前 $t-1$ 组、容量 $\le j$ 中，由 $f[t-1][j]$ 取上界

- **选第 $t$ 组的第 $k$ 件**：方案剩余在前 $t-1$ 组、容量 $\le j - w_k$ 中，价值贡献为 $f[t-1][j - w_k] + v_k$

所有合法方案的价值都能被两种情形之一覆盖，且 $\max$ 取最大——故转移正确。$\blacksquare$

### 三重循环顺序的正确性

**命题**：一维滚动版的三重循环顺序 $t \to j (\text{倒序}) \to k$ 保证"每组至多选一件"。

**证明**：固定 $t$（外层第 $t$ 组）。对每个倒序的 $j$，内层枚举 $k$ 时——

- 读取的 $f[j - w_k]$ 仍是**第 $t-1$ 组结束后的值**（因为 $j - w_k < j$，倒序时 $j - w_k$ 还没被本轮访问；并且对所有 $k$ 来说 $j - w_k$ 都未在第 $t$ 组中被覆写）

- 每个 $k$ 用同一份"旧 $f$"——多次执行 $\max$，结果只反映"在多个候选 $k$ 中**取最优**"，不会出现"选 $k_1$ 又选 $k_2$"

更严格地，**循环不变量**：第 $t$ 轮处理 $j$ 之**前**，所有 $j' \ge j$ 的 $f[j']$ 已是 $f_t[j']$；所有 $j' < j$ 的 $f[j']$ 仍是 $f_{t-1}[j']$。

更新 $f[j]$ 时，对所有 $k$ 读的 $f[j - w_k]$（$j - w_k < j$）都是 $f_{t-1}[j - w_k]$——即每个候选 $k$ 都基于"前 $t-1$ 组的最优"延伸，互不干扰。$\blacksquare$

### 反例：错误的循环顺序

若把内层 $k$ 提到 $j$ 之外——

```cpp

for (k : group_t) {

    for (j = V; j >= w_k; j--) {

        f[j] = max(f[j], f[j - w_k] + v_k);     // 错误顺序

    }

}

```

变成"每件物品独立做 0-1 背包"——前一件 $k_1$ 已经修改过 $f$，下一件 $k_2$ 读取的 $f[j - w_{k_2}]$ 可能已包含 $k_1$ 的贡献。结果就成了"组内可任意多选"——退化成 [[0-1背包]]。$\blacksquare$

## 几个常见错误

- **三重循环顺序写反**：把 $k$ 移到 $j$ 外，组内会变成可同时选多件

- **二维版误写 $f[t][j-w_k]$**：转移应基于 $f[t-1]$，写 $f[t]$ 会变成"组内可重复选"（类似 [[完全背包]] 的错误）

- **空组未处理**：若某组 $|\text{group}_t| = 0$，二维版 $f[t][j] = f[t-1][j]$ 自动正确；一维版本身就跳过内层循环，也无影响——但写代码时别忘了"不选"也是合法选择

- **物品下标管理混乱**：建议用 `vector<vector<long long>>` 直接按组组织 `w[t]`、`v[t]`——比扁平存储 + 分组数组的写法清晰得多

## 应用扩展

### 主件 + 附件型依赖背包

经典题型 [洛谷P1064](https://www.luogu.com.cn/problem/P1064)：每个主件可以独立选；选了主件后才能再选其若干附件（每个主件最多 2 个附件）。

**化归思路**：把"一个主件 + 它的附件子集"作为分组背包的"组内物品"——共 $\le 4$ 种选法（不选；只选主件；主件 + 附件 1；主件 + 附件 2；主件 + 附件 1 + 附件 2）。

```text

group_t = {

    (w_主, v_主),

    (w_主 + w_附1, v_主 + v_附1),

    (w_主 + w_附2, v_主 + v_附2),

    (w_主 + w_附1 + w_附2, v_主 + v_附1 + v_附2)

}

```

附件多于 2 个时，可用枚举子集 + [[状压dp]] 或单独建图——但 OI 中此类题通常限制附件数 $\le 2$。

### 分组背包求方案数

把 $\max$ 换成求和——

$$f[t][j] = f[t-1][j] + \sum_{k \in \text{group}_t} f[t-1][j - w_k]$$

代表"考虑前 $t$ 组、容量 $j$ 的方案数"。注意"不选"也算一种方案，要单独累加。
