#难度/★★★

> 把字符串编码成一个数字"指纹"——前缀哈希 + 减法变形让任意子串哈希 $O(1)$ 求出，是字符串相等判断的瑞士军刀。

## 前置知识

- [[模运算]]

- [[快速幂]]

## 核心思想

**问题来源**：判断两个字符串是否相等需要 $O(n)$ 逐字符比较——若要做大量字符串比较（如"区间内所有子串中有多少个相同"），$O(nm)$ 暴力太慢。

**字符串哈希（Rabin-Karp 哈希）**：把每个字符串映射为一个整数"指纹"——

> 视字符串 $s = s_1 s_2 \cdots s_n$ 为 $\mathrm{base}$ 进制数：$h(s) = \sum_{i=1}^{n} s_i \cdot \mathrm{base}^{n-i} \pmod p$

**两步关键设计**：

- **预处理前缀哈希** $h_i = h(s_1 s_2 \cdots s_i)$：递推 $h_i = h_{i-1} \cdot \mathrm{base} + s_i \pmod p$

- **子串哈希 $O(1)$ 求出**：$h(s_l s_{l+1} \cdots s_r) = h_r - h_{l-1} \cdot \mathrm{base}^{r - l + 1} \pmod p$

**类比 [[前缀和]]**：前缀和让区间和 $O(1)$；前缀哈希让子串哈希 $O(1)$——结构完全一致，只是"加法"换成了"按位置加权"。

**碰撞与双哈希**：

不同字符串可能映射到同一个哈希值（**碰撞**）——这是哈希的本质局限。在模 $p$ 下随机字符串的碰撞概率约 $1/p$。

**双哈希（双模数）**：用两套 $(\mathrm{base}, p)$ 各算一次——若两套都相等才认为字符串相等。碰撞概率降到 $1 / (p_1 p_2)$，实战中 $p_1, p_2 \approx 10^9$ 时已远小于宇宙原子数。

> ⚠️ **不要用 `unsigned long long` 自然溢出**：相当于模 $2^{64}$ 哈希——简单但**容易被构造数据卡到 100% 碰撞**。竞赛中坚持用大质数模数 + 双哈希。

## 适用场景

- **快速判断子串相等**：$O(1)$ 单次比较，是哈希最经典的用途

- **统计相同子串个数**：把所有子串哈希后用哈希表 / 排序统计

- **配合二分求"最长公共前缀"**：二分长度 + 哈希判等

- **回文判定**：与"反向哈希"比较（$s_l \cdots s_r$ 是否等于 $s_r \cdots s_l$）

- **字符串匹配**：滑动窗口 + 哈希（类似 [[KMP]] 但用哈希判等，是 Rabin-Karp 算法）

- 不适用：要求**严格无碰撞**（用 [[KMP]] 或 [[AC自动机]]）；非常长字符串需要在线匹配

## 步骤拆解

1. **选择 $\mathrm{base}$ 和 $p$**：$\mathrm{base}$ 通常用 $131$ 或 $13331$（小质数大于字符集大小）；$p$ 用 $10^9 + 7$ 或 $998244353$ 等大质数

2. **预处理**：扫一遍字符串，递推 $h_i$ 和 $\mathrm{base}^i$

3. **查询子串 $s[l..r]$ 的哈希**：$h(s[l..r]) = h_r - h_{l-1} \cdot \mathrm{base}^{r-l+1} \pmod p$

4. **比较**：两个子串哈希相等 $\Leftrightarrow$ 两子串"很可能"相等（双哈希后接近确定相等）

## 代码模板

**模板一：单哈希（适合单次比较或低强度场景）**

```cpp
class string_hash {

private:

    static constexpr long long MOD = 1e9 + 7;

    static constexpr long long BASE = 131;

    int n;

    vector<long long> h, p;                     // h[i] = 前 i 个字符的哈希；p[i] = BASE^i

public:

    string_hash(const string& s) {

        n = s.size();

        h.assign(n + 1, 0);

        p.assign(n + 1, 0);

        p[0] = 1;

        for (int i = 1; i <= n; i++) {

            h[i] = (h[i - 1] * BASE + s[i - 1]) % MOD;

            p[i] = p[i - 1] * BASE % MOD;

        }

    }

    // 查询子串 s[l..r] 的哈希（1-indexed）
    long long query(int l, int r) {

        long long res = (h[r] - h[l - 1] * p[r - l + 1]) % MOD;

        return (res + MOD) % MOD;               // 防止负数

    }

};
```

> 💡 **`(res + MOD) % MOD`**：模运算下 `h[r] - h[l-1] * p[...]` 可能是负数（C++ 中负数 mod 仍负）——加 MOD 再取模规整到 $[0, p)$。

> 💡 **`p[i]` 的预处理是关键**：每次查询都要用到 $\mathrm{base}^{r-l+1}$，预处理后 $O(1)$ 取用。

**模板二：双哈希（强度更高，竞赛推荐）**

```cpp
class double_hash {

private:

    static constexpr long long MOD1 = 1e9 + 7;

    static constexpr long long MOD2 = 998244353;

    static constexpr long long BASE1 = 131;

    static constexpr long long BASE2 = 13331;

    int n;

    vector<long long> h1, h2, p1, p2;

public:

    double_hash(const string& s) {

        n = s.size();

        h1.assign(n + 1, 0);

        h2.assign(n + 1, 0);

        p1.assign(n + 1, 0);

        p2.assign(n + 1, 0);

        p1[0] = p2[0] = 1;

        for (int i = 1; i <= n; i++) {

            h1[i] = (h1[i - 1] * BASE1 + s[i - 1]) % MOD1;

            h2[i] = (h2[i - 1] * BASE2 + s[i - 1]) % MOD2;

            p1[i] = p1[i - 1] * BASE1 % MOD1;

            p2[i] = p2[i - 1] * BASE2 % MOD2;

        }

    }

    pair<long long, long long> query(int l, int r) {

        long long r1 = ((h1[r] - h1[l - 1] * p1[r - l + 1]) % MOD1 + MOD1) % MOD1;

        long long r2 = ((h2[r] - h2[l - 1] * p2[r - l + 1]) % MOD2 + MOD2) % MOD2;

        return {r1, r2};

    }

};
```

**应用示例：求两字符串的最长公共前缀长度**

```cpp
int lcp(const string& s, const string& t) {

    string_hash hs(s), ht(t);

    int lo = 0, hi = min(s.size(), t.size());

    while (lo < hi) {

        int mid = (lo + hi + 1) / 2;

        if (hs.query(1, mid) == ht.query(1, mid)) {

            lo = mid;

        } else {

            hi = mid - 1;

        }

    }

    return lo;

}
```

> 💡 **二分 + 哈希**：求 LCP 最直接的方法。复杂度 $O(\log n)$ 单次查询，预处理 $O(n)$。

## 复杂度分析

- 预处理：$O(n)$（建表）

- 单次子串哈希查询：$O(1)$

- 单次子串相等比较：$O(1)$（双哈希为 $O(1)$ 但常数 ×2）

- 空间：$O(n)$

## 正确性证明

### 哈希函数的正确性

**命题**：$h(s) = \sum_{i=1}^{n} s_i \cdot \mathrm{base}^{n-i} \pmod p$ 是一个**确定性函数**——相同字符串必定有相同哈希值。

**证明（显然）**：哈希定义中没有任何随机成分——给定相同 $s$，$h(s)$ 计算结果唯一。$\blacksquare$

注意：反向不成立——不同字符串可能有相同哈希（碰撞）。

### 子串哈希公式的正确性

**命题**：$h(s_l \cdots s_r) = h_r - h_{l-1} \cdot \mathrm{base}^{r - l + 1} \pmod p$。

**证明**：

$$h_r = \sum_{i=1}^{r} s_i \cdot \mathrm{base}^{r-i} = \underbrace{\sum_{i=1}^{l-1} s_i \cdot \mathrm{base}^{r-i}}_{A} + \underbrace{\sum_{i=l}^{r} s_i \cdot \mathrm{base}^{r-i}}_{B}$$

第 $A$ 部分：

$$A = \sum_{i=1}^{l-1} s_i \cdot \mathrm{base}^{r-i} = \mathrm{base}^{r-l+1} \cdot \sum_{i=1}^{l-1} s_i \cdot \mathrm{base}^{l-1-i} = \mathrm{base}^{r-l+1} \cdot h_{l-1}$$

第 $B$ 部分：

$$B = \sum_{i=l}^{r} s_i \cdot \mathrm{base}^{r-i}$$

把指标平移 $j = i - l + 1$：$j$ 从 $1$ 到 $r - l + 1$，$i = j + l - 1$，$r - i = (r - l + 1) - j$：

$$B = \sum_{j=1}^{r-l+1} s_{j+l-1} \cdot \mathrm{base}^{(r-l+1) - j} = h(s_l s_{l+1} \cdots s_r)$$

所以 $h_r = \mathrm{base}^{r-l+1} \cdot h_{l-1} + h(s_l \cdots s_r)$，移项即得公式。$\blacksquare$

### 碰撞概率

**命题**：在模 $p$ 哈希下，假设字符串"随机"分布，两个不等的字符串 $s, t$ 满足 $h(s) = h(t)$ 的概率约为 $1/p$。

**直觉论证**：$h(s) - h(t) \pmod p$ 是 $s, t$ 差值的某个加权和——在"均匀随机字符串"假设下，这个差值取 $0$ 到 $p - 1$ 中每个值的概率均等，所以 $\mathbb P[h(s) - h(t) = 0] \approx 1/p$。

**实际意义**：

- $p = 10^9 + 7$ → 单次碰撞概率 $\approx 10^{-9}$

- 若进行 $q$ 次比较，至少一次碰撞概率约 $q / p$（**生日悖论**让全局碰撞概率更大，但局部比较仍合理）

- 双哈希 $p_1 p_2 \approx 10^{18}$ → 碰撞概率忽略不计

**为什么自然溢出会被卡**：自然溢出等价于模 $2^{64}$，且 $\mathrm{base} = 131$ 时 $2^{64}$ 不是质数——存在很多"小阶元素"使 $\mathrm{base}^k \equiv 1$。攻击者可以构造让碰撞概率 100% 的字符串（搜"anti-hash"数据）。

### 选择 $\mathrm{base}$ 和 $p$

**$\mathrm{base}$ 的选择**：

- 必须 $> $ 字符集大小（128 或 256）——保证 $\mathrm{base}$ 进制下每个字符独立编码

- 选小素数（131, 13331）方便记忆，且实测分布良好

- 避免 $\mathrm{base} = 2^k$（在 mod 大质数下没问题，但可能与一些攻击模式相关）

**$p$ 的选择**：

- 大质数（$10^9$ 量级或更大）

- 常用：$10^9 + 7$, $998244353$, $10^9 + 9$

- **不要用 $2^{64}$**（自然溢出）

### 复杂度的来源

- 预处理：$h$ 和 $p$ 数组各 $O(n)$ 次乘加 = $O(n)$

- 查询：常数次乘加 + 取模 = $O(1)$

$\blacksquare$

## 应用扩展

### 反向哈希与回文

把字符串反向后再算一套哈希，与正向哈希的某区间比较——若相等，则该区间是**回文**。这是回文判定的简洁做法（虽然 [[Manacher]] 更优雅）。

```cpp
string_hash forward(s);

string s_rev = s;

reverse(s_rev.begin(), s_rev.end());

string_hash backward(s_rev);

  

// 判断 s[l..r] 是否回文（1-indexed）

int n = s.size();

bool is_palindrome = (forward.query(l, r) == backward.query(n - r + 1, n - l + 1));
```

> 💡 **下标转换**：原 $s$ 的 $[l, r]$ 在反向 $s_\text{rev}$ 中对应 $[n - r + 1, n - l + 1]$。

### Rabin-Karp 字符串匹配

用滑动哈希在主串中找模式串——

- 预处理模式串 $T$ 的哈希 $h_T$

- 在主串 $S$ 上滑动长度为 $|T|$ 的窗口，每次 $O(1)$ 计算窗口哈希

- 哈希等于 $h_T$ 时认为匹配（双哈希避免误判）

复杂度 $O(|S| + |T|)$，与 [[KMP]] 同级。代码更短，但有小概率误判（双哈希后近乎不可能）。

## 几个常见错误

- **忘记 `(res + MOD) % MOD`**：减法可能导致负数，C++ 的 `%` 对负数仍返回负

- **`p[]` 数组没预处理**：每次查询现算 $\mathrm{base}^{r-l+1}$ 用 [[快速幂]] 是 $O(\log)$，比预处理慢

- **用了自然溢出**：上文已警告

- **单哈希被卡**：竞赛中**默认使用双哈希**——多写几行换来稳定性
