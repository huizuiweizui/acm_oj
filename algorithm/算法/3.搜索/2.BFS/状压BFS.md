#难度/★★★

> 用一个整数的二进制位压缩表示集合状态，让 BFS 能在"$2^k$ 种状态 × 节点数"的空间上跑动。

## 前置知识

- [[位运算]]

- [[BFS]]

## 核心思想

普通 [[BFS]] 的状态只是"当前节点"，但很多问题中状态还包含**额外信息**——比如"已经收集了哪些钥匙""已经访问了哪些点"。如果把"额外信息"原样存进队列，状态空间会爆炸。

**状态压缩**的核心：当额外信息可以用"集合"刻画，且集合规模 $k \le 20$ 左右时，可以用一个整数的**二进制位**表示这个集合——第 $i$ 位为 1 表示"已经获得第 $i$ 个东西"。这样：

- 集合状态变成一个整数（最多 $2^k$ 种）

- 集合上的"添加""删除""判断包含"操作变成 $O(1)$ 的位运算

BFS 的状态从"节点 $u$"扩展为二元组"(节点 $u$, 状态 $S$)"，整个状态空间是 $n \cdot 2^k$，仍然可控。

## 适用场景

- "在网格 / 图上移动 + 收集物品"型问题（如收集所有钥匙的最短路径）

- 状态包含**小集合信息**（$k \le 20$，否则 $2^k$ 内存爆炸）

- 求最少步数、最短路径

- 经典模型：**旅行商问题（TSP）的小规模版**——访问所有 $n$ 个城市的最短路径，状态为 $(\text{当前位置}, \text{已访问集合})$

- 不适用：$k > 20$（状态太多，应换 [[状压dp]] 配合启发式或其他技巧）；状态信息不是集合（如连续值）

## 步骤拆解

1. **确定状态空间**：识别哪些信息会影响后续决策。常见有"当前位置 $u$ + 已收集的集合 $S$"

2. **设计状态编码**：把集合 $S$ 用 $k$ 位二进制压缩成整数

3. **设计转移**：从 $(u, S)$ 出发，每条出边 $u \to v$ 产生新状态 $(v, S')$，其中 $S'$ 由 $v$ 是否包含新物品决定

4. **维护 `dist[u][S]`**：表示到达状态 $(u, S)$ 的最少步数，初始全 $-1$

5. **跑 BFS**：起点为 $(\text{start}, S_0)$，目标视题目而定（如 $S = 2^k - 1$ 表示收集齐了）

## 代码模板

**模板：网格图上收集所有钥匙的最少步数**

```cpp
// grid 上：'.' 空地，'#' 墙，'@' 起点，'a'-'z' 钥匙，'A'-'Z' 对应锁
// 求拿到所有钥匙的最少步数

int shortest_path_all_keys(vector<string>& grid) {

    int n = grid.size();

    int m = grid[0].size();

    int sx = 0, sy = 0;

    int total_keys = 0;

    // 找起点和钥匙数
    for (int i = 0; i < n; i++) {

        for (int j = 0; j < m; j++) {

            char c = grid[i][j];

            if (c == '@') {

                sx = i;

                sy = j;

            }

            if (c >= 'a' && c <= 'z') {

                total_keys += 1;

            }

        }

    }

    int full = (1 << total_keys) - 1;       // 所有钥匙都拿到的状态

    // dist[x][y][S] = 到 (x, y) 且拥有钥匙集合 S 的最少步数
    vector<vector<vector<int>>> dist(

        n, vector<vector<int>>(m, vector<int>(full + 1, -1))

    );

    queue<tuple<int, int, int>> q;

    dist[sx][sy][0] = 0;

    q.push({sx, sy, 0});

    int dx[] = {-1, 1, 0, 0};

    int dy[] = {0, 0, -1, 1};

    while (!q.empty()) {

        auto [x, y, S] = q.front();

        q.pop();

        if (S == full) {

            return dist[x][y][S];

        }

        for (int d = 0; d < 4; d++) {

            int nx = x + dx[d];

            int ny = y + dy[d];

            if (nx < 0 || nx >= n || ny < 0 || ny >= m) {

                continue;

            }

            char c = grid[nx][ny];

            if (c == '#') {

                continue;

            }

            int nS = S;

            if (c >= 'a' && c <= 'z') {

                nS |= (1 << (c - 'a'));     // 拿到钥匙

            }

            if (c >= 'A' && c <= 'Z') {

                int need = 1 << (c - 'A');

                if ((S & need) == 0) {      // 没对应钥匙，过不去

                    continue;

                }

            }

            if (dist[nx][ny][nS] != -1) {

                continue;

            }

            dist[nx][ny][nS] = dist[x][y][S] + 1;

            q.push({nx, ny, nS});

        }

    }

    return -1;

}
```

> 💡 **关键观察**：同一格子 $(x, y)$ 可以被**多次访问**，只要"拥有的钥集合 $S$"不同。所以 `visited` 必须**带上 $S$ 维度**——这就是状压 BFS 的核心：节点不再是原图节点，而是 $(原节点, 状态)$ 二元组。

**典型状态压缩位运算**：

```cpp

S | (1 << i)       // 添加第 i 个元素

S & ~(1 << i)      // 删除第 i 个元素

S & (1 << i)       // 判断第 i 个元素是否在 S 中（非零即在）

__builtin_popcount(S)   // 集合大小

S == full          // 集合是否全集

```

## 复杂度分析

- 时间复杂度：$O(\text{节点数} \cdot 2^k \cdot \text{平均出度})$

- 空间复杂度：$O(\text{节点数} \cdot 2^k)$

## 正确性证明

### 状态空间扩张的合法性

**核心命题**：把状态从原图节点 $u$ 扩展为二元组 $(u, S)$ 后，扩展后的图仍然是一张普通的有向图，可以用标准 [[BFS]] 求最短路。

**证明**：定义新图 $G'$ 如下：

- 节点集 $V' = V \times \{0, 1\}^k$（即所有 $(u, S)$ 二元组）

- 边集 $E'$：对原图每条边 $u \to v$ 和每个状态 $S$，新图中有边 $(u, S) \to (v, S')$，其中 $S'$ 由"经过 $v$ 后状态如何更新"的规则决定

容易验证 $G'$ 是普通有向图，每条边的代价仍为 1。所以在 $G'$ 上跑 [[BFS]] 就能求出从 $(\text{start}, S_0)$ 到任意 $(u, S)$ 的最短路。

由 [[BFS]] 的正确性（详见其笔记），算法找到的就是真实最短路径。$\blacksquare$

### 为什么必须把 $S$ 纳入 visited 标记

**反证**：若仍按原图节点 $u$ 来标记 visited——即只维护 `dist[u]` 而非 `dist[u][S]`——会导致漏解。

考虑反例：起点 $s$，目标 $t$，钥匙 $k$ 在分支 $s \to k \to t$ 上。直接 $s \to t$ 距离 5，但缺钥匙过不去；$s \to k \to t$ 距离 7，但获得了钥匙。

若按原图标记，BFS 先到 $t$ 时距离为 5（无钥匙过不去），但 visited 已标记 $t$。后续路径带着钥匙到 $t$ 时被拒绝——错过最优解。

**核心原因**："状态相同的两次访问可以等价"，但 $(u, S_1)$ 和 $(u, S_2)$ 在 $S_1 \neq S_2$ 时**不是同一个状态**——后续可达性不同，必须分别处理。$\blacksquare$

### 复杂度的来源

新图 $G'$ 共有 $n \cdot 2^k$ 个节点，每节点的出边数等于原图中对应节点的出度。总边数 $\le m \cdot 2^k$。BFS 在 $G'$ 上的复杂度为 $O((n + m) \cdot 2^k)$。

**为什么 $k$ 必须很小**：$2^{20} \approx 10^6$ 已是上限。$k = 20$ 时状态总数还能跑，但 $k = 25$ 就 $3 \times 10^7$ 直接爆。这个上界是**指数级**的，无法通过常数优化突破。$k$ 一旦超过 20，必须考虑：

- 启发式搜索（[[A∗]]）

- 双向 BFS / [[折半搜索]]

- 改用 [[状压dp]] 配合其他剪枝
