#难度/★★

> 给 [[DFS]] 加上"已计算结果缓存"，把指数级的重复递归压成多项式级，是动态规划的递归化身。

## 前置知识

- [[DFS]]

## 核心思想

朴素 [[DFS]] 在搜索过程中常常**重复计算同一子问题**——比如算斐波那契数 $f(n) = f(n-1) + f(n-2)$ 时，$f(n-2)$ 在两条递归路径上都会被算到，$f(n-3)$ 被算到 3 次，越往下指数级爆炸，整体 $O(2^n)$。

**记忆化搜索**的核心：用一个数组（或哈希表）`memo[]` 记录"已经算过的子问题答案"。每次递归进入函数时——

- 先查 `memo`：若已算过，直接返回缓存值

- 若没算过，正常递归计算，**算完后把结果写入 `memo`**

这样每个子问题**最多被真正计算一次**，总复杂度等于"不同子问题数 × 单次转移代价"。这正是动态规划的核心思想，只不过用"递归 + 缓存"的形式书写——所以记忆化搜索本质就是**自顶向下写法的 dp**。

与传统 dp（自底向上递推）相比，记忆化搜索的优势是：

- **不需要思考状态计算顺序**：递归会自然按依赖关系展开

- **只计算真正用到的状态**：自底向上要把所有状态填满，记忆化只算从入口可达的子问题

- **代码贴近问题描述**：转移方程怎么写，代码就怎么写

## 适用场景

- 子问题之间有**重叠**（同一子问题被多条路径访问）

- 子问题之间**无后效性**（子问题的答案只取决于其参数，不依赖于"是从哪里调用过来的"）

- 状态数较少且能用有限维度刻画（数组下标可表达）

- 经典模型：

  - **数字三角形 / 路径计数**：从顶到底的最大路径和

  - **最长公共子序列 / 最长上升子序列**：朴素 dp 的递归版

  - **区间 dp**：如石子合并，自顶向下写起来比循环更直观（见 [[区间dp]]）

  - **数位 dp**：状态多且转移复杂，递归写法清晰得多（见 [[数位dp]]）

  - **博弈型搜索**：极小化极大配合记忆化

- 不适用：状态空间过大无法用数组缓存（要用哈希表，或换思路）；存在后效性（如某些贪心 / 反悔模型）

## 步骤拆解

1. **定义状态**：明确递归函数的参数代表什么、返回值代表什么。状态参数一般就是 `memo` 的下标

2. **写出转移方程**：用更小的子状态表达当前状态

3. **设计 `memo` 数组**：用一个"未计算"标记初始化（如 $-1$ 或 $\infty$，根据答案的可能取值选择）

4. **写函数**：

   - 处理边界（递归终点）

   - 查 `memo`，命中则返回

   - 计算结果并写入 `memo`，返回

5. **入口调用**：从初始状态调用一次

## 代码模板

**模板一：数字三角形（经典入门）**

> 给定一个数字三角形，从顶端走到底端，每步只能走到下一行**相邻**的两个数之一，求路径上数字之和的最大值。

```cpp
class triangle_max_path {

private:

    int n;

    vector<vector<int>> a;

    vector<vector<int>> memo;               // memo[i][j] = 从 (i,j) 出发到底端的最大和

    int dfs(int i, int j) {

        if (i == n) {

            return 0;                        // 走出三角形，无贡献

        }

        if (memo[i][j] != -1) {

            return memo[i][j];                // 命中缓存

        }

        int res = a[i][j] + max(dfs(i + 1, j), dfs(i + 1, j + 1));

        memo[i][j] = res;                     // 写入缓存

        return res;

    }

public:

    triangle_max_path(vector<vector<int>>& a_in) {

        a = a_in;

        n = a.size() - 1;

        memo.assign(n + 1, vector<int>(n + 1, -1));

    }

    int solve() {

        return dfs(1, 1);

    }

};
```

**模板二：最长公共子序列（双参数状态）**

> 求字符串 $s$ 和 $t$ 的最长公共子序列长度。

```cpp
class lcs {

private:

    string s, t;

    int n, m;

    vector<vector<int>> memo;

    int dfs(int i, int j) {

        if (i == 0 || j == 0) {

            return 0;

        }

        if (memo[i][j] != -1) {

            return memo[i][j];

        }

        int res;

        if (s[i - 1] == t[j - 1]) {

            res = dfs(i - 1, j - 1) + 1;

        } else {

            res = max(dfs(i - 1, j), dfs(i, j - 1));

        }

        memo[i][j] = res;

        return res;

    }

public:

    lcs(string& s_in, string& t_in) {

        s = s_in;

        t = t_in;

        n = s.size();

        m = t.size();

        memo.assign(n + 1, vector<int>(m + 1, -1));

    }

    int solve() {

        return dfs(n, m);

    }

};
```

> 💡 **从"已经写好转移方程"到"记忆化搜索"几乎是机械翻译**：把转移方程的左边写成函数返回值，右边写成递归调用，加上边界和缓存即可。

**模板三：状态用 map 缓存（状态空间稀疏时）**

当状态参数很大但**实际访问到的状态很少**时，用 `unordered_map` 替代数组：

```cpp
unordered_map<long long, long long> memo;

long long dfs(long long state) {

    if (/* 边界条件 */) {

        return 0;

    }

    auto it = memo.find(state);

    if (it != memo.end()) {

        return it->second;

    }

    long long res = /* 递归计算 */;

    memo[state] = res;

    return res;

}
```

## 复杂度分析

- 时间复杂度：$O(\text{状态数} \times \text{单次转移代价})$

- 空间复杂度：$O(\text{状态数})$（`memo` 数组）+ $O(\text{递归深度})$（系统栈）

## 正确性证明

### 缓存的等价性

**核心命题**：对任一状态 $s$，无论函数 $\mathtt{dfs}(s)$ 被调用多少次、从哪里调用过来，返回值始终相同——即"答案只取决于状态参数"。

这是记忆化搜索能成立的**根本前提**——也就是问题必须满足**无后效性**：当前状态的答案只与状态本身有关，不依赖于到达该状态的路径。

**证明（反证）**：假设存在状态 $s$，使 $\mathtt{dfs}(s)$ 在两条调用路径上返回不同值 $r_1 \ne r_2$。则函数内部的所有"子调用 + 合并"过程会因调用上下文不同而产生不同结果——这意味着函数行为依赖于"如何到达 $s$"，违反无后效性。

反之，若问题无后效性，则 $\mathtt{dfs}(s)$ 只取决于 $s$，缓存替代重新计算就是合法的。$\blacksquare$

### 每个状态最多计算一次

**命题**：从入口调用开始，整个递归过程中每个状态 $s$ 最多被"实际计算"一次（不计缓存命中的查询）。

**证明**：考察某状态 $s$ 第一次被调用——此时 $\mathtt{memo}[s]$ 是未访问标记，函数走完整个计算流程并把结果写入 $\mathtt{memo}[s]$。

之后任何对 $\mathtt{dfs}(s)$ 的调用，都会在缓存检查处直接返回——不再触发递归计算。

由此，每个状态的"完整计算流程"最多发生一次。$\blacksquare$

### 复杂度的来源

设状态总数为 $N$，单个状态的计算（不算递归子调用）耗时 $T$。由"每个状态最多计算一次"，所有"完整计算"加起来贡献 $O(N \cdot T)$。

缓存命中的调用是 $O(1)$，调用次数受递归结构限制，常数级，不改变量级。

总时间 $O(N \cdot T)$，空间 $O(N)$（`memo`）+ $O(D)$（递归栈深度，$D$ 为递归最深层数）。$\blacksquare$

### 记忆化搜索 ≡ 动态规划

**命题**：任何无后效性的递归问题，记忆化搜索得到的答案与自底向上 dp 的答案完全相同。

**证明**：两种方法都是在求解递推方程

$$f(s) = \text{combine}\left(f(s_1), f(s_2), \ldots, f(s_k)\right) \quad (s_1, \ldots, s_k \text{ 是 } s \text{ 的子状态})$$

- 自底向上 dp：按拓扑序（依赖顺序）逐个填表

- 记忆化搜索：从顶层调用，按需展开依赖，递归到底后回溯填表

两者本质都是把 $f$ 的依赖图（DAG）按拓扑序求解，只是遍历顺序不同。最终每个 $f(s)$ 的取值由相同的递推式决定，结果一致。$\blacksquare$

### 为什么必须"算完再写缓存"

**反例**：若提前把"未完成"的中间值写入 `memo`，递归途中读到这个未完成值会得到错误答案。

更微妙的情况是**自引用**——若在递归过程中再次需要 $\mathtt{dfs}(s)$ 的值（即依赖图有环），记忆化搜索会陷入"等待自己"的死循环。这对应于问题**有后效性**或**存在循环依赖**——这种情况下记忆化搜索本身就不适用，需要换成迭代法或用其他算法（如最短路）。

正确的写法永远是：**先递归算完所有子问题，组合得到结果，最后一步写入 `memo`**。$\blacksquare$

## 与自底向上 dp 的对比

| 维度        | 记忆化搜索                | 自底向上 dp           |
| --------- | -------------------- | ----------------- |
| 写法        | 递归 + 缓存              | 多重循环填表            |
| 状态计算顺序    | 自动按依赖展开              | 必须人工设计拓扑序         |
| 计算的状态范围   | 仅入口可达的状态             | 所有状态全填            |
| 空间        | $O(N) + O(D)$（含递归栈）  | $O(N)$            |
| 常数        | 较大（函数调用开销）           | 较小                |
| 代码贴近转移方程  | ✅ 几乎机械翻译             | 需要重新组织循环          |
| 容易爆栈      | ✅（深度大时）              | ❌                 |
| 滚动数组优化    | 较难                   | 较容易               |

**经验**：状态转移复杂、依赖关系绕（如 [[数位dp]]、[[树形dp]] 中的某些情形）→ 优先记忆化搜索；状态转移规整、要求极致优化（卡常或滚动数组）→ 自底向上 dp。
