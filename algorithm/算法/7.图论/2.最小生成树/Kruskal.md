#难度/★★★

> 把所有边按权值升序排序，依次尝试加入"不形成环"的边——并查集动态判环，贪心构造最小生成树。

## 前置知识

- [[并查集]]

- [[排序贪心]]

## 核心思想

**最小生成树（MST）**：连通图 $G$ 的一棵生成树（含全部 $n$ 个节点的无环连通子图，恰有 $n - 1$ 条边）中，**边权和最小**的那一棵。

Kruskal 用最朴素的贪心构造 MST：

> 把所有 $m$ 条边按权值**升序**排序；依次扫描每条边 $(u, v, w)$——若 $u, v$ 当前**不连通**，就把这条边加入 MST，否则跳过；直到加入 $n - 1$ 条边为止。

实现的关键是**快速判断 $u, v$ 是否连通**，并在加边后动态维护连通性。这正是 [[并查集]] 的看家本领——`find(u)` 找 $u$ 的代表元，`find(u) == find(v)` 即两点连通；`union(u, v)` 合并两个连通块。每次操作均摊 $O(\alpha(n)) \approx O(1)$。

为什么"按权值升序贪心"是对的？这要靠图论中经典的 **割性质（cut property）**：对图的任一切（把节点分为两个非空集合 $S, V \setminus S$），所有横跨切的边中，**权值最小的那条**必然属于某棵 MST。Kruskal 每次选择的最小边在并查集视角下都是某个切的最小横跨边，所以它的每一步选择都是最优的。详见正确性证明。

## 适用场景

- **求最小生成树**——稀疏图首选（边少时排序代价小）

- 经典扩展：

  - **次小生成树**：枚举非 MST 边替换

  - **最小瓶颈生成树**：MST 即最小化最大边权

  - **Boruvka 算法**：与 Kruskal 同源的并行 MST

- 不适用：稠密图且边多到 $m \log m$ 不能接受（用 [[Prim]] 朴素 $O(n^2)$）

## 步骤拆解

1. 把所有边按权值升序排序

2. 初始化并查集：每个节点独立成块

3. 顺序扫描每条边 $(u, v, w)$：

   a. 若 `find(u) != find(v)`：执行 `union(u, v)`，把 $w$ 累加到答案，加边数 + 1

   b. 否则跳过

4. 当加边数 $= n - 1$ 时算法结束，得到一棵 MST

## 代码模板

```cpp

class kruskal {

private:

    int n;

    struct edge {

        int u, v;

        long long w;

        bool operator<(const edge& o) const {

            return w < o.w;

        }

    };

    vector<edge> es;

    vector<int> fa;

    int find(int x) {

        if (fa[x] == x) {

            return x;

        }

        return fa[x] = find(fa[x]);              // 路径压缩

    }

public:

    kruskal(int total, vector<edge>& edges) {

        n = total;

        es = edges;

        fa.resize(n + 1);

    }

    // 返回 MST 总权值；若图不连通则返回 -1
    long long solve() {

        sort(es.begin(), es.end());

        for (int i = 1; i <= n; i++) {

            fa[i] = i;

        }

        long long total = 0;

        int cnt = 0;

        for (auto& e : es) {

            int fu = find(e.u);

            int fv = find(e.v);

            if (fu != fv) {

                fa[fu] = fv;

                total += e.w;

                cnt += 1;

                if (cnt == n - 1) {

                    break;                       // 已凑齐 n-1 条边

                }

            }

        }

        return cnt == n - 1 ? total : -1;

    }

};
```

> 💡 **路径压缩 + 按秩合并**：竞赛中通常路径压缩就够了，足以让并查集均摊 $O(\alpha(n))$。完整理论保证需配合按秩合并，详见 [[并查集]]。

> 💡 **提前结束**：当 `cnt == n - 1` 时立即 `break`，省去对剩余边的扫描。这在边数远多于 $n$ 时能显著提速。

## 复杂度分析

- 时间复杂度：$O(m \log m)$（排序占主导）+ $O(m \cdot \alpha(n))$（并查集）= $O(m \log m)$

- 空间复杂度：$O(n + m)$

## 正确性证明

### 割性质（Cut Property）

**定义（割）**：对图 $G = (V, E)$ 的一个非空真子集 $S \subset V$，称无序对 $(S, V \setminus S)$ 为一个**割**。一条边 $(u, v)$ **横跨**这个割，当且仅当 $u \in S$ 且 $v \in V \setminus S$（或反之）。

**割性质**：设 $C$ 是 $G$ 的某个割上**所有横跨边**的集合。若 $C$ 中存在唯一的最小权边 $e^*$，则 $e^*$ 属于 $G$ 的**任何一棵** MST。

> 我们用稍弱的版本就够：若 $e^*$ 是 $C$ 中权值最小的边（不要求唯一），则**存在某棵** MST 含 $e^*$。

**证明（交换论证）**：

设 $T$ 为任一棵 MST。若 $e^* \in T$，命题已成立。

否则 $T$ 不含 $e^*$。由 $T$ 是生成树（连通无环），把 $e^*$ 加入 $T$ 形成**唯一一个环** $C^*$（树加边形成环的标准结论）。

环 $C^*$ 在割 $(S, V \setminus S)$ 中**至少穿越两次**（因为环从 $S$ 出发回到 $S$，每次穿越用一条横跨边，必为偶数次）。$e^*$ 是其中一次穿越——必存在另一条横跨边 $e' \in C^* \setminus \{e^*\}$。

由 $e^*$ 是横跨边中权值最小者，$w(e') \ge w(e^*)$。

构造 $T' = T \setminus \{e'\} \cup \{e^*\}$：

- $T'$ 仍是生成树：从 $T$ 去掉 $e'$ 把它分成两个连通块，$e^*$ 把它们重新连接（因 $e^*, e'$ 都在环 $C^*$ 上，去 $e'$ 加 $e^*$ 仍连通）；边数仍为 $n - 1$。

- $w(T') = w(T) - w(e') + w(e^*) \le w(T)$。

由 $T$ 已是 MST，$w(T') \le w(T)$ 蕴含 $w(T') = w(T)$，即 $T'$ 也是 MST，且含 $e^*$。$\blacksquare$

### Kruskal 的正确性

**主定理**：Kruskal 算法终止时得到的边集 $T$ 是一棵 MST。

**证明（归纳）**：以下用 $T_i$ 表示算法**加入第 $i$ 条边后**的边集（$T_0 = \emptyset$）。声明不变量：

> **不变量**：每个 $T_i$ 都是某棵 MST 的子集。

**基础**：$T_0 = \emptyset$ 是任何 MST 的子集。

**归纳**：假设 $T_{i-1}$ 是某棵 MST $T^*$ 的子集。考察第 $i$ 步加入的边 $e = (u, v)$，由算法逻辑——$e$ 是按权值升序扫描中**第一条让 $u, v$ 已连通块合并**的边。

在加入 $e$ 之前，$T_{i-1}$ 把节点划分成若干连通块。设 $S = $ "包含 $u$ 的连通块"。$v \notin S$（否则 $u, v$ 已连通，$e$ 不会被选）。考虑割 $(S, V \setminus S)$：

- $e$ 横跨此割（$u \in S, v \notin S$）。

- $e$ 是当前所有未被处理边中**权值最小**的。

- 此前所有"被跳过的边"（端点在同一连通块）都不横跨 $(S, V \setminus S)$——因为它们的两端在同一个之前合并好的连通块里，而 $S$ 由这些合并产生。

**关键**：$(S, V \setminus S)$ 上的横跨边只能在"还未被处理的边"中出现，而它们都按权值升序排列。所以 $e$ 是 $(S, V \setminus S)$ 上权值最小的横跨边。

由割性质，存在某棵 MST $T^{**}$ 含 $T_{i-1} \cup \{e\}$（具体构造：若 $T^*$ 已含 $e$，取 $T^{**} = T^*$；否则交换论证替换为含 $e$ 的 MST，且仍含 $T_{i-1}$——因为被换出的横跨边不在 $T_{i-1}$ 中，因为 $T_{i-1}$ 不含横跨 $(S, V \setminus S)$ 的边，否则破坏 $S$ 的定义）。

所以 $T_i = T_{i-1} \cup \{e\}$ 仍是某棵 MST 的子集。

**终止**：算法加入恰好 $n - 1$ 条边后停止。由不变量，$T_{n-1}$ 是某棵 MST 的子集；又 MST 恰有 $n - 1$ 条边——所以 $T_{n-1}$ 就是该 MST 本身。$\blacksquare$

### 复杂度的来源

- 排序：$O(m \log m)$

- 并查集：$m$ 次 `find` + 至多 $n - 1$ 次 `union`，每次均摊 $O(\alpha(n))$，共 $O(m \alpha(n))$

- 总复杂度 $O(m \log m + m \alpha(n)) = O(m \log m)$

由于 $m \le n^2$，$\log m \le 2 \log n$，所以也写作 $O(m \log n)$。$\blacksquare$

## 与 [[Prim]] 的对比

| 维度        | Kruskal                | Prim 朴素      | Prim 堆优化          |
| --------- | ---------------------- | ------------ | ----------------- |
| 复杂度       | $O(m \log m)$          | $O(n^2)$     | $O((n+m) \log n)$ |
| 适合图密度     | 稀疏图                    | 稠密图          | 稀疏图               |
| 数据结构      | 并查集 + 排序               | 数组           | 优先队列              |
| 代码量       | 短                      | 极短           | 中等                |
| 处理多个连通块   | 自然支持（最后判 `cnt == n-1`） | 需起多次（每个连通块）  | 同朴素               |


**经验**：竞赛中 Kruskal 用得更多——代码短、容易写对、并查集也是常用工具。Prim 仅在稠密图（$n^2$ 个边）下用朴素 $O(n^2)$ 版本更优。
