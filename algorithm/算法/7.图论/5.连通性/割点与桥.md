#难度/★★★★

> 同样基于 dfn / low 时间戳的 DFS——一遍 $O(n + m)$ 找出无向图中所有的"删除后会让图断开"的关键点和边。

## 前置知识

- [[DFS]]

- [[Tarjan]]

## 核心思想

**割点（cut vertex / articulation point）**：无向连通图中，删除该点（连同其所有边）后图变得**不连通**的点。

**桥（bridge）**：无向连通图中，删除该边后图变得不连通的边。

> 注：以下都讨论无向图。有向图的对应概念是 [[Tarjan]] 中的 SCC 缩点。

直觉上，割点和桥是图的"咽喉要道"。识别它们对网络可靠性、电路设计、社区发现等都有重要意义。

**算法核心**——和 [[Tarjan]] 一样基于 dfn / low 框架的 DFS：

- $\mathtt{dfn}[u]$：$u$ 的 DFS 序

- $\mathtt{low}[u]$：$u$ 的子树中通过边能"绕回"到的最小 dfn 值

**判定规则**——

**桥**：树边 $(u, v)$（其中 $v$ 是 $u$ 的子节点）是桥 $\Leftrightarrow$ $\mathtt{low}[v] > \mathtt{dfn}[u]$。

**含义**：$\mathtt{low}[v] > \mathtt{dfn}[u]$ 意味着从 $v$ 子树出发**没有任何路径**绕过 $u$ 回到祖先——所以删掉边 $(u, v)$ 后 $v$ 子树就和上面失去了连接。

**割点**：分两类——

- **非根节点 $u$**：$u$ 是割点 $\Leftrightarrow$ 存在子节点 $v$ 使 $\mathtt{low}[v] \ge \mathtt{dfn}[u]$

- **根节点 $u$**：$u$ 是割点 $\Leftrightarrow$ 在 DFS 树中至少有 2 个子节点

**含义**：$\mathtt{low}[v] \ge \mathtt{dfn}[u]$ 意味着 $v$ 子树最远只能"绕到 $u$"，绕不过 $u$——删 $u$ 后 $v$ 子树孤立。

> ⚠️ **桥用 $>$，割点用 $\ge$，不要混淆**。这一字之差是因为：桥要求"绕不到 $u$ 之上"（可以绕到 $u$ 但不算桥消失，因为 $u$ 还在），而割点要求"绕不过 $u$"（绕到 $u$ 也不行，因为 $u$ 被删了）。

## 适用场景

- 求无向图的所有割点和桥

- **双连通分量分解**：用桥把图分成若干"边双连通分量"（每对边都在某个简单环上）

- **网络脆弱性分析**：找出网络中"删了就崩"的关键节点

- **离线 LCA**（[[LCA]] 的 Tarjan 离线算法）的近亲框架

- 不适用：有向图（用 [[Tarjan]] 求 SCC）；动态加删边问题（用 LCT 等高级数据结构）

## 步骤拆解

1. 初始化 $\mathtt{dfn}, \mathtt{low}$ 全 0，$\mathtt{timer} = 0$

2. 对每个连通块从某个起点调用 $\mathtt{dfs}(\mathtt{root}, 0)$（0 表示无来时边）

3. $\mathtt{dfs}(u, \mathtt{from\_edge})$：

   a. $\mathtt{timer} \mathrel{+}= 1$；$\mathtt{dfn}[u] = \mathtt{low}[u] = \mathtt{timer}$

   b. 维护 $\mathtt{child\_count} = 0$（仅根节点用）

   c. 枚举每条出边 $(u, v, e)$：

     - 若 $e = \mathtt{from\_edge}$：跳过（不走来时边）

     - 若 $\mathtt{dfn}[v] = 0$（树边）：递归，回溯后用 $\mathtt{low}[v]$ 更新 $\mathtt{low}[u]$；再判桥与割点

     - 否则（返祖边或重边）：$\mathtt{low}[u] = \min(\mathtt{low}[u], \mathtt{dfn}[v])$

   d. 若 $u$ 是根且 $\mathtt{child\_count} \ge 2$：$u$ 是割点

## 代码模板

**核心实现细节**——无向图中每条边在邻接表中存两份（双向），递归时若用"父节点"判断会被重边坑（重边的父节点是同一个，会误以为是返祖边）。**正确做法是用边的编号判断**：用 `from_edge` 记录"我是从哪条边来的"，跳过这条边的反向即可。

```cpp
class cut_vertex_bridge {

private:

    int n;

    vector<vector<pair<int, int>>> g;           // g[u] = {邻居, 边编号}

    vector<int> dfn, low;

    vector<bool> is_cut;

    vector<bool> is_bridge;                     // 索引为边编号

    int timer;

    // from_edge = 来时的边编号；root 入口传 0
    void dfs(int u, int from_edge) {

        timer += 1;

        dfn[u] = low[u] = timer;

        int child_count = 0;

        for (auto [v, e] : g[u]) {

            if (e == from_edge) {

                continue;                       // 不走回头路

            }

            if (dfn[v] == 0) {

                child_count += 1;

                dfs(v, e);

                low[u] = min(low[u], low[v]);

                // 桥的判定
                if (low[v] > dfn[u]) {

                    is_bridge[e] = true;

                }
                
                // 非根割点的判定
                if (from_edge != 0 && low[v] >= dfn[u]) {

                    is_cut[u] = true;

                }

            } else {

                low[u] = min(low[u], dfn[v]);

            }

        }

        // 根节点割点的判定
        if (from_edge == 0 && child_count >= 2) {

            is_cut[u] = true;

        }

    }

public:

    cut_vertex_bridge(int total, vector<vector<pair<int, int>>>& g_in) {

        n = total;

        g = g_in;

    }

    void solve() {

        dfn.assign(n + 1, 0);

        low.assign(n + 1, 0);

        is_cut.assign(n + 1, false);

        // is_bridge 大小由边数决定，用前调用方分配

        timer = 0;

        for (int u = 1; u <= n; u++) {

            if (dfn[u] == 0) {

                dfs(u, 0);

            }

        }

    }

};

```

> 💡 **存边技巧**：建图时第 $i$ 条无向边 $(u, v)$ 通常存为两条有向边，编号 $2i - 1$ 和 $2i$（或 $2i$ 和 $2i + 1$）。用 `e xor 1` 即可由一条边找到反向边。这种存法在网络流中也很常见。

```cpp
// 错误代码（重边时出问题）

void dfs(int u, int parent) {

    for (int v : g[u]) {

        if (v == parent) continue;  // 错！若 u-parent 之间有重边，反向边也被跳过

        ...

    }

}
```

> 当 $u$ 与父节点之间有重边时，"父节点判定"会跳过所有指向父节点的边——但其中一条反向边其实应该被视为返祖边参与 low 更新。改用边编号即可避免。

## 复杂度分析

- 时间复杂度：$O(n + m)$

- 空间复杂度：$O(n + m)$

## 正确性证明

### 桥的判定

**命题**：树边 $(u, v)$（$v$ 是 $u$ 的 DFS 子节点）是桥 $\Leftrightarrow$ $\mathtt{low}[v] > \mathtt{dfn}[u]$。

**"$\Leftarrow$"（$\mathtt{low}[v] > \mathtt{dfn}[u] \Rightarrow$ 是桥）**：

$\mathtt{low}[v] > \mathtt{dfn}[u]$ 意味着 $v$ 子树中没有节点能通过返祖边到达 $u$ 或 $u$ 的祖先。

删除 $(u, v)$ 后，$v$ 子树与图的其余部分**断开**：

- 通过 DFS 树的连接：$(u, v)$ 是 $v$ 子树与外界唯一的树边连接，被删后这条线断了

- 通过非树边的连接：由 $\mathtt{low}[v] > \mathtt{dfn}[u]$，没有任何返祖边能"绕过 $(u, v)$"

所以删除 $(u, v)$ 后 $v$ 子树不再与其他部分连通——是桥。

**"$\Rightarrow$"（是桥 $\Rightarrow \mathtt{low}[v] > \mathtt{dfn}[u]$）（反证）**：

若 $\mathtt{low}[v] \le \mathtt{dfn}[u]$，则存在某节点 $w$ 在 $v$ 子树中（含 $v$），通过非树边能到达 dfn $\le \mathtt{dfn}[u]$ 的某节点 $w'$。$w'$ 是 $u$ 自己或 $u$ 的祖先。

删除 $(u, v)$ 后，仍有路径 $v \to^* w \to w' \to^* u$（$w' \to^* u$ 沿 DFS 树）——$v$ 子树与 $u$ 仍连通，$(u, v)$ 不是桥。$\blacksquare$

### 割点的判定（非根）

**命题**：非根节点 $u$ 是割点 $\Leftrightarrow$ 存在子节点 $v$ 使 $\mathtt{low}[v] \ge \mathtt{dfn}[u]$。

**"$\Leftarrow$"**：

$\mathtt{low}[v] \ge \mathtt{dfn}[u]$ 意味着 $v$ 子树中没有节点能"绕过 $u$"到达 $u$ 的祖先（最远只能绕到 $u$ 自己）。删除 $u$ 后，$v$ 子树与 $u$ 的祖先（含父节点 $\mathtt{parent}(u)$）失去连接。

剩余图中至少分成两部分：含 $\mathtt{parent}(u)$ 的部分和含 $v$ 子树的部分——$u$ 是割点。

**"$\Rightarrow$"（反证）**：

若所有子节点 $v$ 都满足 $\mathtt{low}[v] < \mathtt{dfn}[u]$，每个子树都能绕过 $u$ 到达 $u$ 的祖先。删除 $u$ 后，所有子树仍能连接到 $u$ 的祖先——通过祖先互相连通——图保持连通，$u$ 不是割点。$\blacksquare$

### 割点的判定（根节点）

**命题**：根节点 $u$ 是割点 $\Leftrightarrow$ 在 DFS 树中至少有 2 个子节点。

**证明**：

**"$\Leftarrow$"**：根有两个子节点 $v_1, v_2$。$v_1$ 子树与 $v_2$ 子树**只能通过 $u$ 连接**（DFS 树之外的边只能是返祖边，不能跨过根的不同子树——这是 DFS 的关键性质）。删除 $u$ 后两个子树孤立，$u$ 是割点。

**"$\Rightarrow$"**：若根只有 1 个子节点，删除根后剩余图就是该子节点的子树——若它原本连通则现在仍连通，$u$ 不是割点。$\blacksquare$

> 💡 **DFS 树无横叉边**：无向图的 DFS 树有个重要性质——所有非树边都是"返祖边"（子孙到祖先），不存在"横叉边"（不同子树间的边）。理由：若有横叉边 $(u, v)$ 连接两个不同子树，DFS 必然从某子树 $u$ 沿这条边访问 $v$——那 $v$ 就成了 $u$ 的子孙而非另一子树。这正是为什么"根的不同子树间没有连接"。

### 桥与割点的细微差别（$>$ 与 $\ge$）

为什么桥用 $\mathtt{low}[v] > \mathtt{dfn}[u]$ 而割点用 $\mathtt{low}[v] \ge \mathtt{dfn}[u]$？

考虑临界情形 $\mathtt{low}[v] = \mathtt{dfn}[u]$——$v$ 子树能通过返祖边绕回 $u$ 自己，但绕不到 $u$ 的祖先。

- 删除**边 $(u, v)$**：$v$ 子树仍能通过那条返祖边连到 $u$ —— **不是桥**

- 删除**点 $u$**：$u$ 没了，那条返祖边的另一端也被删 —— $v$ 子树孤立 —— **是割点**

所以桥要求严格大于，割点允许等于。$\blacksquare$

### 复杂度的来源

DFS 一次 $O(n + m)$；每条边检查一次，每个节点处理 $O(1)$。$\blacksquare$

## 重要扩展：边双连通分量

**边双连通分量（edge biconnected component, e-BCC）**：把所有桥从图中删除后，每个连通块就是一个边双连通分量。

性质：e-BCC 内任意两点之间至少有 2 条**边不相交**的路径。

**应用**：把每个 e-BCC 缩成一个点，桥保留——得到一棵**树**（"桥树"或"e-BCC 树"）。这把"图上路径问题"转化为"树上路径问题"，是很多问题的关键转化。

## 与 [[Tarjan]] 的联系

割点 / 桥与 Tarjan 求 SCC 的算法**共用 dfn / low 的框架**，区别在于：

| 维度         | Tarjan SCC（有向图）       | 割点/桥（无向图）               |
| ---------- | --------------------- | ----------------------- |
| 图类型        | 有向图                   | 无向图                     |
| 用栈         | 维护"待确定 SCC"的节点        | 不需要                     |
| low 定义     | 子树可达的最小栈中节点 dfn       | 子树可达的最小 dfn             |
| "回头路"处理    | 按 in_stack 判定         | 用边编号判定（避免重边坑）           |

**记忆点**：dfn / low 是一套通用工具——一遍 DFS 就能挖出图的诸多结构性质。
