#难度/★★★★

> 把二维问题按某轴排序后逐个事件处理——经典的二维降一维思想，配合特殊线段树解决矩形面积并、周长并等。

- [[懒标记线段树]]

## 核心思想

**为什么要"扫描"？** 直接计算 $n$ 个矩形并集的面积是个二维难题。但若沿 $x$ 轴从左到右走，每两个相邻"事件"之间——`哪些矩形当前活跃`是不变的——也就是说，**在这一段 $x$ 区间内问题退化成一维**。这就是"扫描线"的根本思想：**把二维问题切成若干一维子问题**。

**事件化建模**：每个矩形 $[x_1, x_2] \times [y_1, y_2]$ 拆成两个事件——

- 在 $x_1$ 处"矩形开始"（活跃集合 $+1$）

- 在 $x_2$ 处"矩形结束"（活跃集合 $-1$）

把这些事件按 $x$ 升序排序后依次处理。两个相邻事件 $x_i, x_{i+1}$ 之间没有变化，对面积的贡献 $=$ $(x_{i+1} - x_i)$ $\times$ $($当前 $y$ 轴被覆盖至少一次的总长$)$。

**用一棵"特殊"线段树维护"另一维状态"**：线段树节点对应一段离散化后的 $y$ 区间，每个节点存两个量——

- `cover`：该节点对应区间被多少个"当前活跃矩形"完全覆盖

- `length`：该节点对应区间内被覆盖至少一次的 $y$ 长度

**关键设计——cover 不下传**：扫描线的 `cover` 是"**标记永久化**"的计数器——**不会传给子节点**。代价是 `length` 在每次 update 后要重新自底向上算；好处是逻辑大大简化（不用写复杂的懒标记下传）。这正是扫描线相对普通懒标记线段树最优美的地方。

**不变量**：扫描到任何时刻，根节点 `length[1]` 等于"当前 $y$ 轴被覆盖至少一次的总长度"。

> 💡 **为什么需要 [[离散化]]**：原始 $y$ 值可能高达 $10^9$，但所有事件只涉及 $2n$ 个不同的 $y$ 值——把它们离散化压到 $[1, m]$，线段树才开得下。

## 适用场景

- **矩形面积并** / **矩形周长并**（最经典应用）

- **二维偏序问题**：把某维度作为扫描时间，另一维度用 BIT / 线段树维护

- **离线区间问题**：把所有查询按右端点排序后扫描

- **三维偏序的标准做法**之一：[[CDQ分治]] + 扫描线

- **几何问题**：圆的面积并（变体扫描线）、最近点对（分治 + 扫描线）

- 不适用：要求强制在线（扫描线本质是离线）；维度更高时需嵌套使用扫描线

## 步骤拆解

以矩形面积并为例——

1. **建事件**：把每个矩形 $[x_1, y_1, x_2, y_2]$ 拆成两个事件 $(x_1, y_1, y_2, +1)$ 和 $(x_2, y_1, y_2, -1)$

2. **离散化 $y$ 坐标**：所有 $y_1, y_2$ 收集起来排序去重，得到 $m$ 个 $y$ 段

3. **建特殊线段树**：节点对应"$y$ 段"，维护 `cover` 和 `length`

4. **按 $x$ 排序事件**，逐个处理——

   - 先累加 `(当前 x - 上次 x) × length[1]` 到答案

   - 然后应用当前事件（在 $[y_1, y_2]$ 段上 `cover += val`，回溯时重算 `length`）

5. **最终答案**即为矩形并集总面积

## 代码模板

```cpp

class scanline_rect_area {

private:

    struct event {

        long long x;

        long long y1, y2;

        int type;                               // +1 = 矩形开始, -1 = 矩形结束

        bool operator<(const event& o) const {

            return x < o.x;

        }

    };

    int m;                                      // 离散化 y 段数

    vector<long long> ys;                       // 离散化 y 数组

    vector<int> cover;                          // 每个节点被矩形覆盖的次数

    vector<long long> length;                   // 每个节点对应区间内被覆盖的总长

    // 注意：线段树维护的是"y 段"——第 i 段对应 y 区间 [ys[i-1], ys[i]]

    void update(int p, int l, int r, int ql, int qr, int val) {

        if (ql <= l && r <= qr) {

            cover[p] += val;

        } else {

            int mid = l + (r - l) / 2;

            if (ql <= mid) {

                update(p * 2, l, mid, ql, qr, val);

            }

            if (mid <  qr) {

                update(p * 2 + 1, mid + 1, r, ql, qr, val);

            }

        }

        // 重算 length：cover > 0 时整段被覆盖，否则由子节点决定
        if (cover[p] > 0) {

            length[p] = ys[r] - ys[l - 1];

        } else if (l == r) {

            length[p] = 0;

        } else {

            length[p] = length[p * 2] + length[p * 2 + 1];

        }

    }

public:

    long long compute(vector<vector<long long>>& rects) {

        vector<event> events;

        for (auto& r : rects) {

            // r = [x1, y1, x2, y2]

            events.push_back({r[0], r[1], r[3],  1});

            events.push_back({r[2], r[1], r[3], -1});

            ys.push_back(r[1]);

            ys.push_back(r[3]);

        }

        sort(ys.begin(), ys.end());

        ys.erase(unique(ys.begin(), ys.end()), ys.end());

        sort(events.begin(), events.end());

        m = ys.size() - 1;                      // y 段数

        cover.assign(4 * m + 5, 0);

        length.assign(4 * m + 5, 0);

        long long total_area = 0;

        for (int i = 0; i < (int)events.size(); i++) {

            if (i > 0) {

                long long width = events[i].x - events[i - 1].x;

                total_area += width * length[1];

            }

            // 找 [y1, y2] 对应的离散化段范围 [l, r]
            int l = lower_bound(ys.begin(), ys.end(), events[i].y1) - ys.begin() + 1;

            int r = lower_bound(ys.begin(), ys.end(), events[i].y2) - ys.begin();

            if (l <= r) {

                update(1, 1, m, l, r, events[i].type);

            }

        }

        return total_area;

    }

};
```

> 💡 **"段"与"点"的关键区别**：扫描线的线段树维护 $y$ 上的**段**（区间），不是点。第 $i$ 段对应 $y$ 区间 $[\mathtt{ys}[i-1], \mathtt{ys}[i]]$，共 $m = \mathtt{ys.size()} - 1$ 段。

> 💡 **`l = ... + 1, r = ...` 的下标偏移**：要把"$y$ 区间 $[y_1, y_2]$"映射为"段 $l$ 到段 $r$"——

> - 段 $i$ 的左端点是 $\mathtt{ys}[i - 1]$，右端点是 $\mathtt{ys}[i]$

> - $y_1$ 对应的"起始段"是第一个左端点 $= y_1$ 的段，即 `lower_bound(ys, y1) - ys.begin() + 1`

> - $y_2$ 对应的"结束段"是最后一个右端点 $= y_2$ 的段，即 `lower_bound(ys, y2) - ys.begin()`

> ⚠️ **不下传 cover**：`cover` 是"标记永久化"的计数器，不是普通懒标记。下传它会让代码变复杂且易错。每次 update 后重新计算 length 即可——这是扫描线最特殊的地方。

## 复杂度分析

- 时间复杂度：

  - 离散化预处理：$O(n \log n)$（排序 + 去重）

  - 单个事件处理：$O(\log n)$（线段树更新 + 沿路径重算 length）

  - 总体（$n$ 个矩形 $= 2n$ 个事件）：$O(n \log n)$

- 空间复杂度：$O(n)$（事件 + 离散化数组 + $4m$ 大小的线段树节点）

## 正确性证明

### 扫描总面积如何被正确累加

**按 $x$ 切片**：把整个平面按事件 $x$ 坐标切成若干"垂直条带"——每个条带 $[x_i, x_{i+1}]$ 内**没有事件发生**，所以条带内"哪些矩形当前活跃"是固定的。

**条带面积**：条带 $[x_i, x_{i+1}]$ 内被矩形并集覆盖的部分 $=$ 条带宽度 $\times$ 条带内被覆盖的 $y$ 总长。$y$ 总长 $=$ 处理完事件 $i - 1$ 后线段树根节点的 $\mathtt{length}[1]$。

**累加得总面积**：所有条带面积之和 $=$ 矩形并集总面积。算法在处理事件 $i$ 前累加 `(events[i].x - events[i-1].x) * length[1]`，恰好对应条带 $[x_{i-1}, x_i]$ 的面积。

### length 的语义如何在每个节点上保持

对每个节点 $p$ 对应区间 $[l, r]$（指 $y$ 段范围 $[l, r]$，即 $y$ 实际范围 $[\mathtt{ys}[l-1], \mathtt{ys}[r]]$），$\mathtt{length}[p]$ 始终满足：

> $\mathtt{length}[p] =$ "该节点对应 $y$ 区间内被当前活跃矩形覆盖的总长度"

按节点状态分类——

**叶子节点**（$l = r$）：

- 若 $\mathtt{cover}[p] > 0$：该段被某矩形覆盖，length $= \mathtt{ys}[r] - \mathtt{ys}[l-1]$

- 若 $\mathtt{cover}[p] = 0$：无更细子节点支持，length $= 0$

**内部节点**：

- 若 $\mathtt{cover}[p] > 0$：当前节点被某些矩形完全覆盖——整段都活跃，length $= \mathtt{ys}[r] - \mathtt{ys}[l-1]$

- 若 $\mathtt{cover}[p] = 0$：当前节点不被任何矩形**直接**覆盖；但子节点可能被覆盖——length $=$ 左孩子 length $+$ 右孩子 length

**关键现象**：当 $\mathtt{cover}[p] > 0$ 时，即使子节点的 $\mathtt{cover}$ 都为 0、子节点的 $\mathtt{length}$ 也都为 0，当前节点的 $\mathtt{length}$ 仍然是整段长度——这正是"标记永久化"的精髓：父节点的 `cover` 标记**始终生效，不下传**。

### 不下传 cover 为什么不出错

普通懒标记线段树要求"标记下传后子节点保持一致"——但扫描线的 `cover` 没有这种需求。

每次 `update` 函数在递归返回时**重新计算 length**——

```
if (cover[p] > 0):
    length[p] = ys[r] - ys[l-1]

else if (l == r):

    length[p] = 0

else:

    length[p] = length[p*2] + length[p*2+1]
```

回溯时按"自底向上"的顺序更新——孩子的 length 已正确，父节点的 length 由"自己 cover 是否 > 0"和孩子 length 共同决定，结果正确。

而我们查询的对象是**根节点**的 `length[1]`——它在每次 update 后立即被刷新。所以中间节点的 `length` 即使因 `cover` 不下传而看起来"不一致"，也不影响最终结果。

### 离散化的合理性

事件中只有有限个 $y$ 坐标（$2n$ 个），其他 $y$ 值不会改变 `cover` 状态。离散化把 $y$ 值压到 $[1, m]$，不丢失任何信息——因为线段树只关心"段间的覆盖状态变化"，段内部的具体 $y$ 值是均匀的。

$\blacksquare$

## 应用扩展

**矩形周长并**：比面积并稍复杂——既要扫描垂直边算水平贡献，也要扫描水平边算垂直贡献。一种简洁实现是在面积并的扫描中维护 $\mathtt{prev\_length}$（上次的 length），每次事件后水平贡献为 $|\mathtt{length}[1] - \mathtt{prev\_length}|$。

**扫描线 + 离线**：很多看似无关二维的问题也能用——

- **离线区间问题**：每次询问 $(l, r)$ 看作平面点 $(l, r)$，按 $r$ 升序处理——扫描 $r$，维护"当前 $r$ 下每个 $l$ 的答案"用 BIT

- **三维偏序**：[[CDQ分治]] 时一维分治、一维归并排序、一维扫描线（BIT）

## 与其他二维降维方法对比

| 方法            | 适用场景                   | 复杂度                    | 备注            |
| ------------- | ---------------------- | ---------------------- | ------------- |
| 扫描线           | 二维到一维，需维护"另一维状态"       | $O(n \log n)$          | 离线，最常用        |
| [[CDQ分治]]     | 三维偏序、决策单调性 dp 优化       | $O(n \log^2 n)$        | 配合归并、扫描线使用    |
| [[整体二分]]      | 多次同类查询，可用二分回答          | $O((n + q) \log^2 n)$  | 复杂的离线技巧       |
| K-D 树         | 多维点查询                  | $O(n \sqrt n)$         | 强制在线但常数大      |
