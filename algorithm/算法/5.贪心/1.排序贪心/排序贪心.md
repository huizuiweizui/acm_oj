#难度/★

> 把数据按某个关键字排序，再按顺序贪心选择——是最朴素也最常用的贪心范式。

## 核心思想

很多最优化问题中，最优解的"选择顺序"具有某种结构——**按某关键字排序后从前往后扫，每步都按某个简单规则选**，就能得到全局最优。

排序贪心的核心难点不在编码（一行 `sort` 加一个循环就完了），而在**找出"按什么排"以及证明"这样选最优"**。常见的排序依据：

- 按**单一属性**排：截止时间、价值、长度、权值等

- 按**两属性的比例**排：性价比 `value / weight`

- 按**两属性的组合**排：邻项交换法推出的"$a_i \cdot b_j$ vs $a_j \cdot b_i$"型不等式

证明手法主要有两种：

- **交换论证（exchange argument）**：假设最优解不符合贪心顺序，证明可以交换两项使解不变差

- **归纳法**：对扫到的第 $i$ 个元素，证明"贪心已选的部分"始终是"前 $i$ 个元素中的最优部分解"

## 适用场景

- 有"独立选择"语义的最优化问题（每项选或不选互不影响其他项的可行性）

- 任务调度类（按截止时间 / 处理时间 / 优先级排序）

- 经典模型：

  - **田忌赛马**：双方排序后用最弱马耗对方最强马

  - **任务调度最小化总等待时间**：按处理时间升序

  - **皇后游戏 / 接水问题**：邻项交换法推出比较函数

  - **分发糖果**：从两端分别贪心扫描

- 不适用：选择之间有强依赖（应使用 dp）；最优解不具备"局部最优 = 全局最优"性质

## 步骤拆解

1. **观察题目**：找出每个元素的关键属性（一个或多个）

2. **猜想排序方式**：从直觉出发——"想优先满足某个目标，把对该目标贡献大的排前面"

3. **证明正确性**（最重要）：用**交换论证**——假设存在更优解但顺序不同，则交换相邻两项后解不变差，反推贪心解最优

4. **实现**：`sort` + 一遍扫描

## 代码模板

**模板一：单关键字排序贪心——接水问题**

> $n$ 个人接水，第 $i$ 人需 $t_i$ 秒。求总等待时间（每人等待 = 自己接完 + 之前所有人接完的时间总和）最小值。

```cpp
// 答案 = sum_{i=1..n} (n - i + 1) * t[排序后第 i 个]
long long min_total_wait(vector<long long> t) {

    int n = t.size() - 1;

    sort(t.begin() + 1, t.end());           // 升序：耗时少的先接

    long long ans = 0;

    for (int i = 1; i <= n; i++) {

        ans += t[i] * (n - i + 1);

    }

    return ans;

}
```

**模板二:邻项交换法推比较函数——皇后游戏型**

> $n$ 个物品，每个有两个属性 $a_i, b_i$。某代价函数与排序顺序有关，求最小代价。

通过推导，往往能得出形如"按 $a_i / b_i$ 升序"或"按 $a_i + b_i$ 升序"的比较函数。**关键技巧**：写出"$i$ 排在 $j$ 前"和"$j$ 排在 $i$ 前"两种情形的代价差，整理出比较式。

```cpp
struct item {

    long long a, b;

};

// 假设推导得出的比较函数为：i 在 j 前 <=> a_i * b_j < a_j * b_i
bool cmp(const item& x, const item& y) {

    return x.a * y.b < y.a * x.b;

}

void solve(vector<item>& items) {

    int n = items.size() - 1;

    sort(items.begin() + 1, items.end(), cmp);

    // ... 按排好的顺序处理

}
```

> ⚠️ **比较函数必须传递性**：自定义 `cmp` 必须满足"严格弱序"——`cmp(a,b) && cmp(b,c) ⇒ cmp(a,c)`。比例式 `a*d < b*c` 通常自动成立，但加减式（如 `a+b < c+d`）有时不行，要小心。

**模板三：性价比排序——分数背包**

> $n$ 件物品，每件有重量 $w_i$ 和价值 $v_i$。允许**只取一部分**（即"分数背包"）。背包容量 $W$，求最大价值。

```cpp

struct goods {

    double w, v;

};

bool cmp(const goods& x, const goods& y) {

    return x.v / x.w > y.v / y.w;          // 性价比降序

}

double fractional_knapsack(vector<goods>& a, double W) {

    int n = a.size() - 1;

    sort(a.begin() + 1, a.end(), cmp);

    double ans = 0;

    for (int i = 1; i <= n; i++) {

        if (W >= a[i].w) {

            ans += a[i].v;

            W -= a[i].w;

        } else {

            ans += a[i].v * (W / a[i].w);  // 取一部分

            break;

        }

    }

    return ans;

}
```

> 💡 **整数背包不能贪心**：必须每件物品选或不选时（即 [[0-1背包]]），性价比排序贪心会错——这是 dp 出场的经典反例。

## 复杂度分析

- 时间复杂度：$O(n \log n)$（排序为主导）

- 空间复杂度：$O(1)$ 或 $O(n)$（取决于是否原地排序）

## 正确性证明

以接水问题为例，证明"按耗时升序"的贪心策略最优。

**交换论证**：

设排序后两相邻位置 $i$ 与 $i + 1$，若 $t_i > t_{i+1}$（即不满足升序），交换后总等待时间变化：

- 第 $i$ 位：原贡献 $t_i \cdot (n - i + 1)$，新贡献 $t_{i+1} \cdot (n - i + 1)$

- 第 $i+1$ 位：原贡献 $t_{i+1} \cdot (n - i)$，新贡献 $t_i \cdot (n - i)$

差值：

$$\Delta = (t_{i+1} - t_i) \cdot (n - i + 1) + (t_i - t_{i+1}) \cdot (n - i) = -(t_i - t_{i+1}) < 0$$

所以交换后总等待时间**严格变小**——任何不按升序的解都可通过相邻交换变得更小，升序即为最优解。$\blacksquare$

**邻项交换法的普适性**：

几乎所有"按某规则排序"的贪心都能用邻项交换证明。原因——若全局最优解不按贪心顺序，必存在一对**相邻**逆序对（数学上的"逆序"概念），交换它们要么解不变要么变得更优。反复交换最终得到贪心解。

**贪心 vs DP 的边界**：

| 维度         | 排序贪心                 | DP                         |
| ---------- | -------------------- | -------------------------- |
| 决策依赖       | 当前选择不影响未来可行性         | 状态会传递到后续                   |
| 是否需要尝试多种   | 不需要，每步只取最优           | 需要枚举多种转移                   |
| 复杂度        | $O(n \log n)$        | $O(n^2)$ 或更高               |
| 正确性证明      | 交换论证 / 归纳            | 状态转移方程的最优子结构               |

**最容易踩的坑**：以为某规则正确而不证明。竞赛中"看起来对的贪心"经常错——比如 0-1 背包按性价比排不行、最长不下降子序列贪心不行。先证后写。
