#难度/★★★

> 在贪心选择后允许"撤销已选项"换上更优的——用堆维护"反悔代价"，把贪心从"一次决策"升级为"可调整决策"。

## 前置知识

- [[堆贪心]]

## 核心思想

朴素 [[堆贪心]] 一旦做出选择就**不能反悔**——但很多题目中，未来出现的元素可能比已选的某个元素更优，这时强行不换会得到次优解。

**反悔贪心**的核心：每次贪心选择**先尽可能多取**（甚至全取），但当遇到约束（容量上限、时间冲突等）时，**用堆找出"已选项中最差的那个"，与新候选比较**——若新候选比它好，就把它"踢出去"，换上新候选。这相当于把决策从"接受 / 拒绝二选一"扩展为"接受 / 替换 / 拒绝三选一"。

实现上常用一个**最小堆**保存已选项的"得分"（或"代价"）。新元素 $x$ 进来时：

- 若堆未满：直接选中 $x$，push 进堆

- 若堆已满，且 $x$ 比堆顶（已选最差）更优：pop 出堆顶，push $x$

- 否则：放弃 $x$

## 适用场景

- 朴素堆贪心会错，但通过"撤销重选"能改对的问题

- 经典模型：

  - **建筑抢修**：每个建筑有截止时间和耗时，求最多能修几个（[[堆贪心]] 模板三的进阶版）

  - **种树 / 修任务**：选 $k$ 个不相邻或满足限制的元素求最大权

  - **奶牛跳栏**：限制资源下选最大权值集合

- 某些"$k$ 选 $\le k$"的问题——朴素 dp 复杂度高，反悔贪心 $O(n \log n)$ 解决

- 不适用：候选间的约束太复杂（无法用堆顶"已选最差"代表整体）；最优解不具备"局部替换"性质

## 步骤拆解

1. **识别"约束 + 局部替换"性质**：判断"违反约束时把已选最差换出去"是否合理

2. **设计堆**：通常存"已选项的得分"或"已选项的代价"

3. **遍历元素**：

   a. 把当前元素纳入"已选"

   b. 检查约束是否违反；若违反，pop 堆顶并放弃它

4. **统计**：堆中剩下的就是最终选中的方案

## 代码模板

**模板一：建筑抢修（按截止时间排序 + 最大堆维护反悔代价）**

> $n$ 项任务，第 $i$ 项需 $t_i$ 时间，截止时间为 $d_i$。每次只能做一项。求最多能完成多少项。

```cpp
struct task {

    int t, d;

};

int max_tasks_done(vector<task>& a) {

    int n = a.size() - 1;

    sort(a.begin() + 1, a.end(), [](const task& x, const task& y) {

        return x.d < y.d;                    // 按截止时间升序

    });

    priority_queue<int> pq;                  // 大根堆，存已选任务的耗时

    long long current_time = 0;

    for (int i = 1; i <= n; i++) {

        if (current_time + a[i].t <= a[i].d) {

            // 来得及做，直接选

            pq.push(a[i].t);

            current_time += a[i].t;

        } else if (!pq.empty() && pq.top() > a[i].t) {

            // 来不及，但当前任务比已选最耗时的更短——反悔，把那个换掉

            current_time -= pq.top();

            pq.pop();

            current_time += a[i].t;

            pq.push(a[i].t);

        }

        // 否则放弃当前任务

    }

    return pq.size();

}
```

> 💡 **反悔的代价交换**：反悔时不仅 pop 出旧任务，还要把 `current_time` 减去旧任务耗时——本质是模拟"撤销操作"。

**模板二：种树问题——k 个互不相邻位置使权和最大**

> 给定一排 $n$ 个位置每个有权值 $w_i$，选 $k$ 个**互不相邻**的位置使权和最大。

这题有经典反悔贪心解法：

```cpp

struct node {

    long long val;                           // 当前权值

    int prev, next;                          // 双链表

    bool removed;

};

long long max_sum_k_non_adjacent(vector<long long>& w, int k) {

    int n = w.size() - 1;

    vector<node> a(n + 2);

    // 大根堆，存 (权值, 位置)

    priority_queue<pair<long long, int>> pq;

    for (int i = 1; i <= n; i++) {

        a[i].val = w[i];

        a[i].prev = i - 1;

        a[i].next = i + 1;

        a[i].removed = false;

        pq.push({w[i], i});

    }

    a[0].val = a[n + 1].val = LLONG_MIN;     // 哨兵

    a[0].next = 1;

    a[n + 1].prev = n;

  

    long long total = 0;

    for (int t = 0; t < k; t++) {

        while (a[pq.top().second].removed

            || a[pq.top().second].val != pq.top().first) {

            pq.pop();                        // 跳过过期项

        }

        auto [v, i] = pq.top();

        pq.pop();

        total += v;

        // 把位置 i 替换为反悔标记 a[prev]+a[next]-a[i]

        // 原理：选 i 等价于"放弃左右邻居改选 i"——反悔时反过来

        int L = a[i].prev;

        int R = a[i].next;

        a[i].val = a[L].val + a[R].val - a[i].val;

        a[L].removed = true;

        a[R].removed = true;

        a[i].prev = a[L].prev;

        a[i].next = a[R].next;

        a[a[L].prev].next = i;

        a[a[R].next].prev = i;

        pq.push({a[i].val, i});

    }

    return total;

}
```

> 💡 **"反悔权值"的精妙**：选了 $i$ 后，把 $i$ 的权值改为 $w_{i-1} + w_{i+1} - w_i$。如果以后又选到这个新权值，意味着——"放弃 $w_i$，转而选 $w_{i-1}$ 和 $w_{i+1}$"——刚好等价于交换决策。这种"代数化的反悔"是反悔贪心最深刻的形态。

> ⚠️ **过期项处理**：链表删除后堆里的旧记录失效，取堆顶时要跳过 `removed` 或值已变的项。

## 复杂度分析

- 时间复杂度：$O(n \log n)$，每次操作 $O(\log n)$

- 空间复杂度：$O(n)$（堆 + 辅助结构）

## 正确性证明

以**建筑抢修**为例，证明反悔贪心的正确性。

**核心不变量**：算法处理完前 $i$ 项任务后，已选集合 $S_i$ 满足两条性质：

1. $|S_i|$ 等于"前 $i$ 项任务中可选完成的最大数量"

2. 在所有大小为 $|S_i|$ 的合法集合中，$S_i$ 的**总耗时最小**

**归纳证明**：

**基础情形** $i = 0$：$S_0 = \emptyset$，两条性质平凡成立。

**归纳步骤**：假设 $S_{i-1}$ 满足上述性质，考虑加入第 $i$ 个任务 $a_i = (t_i, d_i)$。注意所有任务按 $d$ 升序，所以 $d_i$ 是 $S_{i-1}$ 之外**最早的截止时间约束**。

**情况一**：当前总耗时 $+ t_i \le d_i$（来得及）。

直接加入，$S_i = S_{i-1} \cup \{a_i\}$，$|S_i| = |S_{i-1}| + 1$——大小增 1。需要证明这是新的最大值。设 $S_i^*$ 是处理前 $i$ 项的某最优解：

- 若 $|S_i^*| \le |S_{i-1}|$：$|S_i^*| \le |S_{i-1}| + 1 = |S_i|$，无矛盾

- 若 $|S_i^*| > |S_{i-1}|$：$S_i^*$ 中比 $S_{i-1}$ 多至少一项，由 $S_{i-1}$ 已是前 $i-1$ 项最大值，多的那项必含 $a_i$。即 $|S_i^*| \le |S_{i-1}| + 1 = |S_i|$。

**情况二**：来不及，且 `pq.top() > t_i`（当前任务比已选最耗时的更短）。

替换：移除已选最耗时项 $a_j$，加入 $a_i$。$|S_i| = |S_{i-1}|$，**大小不变**，但**总耗时严格减少**。

这是关键——大小不变不意味着次优；总耗时减少使得后续任务**更容易满足约束**。形式化：若存在前 $i$ 项的合法解 $T$ 满足 $|T| > |S_{i-1}|$，则 $T$ 必含 $a_i$，且 $T \setminus \{a_i\}$ 是前 $i-1$ 项的合法解。但由 $S_{i-1}$ 已是前 $i-1$ 项最大，$|T \setminus \{a_i\}| = |T| - 1 \le |S_{i-1}|$，所以 $|T| \le |S_{i-1}| + 1$。又 $T$ 含 $a_i$ 且来不及（情况二前提），意味 $T$ 必去掉 $S_{i-1}$ 中某项 $a_j$ 来腾时间，且新总耗时 = 原 - $t_j$ + $t_i \le d_i$。我们替换后的 $S_i$ 总耗时 = $S_{i-1}$ 总耗时 - $\max_j t_j$ + $t_i$，比 $T$ 的总耗时 $\le$（因为我们换的是耗时最大的）。所以 $S_i$ 也是合法的，$|S_i| = |S_{i-1}|$，与情况二处理一致。

**情况三**：来不及且 `pq.top() <= t_i`。

放弃 $a_i$，$S_i = S_{i-1}$。容易证明此时无解能比 $S_{i-1}$ 更大。

由上三种情况，归纳成立。$\blacksquare$

**反悔贪心的核心原理**：

反悔贪心的核心假设是——**若把已选最差换成新候选不会破坏可行性**，则可以放心替换。这个假设的成立要求问题具有某种"交换性"——这也是反悔贪心区别于普通贪心的根本。

**朴素堆贪心的缺陷**：

普通堆贪心每次只考虑"加入新元素"和"放弃新元素"，一旦放弃就永远失去这个元素。但若**已选项中有比新元素更差的**，"换掉它"就比"放弃新元素"更优。反悔贪心补全了这第三种选择。

**与 dp 的对比**：

很多反悔贪心题用 dp 也能做，但 dp 复杂度往往是 $O(nk)$ 或更高。反悔贪心通过堆把每步决策时间砍到 $O(\log n)$，整体 $O(n \log n)$。

例如"选 $k$ 个互不相邻位置最大权和"——

- dp：$f[i][j]$ 表示前 $i$ 个选 $j$ 个的最大和，$O(nk)$

- 反悔贪心：$O(n \log n)$，独立于 $k$

**反悔的代数化技巧**：

对于"互不相邻"这类约束，可以用 $w_{\text{new}} = w_{\text{prev}} + w_{\text{next}} - w_i$ 把"反悔操作"编码进权值——堆只需正常维护权值，"反悔"自然发生在比较过程中。这是反悔贪心最巧妙的地方。
