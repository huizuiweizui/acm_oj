#难度/★★

> 用堆动态维护"当前最优元素"，处理"最优选择会随时间变化"的贪心问题。

## 前置知识

- [[排序贪心]]

- [[堆]]

## 核心思想

[[排序贪心]] 的前提是"所有候选项一开始就给出，按某顺序处理一次即可"。但很多问题中**候选项是动态产生的**——比如：

- 处理每条任务时会**新生成**一些次级任务

- 选择某个元素后**剩余可选项**发生变化

- 候选集合会随**时间推进**逐渐扩展

这时朴素的"先排序后扫"做不到——每次选最优时，最优是谁会变。

**堆贪心**的解法：用一个 [[堆]] 维护"当前所有候选项"，每次贪心选**堆顶**（当前最优），处理完后把新生成的候选项 push 进堆。这样每次都能 $O(\log n)$ 地拿到当前最优，整个过程 $O(n \log n)$。

经典代表：

- **哈夫曼编码**：每次取两棵权值最小的子树合并

- **合并果子**：每次合并最小的两堆果子

- **修理牛棚** / **任务调度**：动态决定最优处理顺序

## 适用场景

- 候选集动态变化（每次操作可能加入新元素）

- 每步只关心"当前最大 / 最小"，不需要排序所有元素

- 经典模型：

  - **哈夫曼编码 / 合并果子**：用最小堆每次取两个最小值合并

  - **会议室分配**：用最小堆维护各会议室的最早释放时间

  - **任务调度**：每个任务有截止时间，按价值大小贪心

- 常配合 [[反悔贪心]]，让贪心结果可"撤回"

- 不适用：候选项可一开始全枚举（直接 [[排序贪心]] 即可）；最优选择不只看一个值（用 dp）

## 步骤拆解

1. **识别动态性**：观察"每步选择是否会改变候选集"

2. **建堆**：根据是求最大还是最小，建大根堆或小根堆

3. **初始化**：把初始候选项全部 push 进堆

4. **主循环**：每次 pop 堆顶处理，按题目逻辑可能要 push 新元素回去

5. **统计答案**：通常在循环中累加结果

## 代码模板

**模板一：合并果子（最小堆）**

> $n$ 堆果子，每次合并两堆消耗"两堆果子数之和"的体力，求最小总体力。

```cpp
long long merge_fruits(vector<int>& a) {

    int n = a.size() - 1;

    priority_queue<long long, vector<long long>, greater<long long>> pq;

    for (int i = 1; i <= n; i++) {

        pq.push(a[i]);

    }

    long long total = 0;

    while (pq.size() >= 2) {

        long long x = pq.top();

        pq.pop();

        long long y = pq.top();

        pq.pop();

        long long s = x + y;

        total += s;

        pq.push(s);                          // 新生成的"合并堆"放回堆中

    }

    return total;

}
```

**模板二：任务调度——优先选高价值**

> $n$ 个任务，第 $i$ 个有价值 $v_i$ 和截止时间 $d_i$（每天只能做一个）。求最大总价值。

```cpp

struct task {

    int v, d;

};

long long max_total_value(vector<task>& t) {

    int n = t.size() - 1;

    sort(t.begin() + 1, t.end(), [](const task& x, const task& y) {

        return x.d < y.d;                    // 按截止时间升序

    });

    priority_queue<int, vector<int>, greater<int>> pq;   // 已选任务的价值（最小堆）

    for (int i = 1; i <= n; i++) {

        pq.push(t[i].v);

        // 已选数量超过截止时间——必须丢掉一个，丢价值最小的

        if ((int)pq.size() > t[i].d) {

            pq.pop();

        }

    }

    long long total = 0;

    while (!pq.empty()) {

        total += pq.top();

        pq.pop();

    }

    return total;

}
```

> 💡 **这是 [[反悔贪心]] 的雏形**——一开始把任务全选进堆，后来发现违反约束时再"反悔"（pop 出价值最小的）。这种"先做后悔"的思想在 [[反悔贪心]] 里会更系统化。

## 复杂度分析

- 时间复杂度：$O(n \log n)$，每个元素入堆 / 出堆各 $O(\log n)$

- 空间复杂度：$O(n)$（堆）

## 正确性证明

以**合并果子**为例，证明"每次取两个最小的合并"得到的总体力最小。

**关键观察**：把合并过程画成一棵二叉树——叶子是初始果堆，每个内部节点是其两个孩子合并产生的新堆。设初始第 $i$ 堆的权值为 $w_i$，它在树中的深度为 $d_i$，则总体力为：


$$\text{total} = \sum_{i=1}^{n} w_i \cdot d_i$$

（理由：每次合并贡献 = 该内部节点子树叶子之和。把贡献分摊到每个叶子，每个叶子被合并的次数恰好等于它的深度。）

**目标**：最小化 $\sum w_i d_i$。

**断言 1**：最优树中，**权值最小的两个叶子**必然在最深一层且互为兄弟。

**证明**：设最优解中权值最小的叶子为 $a$，第二小的为 $b$。

- 若 $a$ 不在最深层，存在最深层的某叶子 $c$，$d_c > d_a$ 且 $w_c \ge w_a$。交换 $a$ 和 $c$ 的位置，总代价变化为 $(w_c - w_a)(d_a - d_c) \le 0$——所以可以让 $a$ 在最深层。

- 同理可让 $b$ 在最深层。

- 最深层任两个叶子互换不影响总代价（深度相同），所以可以让 $a, b$ 互为兄弟。

**断言 2**："先合并 $a, b$"是最优策略。

**证明**：对剩余的 $n - 1$ 个堆（其中包含合并后的 $a + b$）递归求解最优合并方案。把 $a, b$ 视为合并后那个新叶子（权值 $w_a + w_b$）的两个孩子，得到的整棵树就是原 $n$ 个堆的最优合并方案。

由数学归纳法，"每次合并最小的两个"始终得到最优解。$\blacksquare$

**这正是哈夫曼编码的核心定理**——堆贪心是哈夫曼算法的实现。

**为什么用堆而不是其他结构**：

堆精准支持"取最优 + 插入新元素"两个核心操作，且都是 $O(\log n)$。set / multiset 也行（功能更强但常数大），最简单的就是 STL `priority_queue`。

**朴素堆贪心的局限**：

经典堆贪心一旦选定就不能反悔。但有些题目中，**未来可能出现更好的选择**——这时朴素堆贪心会错。需要进化成 [[反悔贪心]]，把已选元素也 push 进一个"反悔堆"。
