#难度/★★

  > 用一个大根堆和一个小根堆"对顶"地夹住数据，动态维护中位数（或第 $k$ 大）。

## 前置知识

- [[堆]]

## 定义与特性

- **本质**：两个 [[堆]] 的组合——大根堆 `lo` 存"较小的一半"，小根堆 `hi` 存"较大的一半"

- **核心性质**：`lo.top()` ≤ `hi.top()`，即大根堆的堆顶（小一半的最大值）始终不超过小根堆的堆顶（大一半的最小值）

- **不变量**：两堆大小差不超过 1。具体维持哪种比例由所求目标决定（求中位数时通常让 `hi.size() == lo.size()` 或 `hi.size() == lo.size() + 1`）

## 操作与复杂度

| 操作    | 时间复杂度       | 说明                |
| ----- | ----------- | ----------------- |
| 插入元素  | $O(\log n)$ | 选择合适的堆插入，再调整大小    |
| 查询中位数 | $O(1)$      | 取较大那个堆的堆顶（或两堆顶平均） |
| 删除指定值 | $O(\log n)$ | 需配合"懒删除"技巧        |

## 实现方式  

```cpp
class median_finder {

private:

    priority_queue<int> lo;                                   // 大根堆，存较小一半

    priority_queue<int, vector<int>, greater<int>> hi;        // 小根堆，存较大一半

    void rebalance() {

        // 维持 hi.size() == lo.size() 或 hi.size() == lo.size() + 1
        while (hi.size() > lo.size() + 1) {

            lo.push(hi.top());

            hi.pop();

        }

        while (lo.size() > hi.size()) {

            hi.push(lo.top());

            lo.pop();

        }

    }

public:

    void add(int x) {

        if (hi.empty() || x >= hi.top()) {

            hi.push(x);

        } else {

            lo.push(x);

        }

        rebalance();

    }

    int median() {

        // 当前共有奇数个元素时，中位数在 hi 的堆顶
        return hi.top();

    }

    int size() { return lo.size() + hi.size(); }

};
```

> 💡 **关键技巧**：插入后**总是 rebalance**，让两堆大小差不超过 1。这样小堆顶就是"第 $\lceil n/2 \rceil$ 小"，正是奇数情况的中位数。

## 内部原理

把整个数据集合"拦腰切一刀"，前一半丢进大根堆（顶为前半段最大值），后一半丢进小根堆（顶为后半段最小值）。

**为什么这样设计能 $O(1)$ 查中位数**：中位数本质就是"切分点"附近的值。让两堆大小相差不超过 1，则切分点恰好就是数量较多的那个堆的堆顶。

**为什么插入是 $O(\log n)$**：每次插入只动一两次 [[堆]] 操作（push 一次，可能 rebalance 时再 pop+push 一次）。

**插入策略**：

- 若 `x >= hi.top()`，明显属于"较大一半"，丢进 `hi`

- 否则丢进 `lo`

- 完事后调用 `rebalance()` 修正大小差

## 适用场景

- 动态求中位数（数据流持续到来）

- 第 $k$ 大问题的在线版本：固定 `lo` 堆大小为 $k$，则 `lo.top()` 始终是当前第 $k$ 大

- 滑动窗口中位数（配合"懒删除"技巧处理过期元素）

- 不适用：要求中位数变化前后都能查询历史版本（应使用可持久化数据结构）
