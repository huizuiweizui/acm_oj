#难度/★★★

  > 给线段树节点打上"懒标记"，把区间修改延迟到必要时再下传，让区间修改也降到 $O(\log n)$。

## 前置知识

- [[线段树]]

## 定义与特性

- **本质**：在 [[线段树]] 上为每个节点额外维护一个 `lazy` 数组，记录"该节点的子树还需要被传递的修改"

- **核心思想**：**懒**——当一次区间修改完全覆盖某节点时，只更新该节点的聚合值并打标记，不立即下递到子节点

- **关键操作**：

  - `push_down`（下传）：访问子节点前，先把当前节点的 lazy 推给两个孩子

  - `apply`（施加）：用某个修改值更新当前节点的聚合值和 lazy

- **不变量**：节点的聚合值始终反映"已经施加在该节点上的所有修改"，但子节点可能还没收到更新（懒在那里）

## 操作与复杂度

| 操作   | 时间复杂度       | 说明               |
| ---- | ----------- | ---------------- |
| 建树   | $O(n)$      | 同 [[线段树]]        |
| 区间修改 | $O(\log n)$ | 关键：完全覆盖时直接打标记    |
| 区间查询 | $O(\log n)$ | 下递前先 `push_down` |

## 实现方式

**支持区间加 + 区间求和**：

```cpp
class lazy_segment_tree {

private:

    int n;

    vector<long long> tree, lazy;

    void build(const vector<long long>& arr, int p, int l, int r) {

        if (l == r) { 
        
	        tree[p] = arr[l]; 
	        
	        return; 
	        
		}

        int mid = l + (r - l) / 2;

        build(arr, p * 2, l, mid);

        build(arr, p * 2 + 1, mid + 1, r);

        tree[p] = tree[p * 2] + tree[p * 2 + 1];

    }

    // 下传 lazy
    void push_down(int p, int l, int r) {

        if (lazy[p] == 0) {
        
	        return;
	        
		}

        int mid = l + (r - l) / 2;

        tree[p * 2]     += lazy[p] * (mid - l + 1);

        lazy[p * 2]     += lazy[p];

        tree[p * 2 + 1] += lazy[p] * (r - mid);

        lazy[p * 2 + 1] += lazy[p];

        lazy[p] = 0;

    }
    
    void update(int p, int l, int r, int ql, int qr, long long val) {

        if (ql <= l && r <= qr) {

            tree[p] += val * (r - l + 1);

            lazy[p] += val;

            return;

        }

        push_down(p, l, r);

        int mid = l + (r - l) / 2;

        if (ql <= mid) {
	        
	        update(p * 2, l, mid, ql, qr, val); 
	        
		}
	        
        if (mid <  qr) {
        
	        update(p * 2 + 1, mid+1, r, ql, qr, val);
	        
		}

        tree[p] = tree[p * 2] + tree[p * 2 + 1];

    }

    long long query(int p, int l, int r, int ql, int qr) {

        if (ql <= l && r <= qr) {
        
	        return tree[p];
	        
		}

        push_down(p, l, r);

        long long sum = 0;

        int mid = l + (r - l) / 2;

        if (ql <= mid) {
        
	        sum += query(p * 2, l, mid, ql, qr);
	        
		}

        if (mid <  qr) {
        
	        sum += query(p * 2 + 1, mid+1, r,   ql, qr);
	        
		}

        return sum;

    }

public:

    lazy_segment_tree(const vector<long long>& arr) {

        n = arr.size() - 1;

        tree.resize(4 * n);

        lazy.assign(4 * n, 0);

        build(arr, 1, 1, n);

    }

    void update(int ql, int qr, long long val) { update(1, 1, n, ql, qr, val); }

    long long query(int ql, int qr) { return query(1, 1, n, ql, qr); }

};
```

> ⚠️ **任何下递前必须 `push_down`**：包括 `update` 和 `query`，否则查询会读到过期值。

> 💡 **打标记时同步更新 `tree[p]`**：`tree[p] += val * (r - l + 1)` 反映了"该区间长度个 val 的总和"。

## 多种修改类型并存（区间乘 + 区间加）

如果需要同时支持区间乘法和区间加法。维护两个 lazy：`mul_lazy`（乘法标记）和 `add_lazy`（加法标记）。

**核心约定**：执行顺序总是"**先乘后加**"。即每个节点的真实修改是 `x → x * mul + add`。

新加修改时如何合并到已有 lazy？设原标记为 $(m_0, a_0)$，新加一个 $(m_1, a_1)$：

$$x \to (x \cdot m_0 + a_0) \cdot m_1 + a_1 = x \cdot (m_0 m_1) + (a_0 m_1 + a_1)$$

所以合并规则：

- `mul_lazy` 变为 $m_0 \cdot m_1$

- `add_lazy` 变为 $a_0 \cdot m_1 + a_1$

```cpp

// 给某子节点施加 (mul, add) 修改

void apply(int son, int len, long long mul, long long add) {

    tree[son]     = (tree[son] * mul + add * len) % MOD;

    mul_lazy[son] = mul_lazy[son] * mul % MOD;

    add_lazy[son] = (add_lazy[son] * mul + add) % MOD;

}

```

下传时调用 `apply(son, len, mul_lazy[p], add_lazy[p])`，再把 `p` 自己的标记重置为 $(1, 0)$。

> 💡 **核心套路**：当有多种修改时，先想清楚"复合的代数法则"，再用数学公式推出 lazy 的合并规则。这是懒标记线段树最难也最优雅的部分。

## 内部原理

**为什么"懒"是必要的**：如果不延迟，每次区间修改要下传到所有叶子，最坏 $O(n)$。打标记只在必要时下传，能保证每次修改最多访问 $O(\log n)$ 个节点。

**为什么 `push_down` 安全**：因为标记本质是"还没被分发的修改"，下传时把它一次性应用到两个孩子节点（包括聚合值和 lazy），原节点的 lazy 即可清空。下传后两个孩子可以独立进入下一轮递归。

**`tree[p]` 与 `lazy[p]` 的关系**：`tree[p]` 永远是"该区间当前的正确聚合值"——这是关键！只有 `lazy[p]` 是"欠子节点的债"。所以查询时不必下递，直接返回 `tree[p]` 即可。

## 适用场景

- 区间加 + 区间求和（最经典）

- 区间赋值 + 区间求和/最值

- 区间乘加 + 区间求和（P3373）

- 区间染色 + 区间最值

- 几乎任何需要"区间修改 + 区间查询"的题目

- 不适用：信息无法快速合并或施加 lazy 的情形（如区间众数）
