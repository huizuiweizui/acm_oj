#难度/★★★★

> 线段树节点按需创建——只在被访问时才分配，使值域 $10^9$ 但操作只 $10^5$ 次的"超大稀疏"场景成为可能。

- [[线段树]]

- [[懒标记线段树]]

## 定义与特性

- **本质**：线段树的一种实现变种——**节点不预分配**，每个节点用结构体存"左孩子下标、右孩子下标、值、懒标记"，孩子按需在访问时创建

- **核心动机**：标准线段树预分配 $4n$ 个节点，当 $n = 10^9$ 时根本开不下数组。但若操作只有 $m = 10^5$ 次，实际访问到的节点远小于 $4n$——只创建这些节点，空间降到 $O(m \log V)$

- **关键性质**：每次操作（修改 / 查询）最多创建 $O(\log V)$ 个新节点（$V$ 是值域大小）

- **不变量**：每个已创建的节点对应的区间信息正确；未创建的节点视为"信息全为初值"（如和为 0、最值为 $-\infty$）

## 操作与复杂度

| 操作    | 时间复杂度         | 空间复杂度          | 说明               |
| ----- | ------------- | -------------- | ---------------- |
| 单点修改  | $O(\log V)$   | 至多 $O(\log V)$ | 沿路径每层至多创建 1 节点   |
| 区间修改  | $O(\log V)$   | 至多 $O(\log V)$ | 配合懒标记            |
| 区间查询  | $O(\log V)$   | $O(\log V)$    | 同标准线段树           |
| 总空间   | $O(m \log V)$ | -              | $m$ 次操作          |

## 实现方式

**模板：动态开点线段树（区间加 + 区间求和）**

```cpp
class dynamic_segment_tree {

private:

    struct node {

        long long sum;

        long long lazy;

        int lson, rson;                         // 0 表示孩子尚未创建

    };

    vector<node> tr;

    int root;

    long long n;                                // 值域：[1, n]

    int new_node() {

        tr.push_back({0, 0, 0, 0});

        return (int)tr.size() - 1;

    }

    void push_down(int p, long long len) {

        if (tr[p].lazy == 0) {

            return;

        }

        // 下传时若孩子不存在，按需创建
        if (tr[p].lson == 0) {

            tr[p].lson = new_node();

        }

        if (tr[p].rson == 0) {

            tr[p].rson = new_node();

        }

        long long left_len = (len + 1) / 2;

        long long right_len = len / 2;

        tr[tr[p].lson].sum  += tr[p].lazy * left_len;

        tr[tr[p].lson].lazy += tr[p].lazy;

        tr[tr[p].rson].sum  += tr[p].lazy * right_len;

        tr[tr[p].rson].lazy += tr[p].lazy;

        tr[p].lazy = 0;

    }

    void update(int& p, long long l, long long r, long long ql, long long qr, long long val) {

        if (p == 0) {

            p = new_node();                     // 按需创建

        }

        if (ql <= l && r <= qr) {

            tr[p].sum  += val * (r - l + 1);

            tr[p].lazy += val;

            return;

        }

        push_down(p, r - l + 1);

        long long mid = l + (r - l) / 2;

        if (ql <= mid) {

            update(tr[p].lson, l, mid, ql, qr, val);

        }

        if (mid <  qr) {

            update(tr[p].rson, mid + 1, r, ql, qr, val);

        }

        tr[p].sum = (tr[p].lson ? tr[tr[p].lson].sum : 0)

                  + (tr[p].rson ? tr[tr[p].rson].sum : 0);

    }

    long long query(int p, long long l, long long r, long long ql, long long qr) {

        if (p == 0) {

            return 0;                           // 未创建的节点信息为初值

        }

        if (ql <= l && r <= qr) {

            return tr[p].sum;

        }

        push_down(p, r - l + 1);

        long long mid = l + (r - l) / 2;

        long long sum = 0;

        if (ql <= mid) {

            sum += query(tr[p].lson, l, mid, ql, qr);

        }

        if (mid <  qr) {

            sum += query(tr[p].rson, mid + 1, r, ql, qr);

        }

        return sum;

    }

public:

    dynamic_segment_tree(long long n_in) {

        n = n_in;

        tr.reserve(1);

        new_node();                             // 0 号位作为"空节点"哨兵

        root = new_node();                      // 根节点

    }

    void update(long long ql, long long qr, long long val) {

        update(root, 1, n, ql, qr, val);

    }

    long long query(long long ql, long long qr) {

        return query(root, 1, n, ql, qr);

    }

};
```

> 💡 **`int& p` 作为参数**：注意 `update(int& p, ...)`——传递的是节点编号的**引用**。这样 `p == 0` 时 `p = new_node()` 直接修改了**父节点的 `lson` 或 `rson` 字段**，自动建立父子关系。这是动态开点最优雅的实现技巧。

> ⚠️ **`push_down` 时也要按需创建孩子**：若不创建直接对 `tr[0]` 操作会污染哨兵节点，导致查询错误。但若对节点结构稍作调整（比如 `tr[0]` 的字段全 0 且不可变），也可以省略这个创建——但通常按需创建更清晰。

> ⚠️ **节点池预分配**：实际竞赛中 `vector` 的 `push_back` 可能因 reallocation 导致 `int&` 引用失效。稳妥的做法是预先 `tr.reserve(MAX_NODES)` 或者改用固定数组（如 `node tr[MAX]`）。

## 内部原理

**为什么节点数是 $O(m \log V)$**：

每次操作（修改 / 查询）从根递归向下，路径长度 $O(\log V)$（线段树高 = $\log V$）。每一层至多创建 1 个新节点（沿路径上"原本未创建"的那个孩子）。所以单次操作至多新增 $O(\log V)$ 节点，$m$ 次操作总计 $O(m \log V)$。

**与离散化 + 标准线段树的对比**：

| 维度          | 离散化 + 线段树      | 动态开点                |
| ----------- | -------------- | ------------------- |
| 空间          | $O(n)$         | $O(m \log V)$       |
| 在线 / 离线     | 离线（要先收集所有值）    | 在线（边操作边创建）          |
| 实现复杂度       | 简单             | 中等                  |
| 常数          | 小              | 大（指针跳转）             |
| 支持动态加值      | ❌              | ✅                   |

**经验**：操作离线且能预先收集所有值 → 离散化更省内存常数；强制在线或值域真的大到无法离散化 → 动态开点。

**未访问节点的"虚拟性"**：

未创建的节点对应的区间信息全是初值（和 = 0、最值 = $-\infty$ 等）。查询到这种节点直接返回初值。这等价于"完整的线段树存在，但我们只显式存了被修改过的部分"。

## 适用场景

- **值域极大、操作稀疏**：值域 $10^9$ 但操作 $10^5$

- **强制在线**：题目不允许离线收集所有查询，必须边读边处理

- **可持久化线段树**：动态开点是其基础（每次操作只新建 $O(\log n)$ 节点，旧版本节点可复用）

- **权值线段树**的大值域版本

- **线段树合并**：把多棵动态开点线段树合并（树上启发式合并的进阶）

- 不适用：操作数与值域成线性关系（直接离散化更优）；需要极致的内存常数

| 维度            | 标准线段树     | 离散化 + 线段树         | 动态开点                | 可持久化线段树             |
| ------------- | --------- | ----------------- | ------------------- | ------------------- |
| 空间            | $O(n)$    | $O(n)$（n 离散化后小）   | $O(m \log V)$       | $O(m \log V)$       |

| 支持版本回溯        | ❌         | ❌                 | ❌                   | ✅                   |

## 几个变种的扩展

**变种一：权值线段树的动态开点版**

不维护"区间和"而维护"区间内值的个数"——查询第 $k$ 大、查询某值的排名等问题。值域很大时直接动态开点。

**变种二：线段树合并**

每个节点维护一棵动态开点线段树（如 dsu on tree 的 [[树形dp]] 题）。合并两棵树时递归合并对应节点：若一方为空直接返回另一方；否则递归合并左右子树。复杂度均摊 $O(n \log n)$。

**变种三：可持久化线段树（主席树）**

每次"修改"不直接修改原节点，而是新建一条从根到叶的链（共享未修改的部分）。每个版本对应一个根节点。能查询任意历史版本——这是 [[树状数组]] 做不到的。

## 几个实现陷阱

**陷阱一：节点池数组扩容导致引用失效**

```cpp

// 错误：tr.push_back 可能 reallocation 导致引用失效

int& p = tr[parent].lson;

p = new_node();             // 此时 tr 已 reallocate，p 指向无效位置

```

解决：先 `tr.reserve(MAX_NODES)` 预分配，或用固定数组。

**陷阱二：忘记按需创建孩子**

`push_down` 时若孩子不存在，必须先创建再下传 lazy——否则数据写到 `tr[0]`（哨兵），下次查询读出错误值。

**陷阱三：左右子区间长度的不对称**

区间 $[l, r]$ 长度 $r - l + 1$。若 $\mathtt{mid} = l + (r - l) / 2$，左孩子 $[l, \mathtt{mid}]$ 长度为 $\mathtt{mid} - l + 1$，右孩子 $[\mathtt{mid}+1, r]$ 长度 $r - \mathtt{mid}$。两者通常**不相等**（差 1）。`push_down` 时给左右孩子的 lazy 贡献要按各自长度正确计算。
