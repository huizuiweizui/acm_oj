#难度/★★★ 

  > 用 lowbit 巧妙划分子区间，以 $O(\log n)$ 同时支持单点修改和前缀和查询。

## 前置知识

- [[位运算]]

- [[前缀和]]

## 定义与特性

- **本质**：一棵基于 lowbit 划分的"逻辑树"，物理存储仍是一个数组 `tree[]`

- **核心性质**：`tree[i]` 维护的是区间 $[i - \text{lowbit}(i) + 1, i]$ 上的元素和（其中 $\text{lowbit}(x) = x \,\&\, (-x)$，即 $x$ 二进制最低位的 1 所代表的值）

- **关键运算**：`lowbit(i) = i & -i`，利用补码表示直接得到最低位 1

- **不变量**：每次 `update` 或 `query` 都通过 `i ± lowbit(i)` 跳跃，每步至少变化 1 位，所以最多 $O(\log n)$ 步

## 操作与复杂度

| 操作                 | 时间复杂度       | 说明                        |
| ------------------ | ----------- | ------------------------- |
| 单点加 `update(i, v)` | $O(\log n)$ | 沿着 `i += lowbit(i)` 向上更新  |
| 前缀和 `query(i)`     | $O(\log n)$ | 沿着 `i -= lowbit(i)` 向下累加  |
| 区间和 `[l, r]`       | $O(\log n)$ | `query(r) - query(l - 1)` |
| 建树                 | $O(n)$      | 每个位置加上 `lowbit` 父节点的贡献    |

## 实现方式

```cpp

class fenwick_tree {

private:

    int n;

    vector<long long> tree;

    int lowbit(int x) {
    
		return x & -x;
		
	}

public:

    // O(n) 建树：直接借助"父节点"关系传递贡献
    fenwick_tree(const vector<long long>& arr) {

        n = arr.size() - 1;

        tree.resize(n + 1, 0);

        for (int i = 1; i <= n; i++) {
        
	        tree[i] = arr[i];
	        
		}

        for (int i = 1; i <= n; i++) {

            int j = i + lowbit(i);

            if (j <= n) tree[j] += tree[i];

        }

    }

    // 单点加：在位置 i 加上 val
    void update(int i, long long val) {

        while (i <= n) {

            tree[i] += val;

            i += lowbit(i);

        }

    }

    // 前缀和：查询 [1, i] 的和
    long long query(int i) {

        long long sum = 0;

        while (i > 0) {

            sum += tree[i];

            i -= lowbit(i);

        }

        return sum;

    }

    // 区间和：[l, r]
    long long range_query(int l, int r) {

        return query(r) - query(l - 1);

    }

};
```

> ⚠️ **下标必须从 1 开始**，因为 `lowbit(0) = 0` 会导致死循环。

## 内部原理

**lowbit 的含义**：把一个数的二进制最低位 1 单独提出来。例如 `lowbit(6) = lowbit(110₂) = 010₂ = 2`。

**`tree[i]` 维护什么**：

$$\text{tree}[i] = \sum_{k = i - \text{lowbit}(i) + 1}^{i} a[k]$$

例如 `tree[6]` 维护 `a[5] + a[6]`（`lowbit(6) = 2`），`tree[8]` 维护 `a[1] + a[2] + ... + a[8]`（`lowbit(8) = 8`）。

**树状结构**：把 `i` 视作子节点，`i + lowbit(i)` 视作父节点，便形成了一棵树（实际上是个"森林"——每个 $2^k$ 是一棵小树的根）。例如：

```

         8

       / | \

      4  6  7

     /\  |

    2  3 5

   /

  1

```

**update 沿父链上行**：在位置 $i$ 处加 `val`，所有"包含位置 $i$"的 `tree[]` 节点都需要更新。这些节点恰好是 $i, i + \text{lowbit}(i), i + \text{lowbit}(i + \text{lowbit}(i)), \ldots$ 即沿父链向上。

**query 沿"区间剥离"下行**：要求 `[1, i]` 的和，先取出 `tree[i]`（覆盖了 $[i - \text{lowbit}(i) + 1, i]$），剩余部分是 $[1, i - \text{lowbit}(i)]$，递归处理即可。

**复杂度 $O(\log n)$ 的来源**：每跳一次 `i ± lowbit(i)`，二进制表示中要么减少一位 1（query 时），要么进位带来变化（update 时），无论如何最多 $\log_2 n$ 步。

## 适用场景

- **单点修改 + 区间查询**：是树状数组的"舒适区"，比 [[线段树]] 常数小、代码短

- 求逆序对（离散化后用 BIT 维护"已出现的数的频次"）

- 二维树状数组：单点修改 + 子矩阵查询

- 区间修改 + 单点查询：维护差分数组的 BIT

- 区间修改 + 区间查询：维护两个 BIT（参考 [[二阶差分]] 中提到的技巧）

- 不适用：维护更复杂的信息（如区间最值、区间最大子段和）—— 要用 [[线段树]]

## 与 [[线段树]] 的对比

| 维度   | 树状数组                | 线段树                   |
| ---- | ------------------- | --------------------- |
| 代码量  | 极短（20 行）            | 较长（50+ 行）             |
| 常数   | 很小                  | 较大                    |
| 灵活度  | 仅适合"可差分"信息（区间和、异或等） | 几乎任何区间信息（最值、最大子段和、染等） |
| 区间修改 | 需配合差分技巧             | 用 [[懒标记线段树]] 直接支持     |

**经验**：能用树状数组就用树状数组，写得快又不容易错。
