#难度/★★★★★

> 自平衡的二叉搜索树——FHQ Treap 用 split + merge 两个核心操作以 $O(\log n)$ 期望复杂度支持插入、删除、第 $k$ 小、排名、前驱后继。

## 前置知识

- [[堆]]

- [[二分查找]]

## 定义与特性

- **本质**：一种自平衡的**二叉搜索树**——既满足 BST 性质（左子树键值 < 当前 < 右子树），又通过某种机制维持期望树高 $O(\log n)$

- **OI 中的主流实现**——**FHQ Treap（无旋 Treap）**：每个节点除"键值"外还存一个**随机优先级**，保证树形上同时是"键值 BST + 优先级小根堆"。随机化让期望高度为 $O(\log n)$

- **核心操作**：所有平衡树操作都用两个原子操作组合而成——

  - **split（分裂）**：把一棵 Treap 按某种规则切成两棵

  - **merge（合并）**：把两棵 Treap 合并成一棵（要求第一棵的所有键值 < 第二棵的所有键值）

- **不变量**：

  - **BST 性质**：中序遍历得到键值升序序列

  - **堆性质**：节点的优先级 $\le$ 其孩子的优先级（小根堆）

## 操作与复杂度

| 操作                | 时间复杂度（期望）       | 说明                 |
| ----------------- | --------------- | ------------------ |
| 插入 / 删除一个值        | $O(\log n)$     | 用 split + merge 拼成 |
| 查询排名（< x 的个数 + 1） | $O(\log n)$     | split 一次后看左子树大小    |
| 查询第 $k$ 小         | $O(\log n)$     | 沿子树大小做"二分"         |
| 前驱 / 后继           | $O(\log n)$     | split 一次后取最右 / 最左  |
| split / merge     | $O(\log n)$     | 树高决定的递归深度          |

> **期望** 是因为优先级随机生成——最坏情况理论上可能更高，但出现概率极低。

## 实现方式

**核心思路**：每个节点存五个量——`val`（键值）、`priority`（随机优先级）、`lson` / `rson`（左右孩子）、`sz`（子树大小）。所有操作都通过 split 和 merge 调度。

**模板：FHQ Treap（值集合，支持完整六操作）**

```cpp
class fhq_treap {

private:

    struct node {

        int val;

        int priority;

        int lson, rson;

        int sz;

    };

    vector<node> tr;

    int root;

    mt19937 rng;

    int new_node(int val) {

        tr.push_back({val, (int)rng(), 0, 0, 1});

        return (int)tr.size() - 1;

    }

    void update(int p) {

        tr[p].sz = 1

            + (tr[p].lson ? tr[tr[p].lson].sz : 0)

            + (tr[p].rson ? tr[tr[p].rson].sz : 0);

    }

    // 按 val 分裂：左树所有 val ≤ k，右树所有 val > k
    void split(int p, int k, int& l, int& r) {

        if (p == 0) {

            l = r = 0;

            return;

        }

        if (tr[p].val <= k) {

            l = p;

            split(tr[p].rson, k, tr[p].rson, r);

        } else {

            r = p;

            split(tr[p].lson, k, l, tr[p].lson);

        }

        update(p);

    }

    int merge(int l, int r) {

        if (!l || !r) {

            return l + r;

        }

        if (tr[l].priority < tr[r].priority) {

            tr[l].rson = merge(tr[l].rson, r);

            update(l);

            return l;

        } else {

            tr[r].lson = merge(l, tr[r].lson);

            update(r);

            return r;

        }

    }

public:

    fhq_treap() : rng(chrono::steady_clock::now().time_since_epoch().count()) {

        tr.reserve(1);

        new_node(0);                            // 0 号位作哨兵

        root = 0;

    }

    void insert(int val) {

        int l, r;

        split(root, val, l, r);

        root = merge(merge(l, new_node(val)), r);

    }

    // 删除一个值为 val 的节点（若有多个只删一个）
    void erase(int val) {

        int l, m, r;

        split(root, val, l, r);

        split(l, val - 1, l, m);

        m = merge(tr[m].lson, tr[m].rson);      // 删 m 的根

        root = merge(merge(l, m), r);

    }

    int rank_of(int val) {

        int l, r;

        split(root, val - 1, l, r);

        int ans = (l ? tr[l].sz : 0) + 1;

        root = merge(l, r);

        return ans;

    }

    int kth(int k) {

        int p = root;

        while (p) {

            int left_sz = tr[p].lson ? tr[tr[p].lson].sz : 0;

            if (k <= left_sz) {

                p = tr[p].lson;

            } else if (k == left_sz + 1) {

                return tr[p].val;

            } else {

                k -= left_sz + 1;

                p = tr[p].rson;

            }

        }

        return -1;

    }

    // 严格小于 val 的最大值
    int prev_val(int val) {

        int l, r;

        split(root, val - 1, l, r);

        int p = l;

        while (p && tr[p].rson) {

            p = tr[p].rson;

        }

        int ans = (p ? tr[p].val : INT_MIN);

        root = merge(l, r);

        return ans;

    }

    // 严格大于 val 的最小值
    int next_val(int val) {

        int l, r;

        split(root, val, l, r);

        int p = r;

        while (p && tr[p].lson) {

            p = tr[p].lson;

        }

        int ans = (p ? tr[p].val : INT_MAX);

        root = merge(l, r);

        return ans;

    }

};
```

> 💡 **`int& l, int& r` 的妙用**：`split` 通过引用传递返回两棵子树的根——在父节点的递归调用中直接修改其孩子指针，自动建立父子关系。这是 [[动态开点]] 中"`int& p` 引用传参"思想的延续。

> 💡 **优先级用 `mt19937`**：`mt19937` 是 C++ 的高质量随机数生成器，比 `rand()` 周期长、分布均匀，对树平衡更有保证。比赛建议用 `chrono::steady_clock` 取种子，避免被构造数据卡。

> ⚠️ **`vector` 扩容陷阱**：`new_node` 中 `tr.push_back` 可能触发 reallocation——若同时持有 `tr[p]` 引用，引用会失效。预先 `tr.reserve(MAX_NODES)` 是稳妥做法。

## 内部原理

### 为什么是平衡的

**关键观察**：FHQ Treap 同时满足两个约束——

1. **键值**：左子树 < 根 < 右子树（BST）

2. **优先级**：根 < 左子树最小、根 < 右子树最小（小根堆）

给定一组 (键值, 优先级) 对，**满足这两个约束的二叉树形态是唯一的**——递归定义为：根是优先级最小的节点；按它的键值把其余节点分成左右两组，分别递归构造。

**等价于"按优先级升序插入键值序列形成的 BST"**。由于优先级是随机的——所以等价于"键值按随机顺序插入形成的 BST"——这就是经典的**随机 BST**，期望高度 $O(\log n)$。

### split 的正确性

**命题**：`split(p, k, l, r)` 将以 $p$ 为根的 Treap 分裂为两棵 Treap：左树 $l$ 包含所有 `val <= k` 的节点，右树 $r$ 包含所有 `val > k` 的节点；两棵新树仍同时满足 BST 和堆性质。

**证明（归纳）**：考察当前节点 $p$ 的键值。

**情形 1**：$\mathtt{tr}[p].\mathtt{val} \le k$。

$p$ 及其整个左子树的键值都 $\le \mathtt{tr}[p].\mathtt{val} \le k$，所以**全部归入左树**。$p$ 的右子树可能含 > $k$ 的，递归 split 右子树即可。

具体：`l = p; split(tr[p].rson, k, tr[p].rson, r)`——意味着以 $p$ 为根的左树由 $p$ 自己 + $p$ 的左子树 + $p$ 的右子树中 $\le k$ 的部分组成；右树就是右子树中 > $k$ 的部分。

**情形 2**：$\mathtt{tr}[p].\mathtt{val} > k$。对称地，$p$ 及其右子树整体归入右树，递归处理左子树。

**BST 性质保持**：操作只重新组装 $p$ 的某一侧子树，键值结构不变。

**堆性质保持**：操作不改变任何节点的优先级，也不让低优先级节点变成高优先级节点的祖先（结构上只"切走"子树）。$\blacksquare$

### merge 的正确性

**命题**：`merge(l, r)` 将两棵 Treap $l, r$ 合并为一棵 Treap，前提是 $l$ 的所有键值 < $r$ 的所有键值；新树仍同时满足 BST 和堆性质。

**证明**：考察根的优先级——

- 若 $\mathtt{tr}[l].\mathtt{priority} < \mathtt{tr}[r].\mathtt{priority}$：根应是 $l$ 的根（堆性质要求）。$l$ 的左子树原样保留；$l$ 的右子树和 $r$ 递归 merge——这两棵子树的键值都 > $l$ 的根（因为 $l$ 右子树本就 > $l$ 的根，$r$ 整体也 > $l$ 的根）。

- 否则对称：根是 $r$ 的根。

每步选优先级更小者作根——最终根的优先级是全局最小，符合堆性质。BST 性质由"$l$ 全部 < $r$ 全部"的前提自然保持。$\blacksquare$

### 期望复杂度的来源

**期望树高 $O(\log n)$**：由"等价于随机插入 BST"的论证——随机插入 $n$ 个元素的 BST 期望高度是 $O(\log n)$（这是随机 BST 的经典定理）。

**split / merge 都是单条路径**：从根递归到底，深度 = 当前部分的树高。所以 split / merge 单次 $O(\log n)$。

**所有外部操作都是 $O(1)$ 次 split + $O(1)$ 次 merge**——所以全部 $O(\log n)$ 期望。$\blacksquare$

### 为什么不学有旋 Treap / Splay

| 维度    | FHQ Treap  | 有旋 Treap | Splay   |
| ----- | ---------- | -------- | ------- |
| 代码量   | 短          | 中        | 长       |
| 易错点   | 少          | 较多（旋转边界） | 多（双旋方向） |
| 区间反转  | ✅（增加 lazy） | ❌        | ✅（经典操作） |
| 教学复杂度 | 低          | 中        | 高       |

FHQ Treap 在"代码量、易理解、功能"三方面都达到了很好的平衡，是 OI 中实际使用最多的平衡树。Splay 在某些"区间维护"问题（如序列翻转）有独特优势但代码更复杂，建议先掌握 FHQ Treap 再考虑。

### 用作"序列"维护

把平衡树看作"按 dfs 序排列的序列"——每个节点在序列中的位置由"它的左子树大小 + 在前面祖先序列中的位置"决定。这样可以在序列上：

- **区间反转**：把要反转的子树打 lazy 标记，访问时翻转

- **区间插入 / 删除**：split + merge

- **区间求和 / 最值**：每节点维护子树聚合值

这是 FHQ Treap 真正强大之处——可以替代 [[懒标记线段树]] 处理"序列动态变长"的问题。

## 适用场景

- **维护有序集合**，支持插入、删除、第 $k$ 小、排名、前驱后继

- **维护动态序列**：支持区间反转、区间插入 / 删除、区间求和等高级操作

- **STL 不够用的场景**：`std::set` 不支持"第 $k$ 小"和"小于 $x$ 的个数"

- **可持久化平衡树**：每次操作只新建 $O(\log n)$ 节点，支持版本回溯

- 不适用：仅需"插入、删除、查最值" → 用 [[堆]]；只需"有序去重集合" → 用 `std::set`；值域小 → 用值域 [[树状数组]] 或 [[线段树]]

## 与 STL 容器的对比

| 操作             | `std::set`          | `std::multiset`     | FHQ Treap           |
| -------------- | ------------------- | ------------------- | ------------------- |
| 插入 / 删除        | $O(\log n)$         | $O(\log n)$         | $O(\log n)$         |
| 查找             | $O(\log n)$         | $O(\log n)$         | $O(\log n)$         |
| 第 $k$ 小        | ❌（最坏 $O(n)$）        | ❌                   | $O(\log n)$         |
| 排名 / 严格小于个数    | ❌                   | ❌                   | $O(\log n)$         |
| 区间反转           | ❌                   | ❌                   | $O(\log n)$（带 lazy） |
| 代码量            | $1$ 行               | $1$ 行               | $80+$ 行             |

**经验**：若 STL 能用就用 STL（代码短不易错）；需要"第 $k$ 小""排名""区间维护"等 STL 不直接支持的功能时再上平衡树。

## 几个常见错误

- **`split` 中条件用 `<` 还是 `<=`**：本笔记按 `val <= k` 的左闭右开式分裂——对应"严格小于 $x$ 的最大值"用 `split(root, x - 1, ...)` 取左树最右节点。混用边界会导致 off-by-one 错误。

- **`merge` 中比较优先级的方向**：决定了"小根堆"还是"大根堆"。两种都可以，但要全局统一。

- **节点 0 的特殊性**：通常 0 号节点作为"空哨兵"——它的子树大小、键值都视为 0 / 不存在。访问 `tr[p].lson` 等字段前要先判 `p != 0`，否则读到哨兵的脏数据。

- **优先级用 `rand()`**：`rand()` 在某些平台只有 $2^{15}$ 范围，容易碰撞，让树退化。坚持用 `mt19937`。
