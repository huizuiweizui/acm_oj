#难度/★★

> 由"节点 + 边"构成的非线性数据结构，是图论一切算法的载体。

## 定义与特性

- **本质**：抽象上是一个二元组 $G = (V, E)$，$V$ 是节点集，$E$ 是边集；具体实现需要选择某种"存图方式"

- **核心分类**：

  - **有向 / 无向**：边是否区分方向

  - **带权 / 无权**：边是否有数值

  - **稠密 / 稀疏**：$m$ 接近 $n^2$ 还是远小于 $n^2$

  - **简单图 / 多重图**：是否允许重边和自环

- **三种存图方式**：邻接矩阵、邻接表、链式前向星

- **不变量**：

  - 无向图加边时**两个方向各加一次**

  - 自环和重边的处理由题目语义决定

## 操作与复杂度

设节点数 $n$，边数 $m$：

| 操作            | 邻接矩阵     | 邻接表（vector）   | 链式前向星         |
| ------------- | -------- | ------------- | ------------- |
| 空间            | $O(n^2)$ | $O(n + m)$    | $O(n + m)$    |
| 加边            | $O(1)$   | $O(1)$ 均摊     | $O(1)$        |
| 判断 $u-v$ 是否有边 | $O(1)$   | $O(\text{度})$ | $O(\text{度})$ |
| 遍历 $u$ 的邻居    | $O(n)$   | $O(\text{度})$ | $O(\text{度})$ |
| 缓存友好          | 中等（行连续）  | 中等            | 最好            |
| 易写程度          | 最简单      | 简单            | 较麻烦           |

## 实现方式

**实现一：邻接矩阵**

```cpp

class graph_matrix {

private:

    int n;

    vector<vector<long long>> g;

    static const long long INF = 1e18;

public:

    graph_matrix(int total) {

        n = total;

        g.assign(n + 1, vector<long long>(n + 1, INF));

        for (int i = 1; i <= n; i++) {

            g[i][i] = 0;

        }

    }

    // 加无向边
    void add_edge(int u, int v, long long w) {

        g[u][v] = min(g[u][v], w);          // 重边取最小

        g[v][u] = min(g[v][u], w);

    }

    // 有向边只加一条
    void add_directed_edge(int u, int v, long long w) {

        g[u][v] = min(g[u][v], w);

    }

    long long get_weight(int u, int v) {

        return g[u][v];

    }

};
```

> 💡 **空间 $O(n^2)$**：$n = 10^3$ 时已是 $10^6$，$n = 10^4$ 就 $10^8$ 爆内存了。所以邻接矩阵只适合小图（$n \le 10^3$）。

**实现二：邻接表

```cpp

class graph_list {

private:

    int n;

    vector<vector<pair<int, long long>>> g;     // g[u] = {{v, w}, ...}

public:

    graph_list(int total) {

        n = total;

        g.assign(n + 1, vector<pair<int, long long>>());

    }

    void add_edge(int u, int v, long long w) {

        g[u].push_back({v, w});

        g[v].push_back({u, w});                  // 无向图

    }

    void add_directed_edge(int u, int v, long long w) {

        g[u].push_back({v, w});

    }

    const vector<pair<int, long long>>& neighbors(int u) const {

        return g[u];

    }

};
```

> 💡 **vector 邻接表的好处**：写法直观、动态扩展、配合 C++17 结构化绑定 `auto [v, w] : g[u]` 写起来很舒服。

**实现三：链式前向星**

```cpp

class graph_star {

private:

    int n, edge_cnt;

    vector<int> head;                        // head[u] = 从 u 出发的第一条边的编号

    vector<int> nxt;                         // nxt[e] = 与边 e 同起点的下一条边

    vector<int> to;                          // to[e] = 边 e 的终点

    vector<long long> w;                     // w[e] = 边 e 的权值

public:

    graph_star(int total, int edge_capacity) {

        n = total;

        edge_cnt = 0;

        head.assign(n + 1, 0);               // 0 表示"没有下一条边"

        nxt.resize(edge_capacity * 2 + 1);   // 无向图边数 × 2

        to.resize(edge_capacity * 2 + 1);

        w.resize(edge_capacity * 2 + 1);

    }

    void add_directed_edge(int u, int v, long long weight) {

        edge_cnt += 1;

        to[edge_cnt] = v;

        w[edge_cnt] = weight;

        nxt[edge_cnt] = head[u];             // 把新边插到 u 的链表头

        head[u] = edge_cnt;

    }

    void add_edge(int u, int v, long long weight) {

        add_directed_edge(u, v, weight);

        add_directed_edge(v, u, weight);

    }

    // 遍历 u 的所有出边
    // 用法：for (int e = star.first(u); e != 0; e = star.next(e)) { ... }
    int first(int u) {

        return head[u];

    }

    int next(int e) {

        return nxt[e];

    }

    int target(int e) {

        return to[e];

    }

    long long weight(int e) {

        return w[e];

    }

};
```


> 💡 **链式前向星的精髓**：用三个数组模拟出"每个节点的出边链表"。所有边的 `to[]` 和 `w[]` 数组连续存储，缓存命中率比 vector 高，常数小。

## 内部原理

**三种存图方式的本质差异**：

- **邻接矩阵**：用一个 $n \times n$ 的二维数组直接表示"任意两点之间是否有边"。空间 $O(n^2)$ 是它的硬伤——但作为代价，"判断两点是否相邻"是 $O(1)$ 的，这是其他两种结构做不到的。

- **邻接表**：每个节点维护一个邻居列表，本质是"动态分配的稀疏二维矩阵"。空间正比于实际边数 $m$，对稀疏图远比矩阵省。但"判断两点是否相邻"需要 $O(\text{度})$ 的扫描。

- **链式前向星**：邻接表的"内存级优化"。本质上仍是邻接表，但所有边数据连续存于三个数组中（不像 vector<vector<>> 那样每行单独 new），CPU 缓存预取能跨边生效——遍历巨量边时常数显著优于 vector。

**为什么链式前向星比 vector 快**：

`vector<vector<>>` 的每行（一个节点的邻居列表）是单独 new 出来的，物理上不连续——CPU 缓存预取无法跨行生效。链式前向星的所有边数据都在三个连续数组里，遍历时缓存命中率极高。卡常题（如 $m = 10^7$）会有 $2 \sim 3$ 倍的差距。

**为什么用三个数组而不是一个 struct 数组**：

理论上 `struct edge { int to, next; long long w; }` 也行，但分开三个数组在某些访问模式下更友好——比如只关心 `to` 和 `next`、不需要 `w` 的算法（如纯 [[BFS]]），分离的数组让 CPU 不必加载用不到的 `w` 字段，缓存效率更高。

**重边与自环的处理**：

- **邻接矩阵**：重边时取最小（最大）权值；自环视题意保留或忽略（$g[i][i] = 0$ 表示无自环成本）

- **邻接表 / 链式前向星**：原样存储，让上层算法决定如何处理

**何时选择哪种存图**：

- $n \le 10^3$ 且需要 $O(1)$ 查边权：**邻接矩阵**

- 普通竞赛题，写代码省事：**vector 邻接表**（默认首选）

- 卡常题或 $m \ge 10^7$：**链式前向星**

## 适用场景

- 几乎所有图论算法的存储基础

- 不同算法对存图方式有不同偏好：

  - [[Floyd]]（$O(n^3)$）：必须邻接矩阵

  - [[Dijkstra]]、[[BFS]]、[[Kruskal]] 等：邻接表或前向星

  - 网络流等需要"反向边"的算法：链式前向星（成对加边技巧）

- 不适用：边集动态频繁增删（应使用 `set<pair<int,int>>` 或更复杂的结构）
