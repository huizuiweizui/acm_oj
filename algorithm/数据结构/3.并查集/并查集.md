#难度/★★

> 一种用树形结构维护"集合归属"的数据结构，支持快速合并与查询，是图论与离线问题的常用工具。

## 定义与特性

- **本质**：森林——每棵树代表一个集合，根节点是该集合的"代表元"

- **存储**：用 `parent[]` 数组表示每个节点的父节点，根节点的父节点指向自己

- **核心思想**：判断两元素是否属于同一集合，只需比较它们的根节点是否相同

- **优化方式**：**路径压缩**（让查询路径上的所有节点直接指向根）+ **按秩合并**（让矮树挂到高树下面），两者结合后单次操作均摊 $O(\alpha(n))$，几乎是常数

## 操作与复杂度

| 操作                 | 时间复杂度          | 说明                       |
| ------------------ | -------------- | ------------------------ |
| `find(x)` 查找根      | $O(\alpha(n))$ | 应用路径压缩，几乎 $O(1)$         |
| `unite(x, y)` 合并   | $O(\alpha(n))$ | 应用按秩合并                   |
| `same(x, y)` 是否同集合 | $O(\alpha(n))$ | 即比较 `find(x) == find(y)` |
| 初始化                | $O(n)$         | 每个元素自成一集合                |

> $\alpha(n)$ 是阿克曼函数的反函数，对于一切实际可能的 $n$（哪怕是宇宙原子总数），$\alpha(n) \le 4$。


## 实现方式

```cpp

class union_find {

private:

    vector<int> parent;

    vector<int> rank;

  
public:

    union_find(int n) {

        parent.resize(n + 1);

        rank.resize(n + 1, 1);

        for (int i = 1; i <= n; i++) {
        
	        parent[i] = i;
		
		}
    }


    // 查找根，沿途路径压缩

    int find(int x) {

        while (parent[x] != x) {

            parent[x] = parent[parent[x]];   // 把当前节点直接挂到祖父

            x = parent[x];

        }

        return x;

    }


    // 合并 x 和 y 所在集合，按秩合并

    void unite(int x, int y) {

        int rx = find(x), ry = find(y);

        if (rx == ry) {
        
	        return;
		}
  
        if (rank[rx] < rank[ry]) {

            parent[rx] = ry;

        } else if (rank[ry] < rank[rx]) {

            parent[ry] = rx;

        } else {

            parent[ry] = rx;

            rank[rx] += 1;

        }

    }

    bool same(int x, int y) { 
    
	    return find(x) == find(y); 
	
	}

};

```

> 💡 **路径压缩**有两种写法：

> - **路径减半**（上面代码）：每次让当前节点直接挂到祖父，迭代写法，常数小

> - **完全压缩**（递归写法）：`return parent[x] = find(parent[x]);`，一次性把整条路径全部挂到根，逻辑更简洁
  
## 内部原理

**为什么路径压缩有效**：每次 `find` 都把沿途节点拉近根，下次再查询这些节点时几乎 $O(1)$ 完成。多次操作均摊下来非常快。

**为什么按秩合并有效**：若把矮树挂到高树根下，新树的高度不变；只有两树等高时新树高度加 1。这样树的高度增长是对数级别的，最坏情况单次 `find` 也只走 $O(\log n)$ 步。

**两者结合的玄学**：单独用路径压缩，最坏 $O(\log n)$；单独用按秩合并，最坏也是 $O(\log n)$；但两者一起用，均摊复杂度降到 $O(\alpha(n))$（Tarjan 1975 年的经典结果）。

## 适用场景

- 判断图中两节点是否连通（[[Kruskal]] 求最小生成树的核心）

- 维护等价关系的传递闭包

- 离线处理"删边"问题（倒序处理变成"加边"）

- 二分图判定（用扩展域的 [[种类并查集]]）

- 维护到根距离/边权关系（用 [[带权并查集]]）

- 不适用：需要"分裂"集合的操作（并查集只能合并，分裂需要更复杂的结构）
