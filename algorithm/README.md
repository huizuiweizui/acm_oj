# 第一部分：给读者

## 这是什么

这是一份个人学习与复习用的算法笔记仓库。整个仓库按九大主题组织，每篇笔记是一个独立的 Markdown 文件，通过 Obsidian 的 `[[双向链接]]` 互相引用，形成一张可点击跳转的知识图谱。

笔记的定位是——

- 🚫 **不是入门教程**：不会从最基础的"什么是变量"讲起，默认读者有一定算法基础
- 🚫 **不是参考手册**：不会面面俱到地罗列每种变体、每个 API
- ✅ **而是**："对一个算法的**核心理解** + 可直接复用的**代码模板** + 经得起推敲的**正确性论证**"

如果你已经在学算法竞赛、想找一份"看得见思考过程"的笔记复习参考，这里可能合你的胃口。

## 仓库怎么用

### 推荐工具：Obsidian

下载 Obsidian 后用 "Open folder as vault" 打开仓库根目录即可。所有 `[[]]` 都会变成可点击的跳转链接。

- **直接在 GitHub 上浏览**：双链显示为纯文本，但所有内容仍可阅读

打开仓库后请先看 **`Map.md`**——它是整个仓库的索引页，按九大主题列出所有笔记，点击就能跳转。

**几个值得说明的设计**——

- **题目描述**用引用块（`>`）标注，与正文清晰分开
- **代码风格**：C++17/20、`snake_case` 命名、`class` 封装、1-indexed、`long long` 默认
- **数学公式**用 LaTeX 渲染（Obsidian 内置支持）
- **正确性证明**是每篇的灵魂——算法笔记的价值不在代码本身（百度也能搜到），而在"**为什么这个算法是对的**"
- **相关例题不剧透解法**——只给题号和题名，让你先思考、刷题中体会算法的"使用感"

### DP 笔记的额外结构

动态规划笔记在标准骨架基础上，会显式列出——

- **状态定义**：$f[i][j]$ 表示什么

## 学习路线建议

### 如果你刚开始接触算法竞赛

1. **基础**：位运算、二分查找、前缀和、双指针

### 模板的灵活性

- **前置知识可整块删除**：如果笔记没有真正的前置依赖，删掉整块（不要保留空小节）

## 写作风格

### 整体语气

- **个人化**：像写给自己看，可适度用"舒适区""硬核""坑"等口语词
- **见解 vs 复述**：不只罗列事实，要带"为什么"的剖析
- **类比与对比**：常用类比（如"前缀和让区间和 $O(1)$，前缀哈希让子串哈希 $O(1)$"）
- **设问引导**：用反问 / 设问引导思考（"为什么是 $\sqrt n$？"）

### 难度标记格式

`#难度/★★★`（注意 `#难度/` 前缀和星号数）

### Markdown 格式约定

#### 标题层级

- `#难度/★★★`（笔记开头的难度标签）
- `## 一级小节`（核心结构）
- `### 二级小节`（小节内的细分，如"模板一"、"应用一"）

#### 引用块

- 开头用引用块（`>`）给出"一句话概括"——简洁有力
- **题目描述也用引用块**——让题面与正文清晰分开

```markdown
> 共有 $n$ 级台阶，每次只能跨 1 级或 2 级，问从第 0 级到第 $n$ 级有多少种走法。
```

- 重要命题 / 关键定理也用引用块包裹

#### 加粗术语 + 冒号结构

定义性内容用这种结构，清晰且易于扫读——

```markdown
- **本质**：...
- **核心性质**：...
- **关键操作**：...
- **不变量**：...
```

#### 表格用法

适合做"对比"和"罗列"，但要**节制**——

- **复杂度分析小节绝不用表格**，一律用嵌套列表：

  ```markdown
  - 时间复杂度：
    - 朴素：$O(nm)$
    - 优化：$O(n \log n)$
  - 空间复杂度：$O(n)$
  ```

- **横向算法对比表**不每篇都给——只在最值得放的一篇放一次（如背包系列的对比表只放在 [[0-1背包]]）
- 必含的横向对比表要有 3-5 个维度，并以"经验"小结收尾

#### 列表风格

- **优势 / 劣势 / 适用场景**：用 `-` 列表
- **步骤**：用 `1.` `2.` `3.` 编号
- 列表末尾常以"**不适用**：..."收尾，反衬正例

#### 相关例题——不剧透解法

```markdown
## 相关例题

- [洛谷P1048 采药](https://www.luogu.com.cn/problem/P1048)
- [洛谷P2871 Charm Bracelet](https://www.luogu.com.cn/problem/P2871)
```

**不要**在题号后写括号解释（如"模板题"、"经典 TSP"）——这会剧透解题方法。让读者自己刷题、自己体会。

### 代码风格

#### 基本规范

- **语言**：C++17 / 20（默认 GCC 11 环境）
- **命名**：蛇形命名 `snake_case`（类、变量、函数都用）
- **下标**：数组 **1-indexed**（`a[1]` 是第一个元素）
- **类封装**：`private:` 和 `public:` 分开
- **类型**：默认 `long long` 防溢出
- **注释**：中文注释，标在关键步骤

#### 现代 C++ 特性

- 结构化绑定：`auto [u, w] = pq.top();`
- `auto` 类型推导
- `mt19937` 替代 `rand()`

#### 代码示例

```cpp
class fhq_treap {
private:
    struct node {
        int val, priority;
        int lson, rson, sz;
    };
    vector<node> tr;
    int root;
    mt19937 rng;

    int new_node(int val) {
        tr.push_back({val, (int)rng(), 0, 0, 1});
        return (int)tr.size() - 1;
    }

public:
    fhq_treap() : rng(chrono::steady_clock::now().time_since_epoch().count()) {
        tr.reserve(1);
        new_node(0);                        // 0 号位作哨兵
        root = 0;
    }
};
```

#### 状压 dp 的下标例外

涉及位运算时（如状压 dp），代码可使用 **0-indexed**——这样位 $i$ 与元素 $i$ 自然对应。这是 1-indexed 默认规则的合理例外。

### 数学公式约定

#### 行内 vs 块级

- 行内公式：`$O(\log n)$`、`$\binom{n}{k}$`
- 块级公式：用 `$$ ... $$` 包裹

#### 函数名 / 标识符渲染

⚠️ **Obsidian 渲染陷阱**：

- 错误：`dfs(v_i+1)`——下标 `_` 不会渲染（Markdown 视为下划线分隔）
- 正确：`$\mathtt{dfs}(v_{i+1})$`——用 `\mathtt{}` 转为等宽字体、`_{}` 让下标正确渲染

函数名出现在公式中常用 `\mathtt{}`：

```markdown
$\mathtt{push\_down}$、$\mathtt{find}(x)$、$\mathtt{exgcd}(a, b)$
```

#### 证毕符号

证毕用 `$\blacksquare$`，不用其他符号。

```markdown
所以 $a^{p-1} \equiv 1 \pmod p$。$\blacksquare$
```

#### 数学术语

- 区间用 $[l, r]$ 而非 $[l..r]$
- 取整 $\lfloor x \rfloor$
- 模 $p$ 用 `\pmod p` 或 `\bmod p`
- 集合用 `\{` `\}`

### 提示框使用

- **💡 提示**：解释技巧、妙处、可优化点
- **⚠️ 警告**：陷阱、易错点、必须注意的细节

```markdown
> 💡 **`int& p` 作为参数**：传递的是节点编号的引用——这样自动建立父子关系。

> ⚠️ **必须用 `long long`**：路径长度可能达 $10^{14}$，远超 `int` 范围。
```

每篇笔记通常 3-7 个提示框，分布在代码块之后或关键段落处。

## DP 笔记的特别建议

DP 模块的笔记除标准模板外建议特别突出——

- **状态定义**：`f[i][j]` 表示什么
- **转移方程**：用数学公式清晰写出
- **初始化与边界**：`f[0][0] = ?`
- **答案位置**：从 `f[][]` 中取哪个元素

放在"核心思想"小节，让"状态/转移怎么来的"成为整篇的灵魂——这部分要详细到读者能复现思路。例：

```markdown
## 核心思想

**状态定义**：$f[i][j] = $ ...

**转移方程**：

$$f[i][j] = \min \left( f[i-1][j], f[i-1][j-w_i] + v_i \right)$$

**初始化**：$f[0][\cdot] = 0$

**答案**：$f[n][V]$
```

DP 代码模板要给**完整二维版**和**滚动数组版**两个；0-1 背包"倒序枚举"这类陷阱用 ⚠️ 单独标注。

## 几个易踩的坑

| 坑 | 错误 | 正确 |
| --- | --- | --- |
| 函数下标渲染 | `dfs(v_i+1)` | `$\mathtt{dfs}(v_{i+1})$` |
| 文件夹双链 | `[[图论]]` | "图论"（普通文本） |
| 行内代码下划线 | 表格中的 `inv_fact` 可能渲染异常 | 表格中改用 `$\mathtt{inv\_fact}$` |
| 复杂度用表格 | 列三列对比时间空间 | 改用嵌套列表 |
| 例题加剧透 | "P1234 ABC（模板题）" | "P1234 ABC" |

### 风格示例片段

#### 笔记开头

```markdown
#难度/★★★★

> 自平衡的二叉搜索树——FHQ Treap 用 split + merge 两个核心操作以 $O(\log n)$ 期望复杂度支持插入、删除、第 $k$ 小、排名、前驱后继。

## 前置知识

- [[堆]]
- [[二分查找]]

## 定义与特性

- **本质**：一种自平衡的**二叉搜索树**——既满足 BST 性质（左 < 当前 < 右），又通过随机机制维持期望树高 $O(\log n)$
```

#### 正确性证明

```markdown
## 正确性证明

### 关键不变量：取出即最优

**命题**：每当节点 $u$ 从堆中取出且未过期时，$\mathtt{dist}[u]$ 是 $s \to u$ 的真实最短路。

**证明（反证 + 归纳）**：设 $u$ 是第一个被错误确认的节点... [省略推导]

合并得 $\mathtt{dist}[v_i] < \mathtt{dist}[u]$。但 $v_i$ 此刻在堆中——按算法应优先取出 $v_i$，与"$u$ 被取出"矛盾。$\blacksquare$
```
