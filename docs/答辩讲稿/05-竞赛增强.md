# 答辩讲稿 05 · 竞赛增强（IOI/封榜/补题/虚拟参赛）

> 对应 M8–M9。让平台的竞赛体验"专业起来"。配套技术文档：`docs/05-竞赛增强与社区功能.md`。

---

## 一、答辩讲稿（口播，约 2–3 分钟）

> "这一块是竞赛体验的增强，做了两件事。
>
> **第一，补全 IOI 赛制和封榜。** 原来的排行榜只支持 ICPC 赛制，也就是按'解题数 + 罚时'排名。我把它扩展成同时支持 **IOI 赛制**——IOI 是**分数制**，每道题按测试点通过率给部分分，按总分排名。同时我实现了 **ICPC 的封榜机制**：比赛快结束前的一段时间，新的提交在榜单上**隐藏起来**，只显示一个'封榜尝试'的锁图标，等比赛结束后再一次性揭晓——这就是 ICPC 现场赛最紧张的'滚榜'环节。
>
> **第二，补题和虚拟参赛。** 比赛结束后题目还能做，叫**补题**。我给每道题标了三种状态：赛中就过了、赛后补过了、还没过。**虚拟参赛**是指比赛结束后，一个人可以**按个人计时**重新打这场比赛，就像在原来的时间窗口里参赛一样。这两个功能有个巧妙的地方：我**完全没有改动提交逻辑**，而是靠'提交时间落在哪个窗口'来判定归属——赛中 AC 就算赛中、赛后 AC 就算补题、落在个人虚拟窗口里就算虚拟通过。"

---

## 二、原理拆解

- **ICPC vs IOI**：ICPC 是"过题数 + 罚时"（全或无），IOI 是"分数制"（部分分、按总分）。两种排名逻辑不同，我按赛制分支。
- **封榜为什么存在**：保留比赛悬念。最后一小时的提交隐藏，结束后滚榜揭晓，是 ICPC 的标志性体验。
- **补题/虚拟参赛为什么不用改提交逻辑**：用"时间窗口判定归属"代替"特殊标记"——提交还是普通提交，是否算赛中/补题/虚拟，由它的时间戳落在哪个区间决定。这叫**用数据的自然属性代替额外状态**，更简洁、不易出错。

## 📚 这里你需要懂的

- **ICPC 和 IOI 两种赛制的区别**（罚时制 vs 分数制）。
- **封榜（frozen scoreboard）是什么、为什么要**。
- **补题三态**怎么靠"有没有 contest 关联 + 时间"判定。
- **虚拟参赛**怎么用"个人开始时间 + 原赛时长"定个人窗口。
- **核心思想**：用时间窗口判定归属，不加额外状态字段。

## 🎓 需要补学的知识

- **ACM-ICPC 与 IOI 赛制规则**：罚时怎么算（每题 AC 用时 + 错误 ×20 分钟）、IOI 怎么按测试点给分。
- **Codeforces 的 virtual contest / 封榜**：体验过或了解一下，能说清你"参照"了什么。
- **时间区间判定的思路**：理解"用时间戳归类"比"加 flag"更鲁棒。

## 五、评委可能这样问 + 怎么答

**Q：IOI 的部分分和你前面成绩管理的部分分是一回事吗？**
> A：底层数据一样——都来自评测器记录的每个测试点是否通过。区别是用途：成绩管理里是某次作业的得分，IOI 排名里是把它换算成竞赛积分按总分排名。复用了同一份 `test_results` 数据。

**Q：封榜的提交真的"消失"了吗？数据丢了？**
> A：没丢。提交照常入库，只是**排名计算时**把落在封榜窗口内的提交跳过、不计入得分，只累加一个隐藏计数。比赛结束后判断失效，它们自动重新计入——所以是"显示层隐藏"，不是数据删除。

**Q：虚拟参赛你怎么实现的？为什么说没改提交逻辑？**
> A：我新建了一张虚拟参赛表，记录某人虚拟开始的时间，个人截止就是开始加原赛时长。学生还是去题目页正常提交，统计虚拟成绩时，我只看他的 AC 提交时间有没有落在这个个人窗口里。提交流程一行没改。
