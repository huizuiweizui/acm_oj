# 答辩讲稿 04 · 基于知识图谱的个性化学习路径

> 创新点三。配套技术文档：`docs/04-知识图谱学习路径.md`。

## 一、答辩讲稿（口播，约 3 分钟）

> "第三个创新点是**基于知识图谱的个性化学习路径**。
>
> **背景是这样：** 我的平台里已经有 62 个算法知识点，以及它们之间的关系——比如'学 Dijkstra 之前要先会堆'。这构成了一张**知识图谱**。但之前这张图只用来**展示**。我这个模块让它真正'用起来'：给定一个学习目标，结合学生的做题记录，**自动告诉他该按什么顺序学、每个知识点掌握了没有、接下来该练哪些题**。
>
> **核心算法是图论的。** 知识点之间的'前置依赖'关系构成一个**有向无环图**（DAG）。要学某个目标知识点，必须先学它所有的前置。我对目标节点沿前置边做**后序深度优先遍历**——后序遍历的性质保证：**任何一个节点被输出之前，它的所有前置都已经被输出了**。所以后序遍历的结果天然就是一个'依赖在前、目标在后'的合法学习顺序。我还用一个 visited 集合防止重复访问和成环死循环。
>
> **掌握度和推荐是数据驱动的。** 理想情况下需要题目和知识点的显式关联，但平台暂时没有这个字段，我用了**标签启发式**——把题目的标签和算法名做匹配，把题挂到知识点上。然后一个知识点如果学生关联题做对了过半，就算掌握；没掌握的知识点，就从它的关联题里挑还没 AC 的推荐给学生。
>
> **我也诚实地写了局限**：标签启发式精度依赖标签质量，根本的改进是给题目加'知识点'的显式标注，甚至可以用 NLP 从题面自动抽取——这是我论文的未来工作。另外掌握度现在只用'通过率过半'这种简单规则，可以升级成知识追踪模型，比如贝叶斯知识追踪 BKT 或深度知识追踪 DKT，这会让'数据科学'的含量更高。"

## 二、原理拆解

- **为什么后序 DFS 就是合法学习顺序**：后序 = "处理完所有孩子（前置）才处理自己"。所以前置一定排在目标前面，正好是拓扑序的一种。
- **DAG 为什么无环**：前置关系不应该循环（A 是 B 前置、B 又是 A 前置说不通），所以是有向无环图，能做拓扑排序。
- **标签启发式的本质**：在缺少显式关联时，用"标签名 ⊆ 算法名/类别"这种字符串匹配近似"题考哪个知识点"。

## 📚 这里你需要懂的

- **什么是有向无环图（DAG）**、为什么前置关系是 DAG。
- **什么是拓扑排序**、它和"合法学习顺序"的关系。
- **DFS 的前序/后序区别**，以及**为什么后序遍历能得到依赖在前的顺序**（必问）。
- **为什么要 visited 集合**（防重复、防环）。
- **掌握度是怎么算的**（关联题通过率 ≥ 0.5），以及它的粗糙之处。
- **标签启发式的局限**，以及更好的做法是什么。

## 🎓 需要补学的知识

- **图论基础**：有向图、DAG、拓扑排序、DFS（前序/后序）。这是这块的硬核基础，一定要懂。
- **知识追踪（Knowledge Tracing）**：了解 **BKT（贝叶斯知识追踪）** 和 **DKT（深度知识追踪，用 LSTM）** 是什么——即使你没实现，能在论文/答辩里说"掌握度可升级为 BKT/DKT"会非常加分。
- **推荐系统入门概念**：基于内容的推荐 vs 协同过滤（你这是基于内容/知识点的）。
- **（可选）TF-IDF / 文本向量化**：用于"从题面自动抽知识点"的未来工作，平台已有 bge-m3 向量可用。

## 五、评委可能这样问 + 怎么答

**Q：为什么用后序 DFS，而不是别的排序？**
> A：因为学习有"前置必须先学"的约束，本质是在 DAG 上求拓扑序。后序 DFS 是求拓扑序的标准方法之一：处理完所有前置才输出自己，保证前置一定在前面。

**Q：你怎么知道一道题考的是哪个知识点？这关联可靠吗？**
> A：目前用标签启发式——题目标签和算法名匹配。我承认它精度有限，依赖标签质量。更可靠的做法是给题目加显式的知识点标注，或者用 NLP 从题面/题解自动抽取，这是我明确写出的未来工作。（★ 主动认局限，别硬撑。）

**Q：这块的"数据科学"体现在哪？**
> A：体现在两点：一是用图算法把知识点结构化、规划学习路径；二是用学生做题数据估计掌握度、做个性化推荐。而且我指出了可以升级到知识追踪模型（BKT/DKT），那是更典型的数据科学方法。

**Q：掌握度只用"通过率过半"是不是太简单了？**
> A：是的，这是一个可解释的基线。它没考虑题目难度、尝试次数、遗忘等因素。论文里我把它列为局限，并指出可以用知识追踪模型替代——这恰好是一个很好的延伸方向。

**Q：如果知识图谱的边是错的怎么办？**
> A：边一部分是人工精选的关键依赖、一部分从笔记的双向链接自动解析（见 DEVLOG 阶段十）。错误的边会影响路径，但 DAG + visited 保证不会死循环；后续可以引入专家审核或数据驱动的依赖挖掘来提升边的质量。
