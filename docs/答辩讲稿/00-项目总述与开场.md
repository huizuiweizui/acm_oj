## 二、开场陈述（2–3 分钟，正式开讲）

> "各位老师好。我的题目是《（你的题目）》。
>
> **先说背景。** 现在的在线评测系统（OJ）大多面向竞赛，而高校教学需要的是**考试和作业**——这两件事差别很大：考试要支持选择/判断/填空这些客观题，要限时、要防作弊、要能自动算成绩、要能查重。所以我做的不是又一个竞赛 OJ，而是把竞赛 OJ **扩展成一个全校能用的考试平台**，参照了拼题 A（PTA）的设计思路。
>
> **整体上我做了四块：** 第一块是**考试地基**——客观题题库、函数题、考试容器、成绩管理；第二块是**三个数据科学创新点**；第三块是**竞赛增强**——IOI 赛制、封榜、补题、虚拟参赛；第四块是**团队与社区**——助教角色、题单、题解区等。一共规划并实现了 13 个功能里程碑。
>
> **重点说三个创新点：**
> - 第一，**代码查重**。学生抄代码只要改个变量名、调下格式就能骗过文本比对。我用了 Winnowing 指纹算法，先把代码做词法归一化、再取指纹集合算相似度，能抗住'改名+重排版'这类抄袭。
> - 第二，**竞赛 Rating**。我实现了 Codeforces 的评分模型，比赛结束后按名次更新每个人的 Rating，赢强者涨得多、整体守恒。
> - 第三，**个性化学习路径**。我把算法知识点组织成前置依赖图，结合学生的做题记录，自动生成'该按什么顺序学、每个点掌握没掌握、该练哪些题'。
>
> **技术上**，后端是 Django REST Framework，前端是 Vue 3 单页应用，前后端用 JWT 认证、REST API 通信。下面我详细讲。"

## 三、背后的整体思路（你要能讲出"为什么这么搭"）

- **为什么前后端分离**：评测、考试这些逻辑重，前端要做编辑器、计时、图表，分离后各自演进、接口清晰。
- **为什么分这么多模块**：每个功能各成一个 API 模块（查重、考试、题单……），互不缠绕，好维护好测试。
- **为什么"加表不改表"**：扩展时只加新表/新字段，不动旧逻辑，保证原有竞赛功能不退化。
- **三个创新点为什么算创新**：它们不是 CRUD（增删改查），而是**有算法、有数学、能做实验**的——这正是"数据科学方向"该体现的含量。

## 📚 这里你需要懂的（答辩前务必能脱口而出）

- **你的项目一句话是什么**：竞赛 OJ → 全校考试平台 + 三个算法创新点。别只会说"做了个网站"。
- **三个创新点各解决什么问题**：查重防抄袭、Rating 量化实力、学习路径做个性化导航。
- **为什么这三个是"创新点"而不是普通功能**：因为有算法/数学/实验，不是堆界面。
- **整体架构**：浏览器(Vue) ↔ REST API(Django) ↔ 服务层(算法) ↔ 数据库；JWT 认证。

## 🎓 需要补学的知识（不熟就去补）

- **Web 前后端分离 / RESTful API 是什么**：知道"前端发请求、后端返 JSON"这套模型。
- **JWT（JSON Web Token）认证**：知道登录后拿 token、每次请求带 token 的流程即可。
- **Django + Django REST Framework 基本概念**：Model（模型/表）、View（视图/接口）、Serializer（序列化器）、Migration（迁移）。
- **Vue 3 单页应用（SPA）大概念**：组件、路由、状态管理——不用精通，但要知道页面是 JS 动态渲染的。
- **PTA / Codeforces / LeetCode 这些平台**：你"参照"了它们，要能说出各自特点（PTA 重教学、CF 重竞赛与 Rating、LeetCode 重练习与题解）。

## 五、评委可能这样问 + 怎么答

**Q：你的创新点到底是什么？工作量在哪？**
> A：创新点是三个有算法深度的模块——查重、Rating、学习路径，分别对应论文三章，每个都有数学方法、实现和实验。工作量上，一共 13 个功能里程碑，后端 6 个新 API 模块、9 个数据库迁移，前端十几个页面，并且每个模块都写了端到端测试。

**Q：和现有的 OJ（比如 PTA、洛谷）有什么区别？为什么不直接用它们？**
> A：现有系统要么偏竞赛、要么是闭源商业产品，无法二次开发、无法把查重/Rating/学习路径这些算法按我的研究思路定制。我的工作是把它们的优点整合，并在查重、评分、学习路径上做了可实验、可改进的实现。

**Q：这些功能是不是调了现成的库 / 抄了现成代码？**
> A：界面和框架用了成熟技术（Django/Vue），但三个核心算法（Winnowing 查重、CF Rating、学习路径）都是我**按论文/算法自己实现**的纯 Python 模块，可独立测试。比如查重那块我还踩过坑、做过实验对比。

**Q：（如果被问）有没有上线 / 真实用户？**
> A：目前完成了功能实现与后端端到端测试、前端构建验证，尚未做大规模实跑和压测。我在论文里如实写了这一点，并列出了上线前要做的事（评测沙箱压测、浏览器实跑）。
