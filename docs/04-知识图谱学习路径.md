# 亮点三：基于知识图谱的个性化学习路径

> 对应里程碑 M7。实现：`judge/learning_api_views.py` + 复用已有的 `Algorithm` / `AlgorithmEdge` 模型 + 前端 `LearnDetailView.vue`。

---

## 1. 问题背景与动机

平台已有 62 个算法知识点（`Algorithm`）和它们之间的关系边（`AlgorithmEdge`，前阶段构建的算法知识图谱）。但图谱此前只用于**可视化展示**。本里程碑让它真正「用起来」：

> 给定一个目标算法（如「动态规划」），结合用户的做题历史，自动生成
> **「应该按什么顺序学」的前置路径 + 每个知识点的掌握度 + 该学/该练哪些题**。

这把静态知识图谱变成**个性化学习导航**，是数据驱动教育的典型应用。

## 2. 相关工作

| 方向 | 关系 |
|------|------|
| 知识追踪（Knowledge Tracing, BKT/DKT） | 建模学生对知识点的掌握概率；本实现用简化的「做题通过率」近似 |
| 前置关系图（Prerequisite Graph） | 学习顺序规划的图论基础；本实现的核心 |
| 学习路径推荐 | 在前置 DAG 上做拓扑/最短路；本实现用后序 DFS |

## 3. 方法

### 3.1 图模型

知识图谱是有向图 $G=(V, E)$：

- $V$：算法知识点（62 个）
- $E$：三类边——`prerequisite`（前置依赖）、`related`（相关）、`extends`（扩展）

学习路径只关心 **`prerequisite` 子图**：边 $a \to b$ 表示「$a$ 是学 $b$ 的前置」。它构成一个 **DAG**（前置不成环）。

### 3.2 前置路径：后序 DFS

要学目标 $T$，需先学它所有（递归的）前置，且**前置在前**。对 $T$ 沿 `prerequisite` 边做**后序 DFS**：

$$
\text{后序遍历顺序} \;\Longrightarrow\; \text{依赖在前、目标在后的拓扑序}
$$

```python
def _prereq_order(target):
    visited, order = set(), []
    def dfs(a):
        if a in visited: return
        visited.add(a)
        for pre in prerequisites(a):   # a 的前置
            dfs(pre)
        order.append(a)                # 后序：所有前置入列后才入列 a
    dfs(target)
    return order                       # [前置..., 目标]
```

- **后序**保证：任一节点入列前，其所有前置已入列 → 天然是合法学习顺序。
- `visited` 防止重复访问与（异常）环导致的死循环。

### 3.3 掌握度模型

理想情况需要 `Problem ↔ Algorithm` 的显式关联，但平台暂无此字段。采用**标签启发式**：题目的标签名与算法名/类别做双向子串匹配，把题挂到知识点上。

知识点 $a$ 的掌握度：

$$
\text{mastered}(a) =
\begin{cases}
\text{true} & \dfrac{|\{\text{关联题中用户已 AC}\}|}{|\{a \text{ 的关联题}\}|} \ge 0.5 \\
\text{false} & \text{否则}
\end{cases}
$$

即「该知识点关联题做对过半」视为掌握。

### 3.4 推荐

对路径上每个**未掌握**的知识点，从其关联题里挑**未 AC 的前若干道**作为推荐练习，优先低难度。

## 4. 实现与接口

- 复用 `Algorithm`（节点）与 `AlgorithmEdge`（边，`edge_type='prerequisite'`），无需新表。
- `learning_api_views.py` 提供 `GET /api/learning-path/<algo_id>/`：返回有序前置路径，每个节点带 `mastered` 标记、关联题数、推荐题列表。
- 前端在算法详情页 `LearnDetailView` 加「个性化学习路径」节：登录后展示带 ✓ 的有序路径与推荐题；点击题目跳转。

> 测试：构造前置链 `dp ← bsearch ← sort`（dp 依赖 bsearch 依赖 sort），目标 dp 的路径顺序正确为 `[sort, bsearch, dp]`；用户 AC 过排序题 → sort 标记掌握；dp 为目标且推荐其 2 道未解题。

## 5. 局限与未来工作

- **标签启发式精度有限**（论文要诚实写）：依赖标签数据质量，可能漏挂/错挂。**根本改进是加 `Problem.algorithms` 多对多显式关联**（可由出题人标注或用 NLP 从题面/题解自动抽取）。
- **掌握度模型粗糙**：只用「通过率 ≥ 0.5」，未考虑题目难度权重、遗忘曲线、尝试次数。可升级为 BKT/DKT 等知识追踪模型——这本身是很好的论文延伸点。
- **路径未做难度平滑**：当前只保证依赖顺序，未在同层按难度递增排序。

## 6. 写进论文的建议

**可表述为的创新点**：

> 「将算法知识点组织为前置依赖有向无环图，基于**后序深度优先遍历**生成满足依赖约束的个性化学习路径；结合用户做题历史以通过率近似知识点掌握度，对未掌握节点推荐针对性练习，实现从静态知识图谱到数据驱动学习导航的转化。」

**建议补充/延伸**：

1. **掌握度升级为知识追踪**：用 BKT（贝叶斯知识追踪）或 DKT（深度知识追踪，LSTM）替代简单通过率，对比预测准确度——这能显著提升论文的「数据科学」含量。
2. **显式题目-知识点关联**：用 TF-IDF / 向量检索（平台已有 bge-m3）从题面自动给题打知识点标签，量化对推荐质量的提升。
3. **路径质量评估**：构造若干「学习目标」，对比「本方法路径」与「专家给定路径」的一致性。
4. **与图谱可视化联动**：在力导向图上高亮个人学习路径与掌握状态，形成「可视化 + 个性化」的组合卖点。
