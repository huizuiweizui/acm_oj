## 项目一句话定位

一个**算法竞赛 OJ**，本阶段扩展为**面向全校师生的考试 / 作业平台**（参照拼题 A / PTA），并补齐三个有算法深度的数据科学创新点。

## 技术栈

| 层 | 技术 |
|----|------|
| 后端 | Django 4.2 + Django REST Framework + SimpleJWT |
| 数据库 | MySQL |
| 评测 | 子进程 / Docker 沙箱（`judge/services/`） |
| 任务队列 | Celery + Redis（评测 / AI 反馈异步化） |
| 前端 | Vue 3（`<script setup>`）+ Vite + Pinia + Vue Router + Monaco + ECharts |
| AI/向量 | LLM API + bge-m3 向量检索（前阶段已有） |

## 整体架构（本阶段视角）

```
浏览器 (Vue 3 SPA)
   │  /api/* (axios + JWT)
   ▼
Django REST API —— 按域分文件（本阶段新增 6 个模块）
   ├── question_api_views.py   客观题题库
   ├── exam_api_views.py       考试答题流 + 成绩单 + 查重
   ├── list_api_views.py       题单 / 训练计划
   ├── community_api_views.py  题解 / 提交分布 / 每日一题
   ├── learning_api_views.py   知识图谱学习路径
   └── contest_extra_api_views.py  补题 / 虚拟参赛
   │
   ▼
judge/services/  —— 纯算法/服务层（不耦合视图）
   ├── similarity.py   ★ Winnowing 查重（纯 Python）
   ├── rating.py       ★ CF 式 Rating 结算
   ├── judger.py       评测核心（本阶段绝对不动）
   └── sandbox.py      执行隔离
   │
   ▼
judge/models.py  —— 数据模型（本阶段加表不改表，迁移 0016→0024）
```

**三条架构原则**（贯穿整个扩展）：

1. **不碰评测核心**：`judger.py` 的 `judge_submission()` 绝对不动；需要特殊评测的（函数题）在提交前把代码处理成完整程序再喂给它。
2. **加表不改表**：新功能用新模型或给现有模型加**可空字段**，9 个迁移全是增量、无破坏性改动。
3. **API 按域分文件**：避免 `api_views.py` 继续膨胀，新功能各自成模块。
