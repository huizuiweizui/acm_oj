## M8 IOI 赛制排名 + 封榜滚榜

原 `ContestRankingAPIView` 只实现 ICPC（解题数 + 罚时）。本里程碑重写为同时支持两种赛制 + 封榜（迁移 `0022` 加 `ContestProblem.points`、`Contest.freeze_minutes`）。

### IOI 分数制

每题得分 = `round(题目分值 points × 该选手最佳测试点通过率)`——**部分分**，复用评测器的 `test_results`。按总分降序排名。排名视图按 `rule_type` 分支：ICPC 走解题数+罚时，IOI 走总分。

### 封榜（frozen scoreboard）

ICPC 经典体验。赛末 `freeze_minutes` 内的提交在榜上**隐藏**：

```
freeze_start = end_time − freeze_minutes
逐提交累计时：若 freeze_start ≤ 提交时刻 < end_time:
    不计入得分，只给该题 frozen 计数 +1（显示 🔒）
    continue
```

`frozen` 标记让前端显示「封榜中」横幅；比赛结束后判断失效、自动揭晓（滚榜）。

> 测试：IOI 双人——A=满分100+半分50=150、B=1/4分25+满分100=125，名次 1/2 正确；封榜场景下「此刻提交」被隐藏为 0 分 + frozen 计数 1。

## M9 补题 + 虚拟参赛

实现于 `contest_extra_api_views.py`，**不改动提交逻辑**（赛后题目仍公开可提交，靠时间判定归属）。

### 补题状态机

`/contests/<id>/my-progress/`：每题三态——

| 状态 | 定义 |
|------|------|
| `in_contest` | 有 contest 关联的 AC（赛中通过） |
| `upsolved` | 赛后才 AC（补题成功） |
| `unsolved` | 从未 AC |

### 虚拟参赛

新增 `VirtualParticipation`（迁移 `0023`）。赛后以**个人计时**重开一场：

- `/virtual-start/`：记录个人开始时刻，个人截止 = 开始 + 原赛时长
- `/virtual-status/`：统计**个人窗口内**的 AC 作为虚拟通过

学生照常去题目页提交，落在个人窗口内的 AC 即计数——无需特殊关联。

> 测试：p1 赛中 AC→`in_contest`、p2 赛后 AC→`upsolved`；虚拟参赛 `started=true`、个人时长 7200s、窗口内 AC 计数 1。

## M10 团队 TA 角色 + 院系层级

### 助教（TA）

`TeamMembership.ROLE_CHOICES` 加 `assistant`。权限边界设计：

| 操作 | 创建者/管理员 | 助教 TA | 普通成员 |
|------|:---:|:---:|:---:|
| 批改/看成绩单/查重 | ✓ | ✓ | ✗ |
| 团队设置/成员管理 | ✓ | ✗ | ✗ |

实现：`exam_api_views._is_manager` 放行 `role=assistant`（→ 能管成绩相关）；团队设置仍走 `_is_creator_or_admin`（助教改不了）。

### 院系层级

新增 `Department` 模型 + `Team.department` 外键（迁移 `0024`），支撑全校规模分组。`/api/departments/` 增删、团队建/改接受 `department_id`。前端从简（字段与 API 已通，经 Django admin 管理）。

## M11 题单 / 训练计划

统一一个 `ProblemList` + `ProblemListItem`（迁移 `0019`）覆盖三种用途：**自建题单 / 收藏夹 / 团队训练计划**。

| 范围 scope | 含义 |
|-----------|------|
| `mine` | 我创建的题单 |
| `public` | 公开题单（浏览） |
| `team` | 团队训练计划（成员可见） |

详情带**该用户 AC 进度**（去重统计 solved/total）；`/add/` 一键收藏加题。访问控制：公开/私有 + 团队成员可见。

前端两页：`ProblemListsView`（我的/公开两 Tab + 新建）、`ProblemListDetailView`（进度条 + 有序题目 + 编辑增删题），导航栏加「题单」入口。

> 测试：建题单 → AC 一题 → 进度 solved=1、首题标记已过；收藏加题 count+1；`can_manage` 正确。

## M12 题解区 + 提交分布 + 每日一题

`community_api_views.py` 三件套（迁移 `0020`）。

### 题解区（防剧透）

`Solution` 模型，**AC 本题后才可见/可发**：

```python
def get(request, pk):
    if not _has_ac(request.user, pk):
        return {'locked': True, 'solutions': []}   # 未 AC：锁定
    return {'locked': False, 'solutions': [...]}
```

前端在题目页加「题解」Tab：未 AC 显示 🔒 提示；AC 后可看可发可删（作者/管理员）。

### 提交结果分布（LeetCode 式「击败 X%」）

`/problems/<id>/distribution/?metric=time|memory`：对该题所有 AC 提交的耗时/内存做**直方图分桶**（10 桶），并算当前用户的击败百分比：

$$
\text{beats}\% = \frac{|\{\text{提交} : \text{值} > \text{我的最好值}\}|}{\text{AC 提交总数}} \times 100
$$

前端在题目页「我的记录」加一行「耗时击败 X%」。

> 测试：我 100ms，另两人 200/300ms → 击败 66.7%。

### 每日一题

`DailyProblem` 模型。管理员可指定某日的题；**未指定时确定性自动选**：

$$
\text{今日题} = \text{已发布题}\big[\,\text{日期序数} \bmod \text{题数}\,\big]
$$

同一天对所有人一致、**无需定时任务**。前端首页加每日一题卡片（含「已完成」标记）。
