## 阶段十五：评测稳定性加固（队列 / 沙箱 / 限流）

真机接上 Docker 后做的一轮加固。核心问题都指向同一件事：**之前的实现只在"一个人慢慢用"的前提下成立，一旦比赛并发就崩**。

### Fix 1 — 评测队列：限制并发

**问题**：每次提交都裸起一个 `threading.Thread`，无任何上限。比赛时上百人同时交题会瞬间创建上百个线程 / Docker 容器，把评测机 CPU 与内存打满，结果是所有提交一起超时。

**修复**（新增 `judge/services/judge_queue.py`）：改为进程内固定大小的 `ThreadPoolExecutor`。

- 入队立即返回不阻塞请求，最多 `JUDGE_WORKERS`（默认 4）个评测并发，其余排队
- 懒初始化：第一次入队时才建池，避免 `migrate` 等命令凭空起线程
- `recover_pending()`：进程重启会丢掉内存里排队/在跑的任务，这些提交会永远停在 Pending/Judging。在 `apps.py` 的 `ready()` 里调用一次把它们捞回来
- 不引入 Celery / Redis，保持单进程可运行

多进程部署时总并发 = 进程数 × `JUDGE_WORKERS`，按评测机核数配这两个值。

### Fix 2 — 输出上限与 OLE

**问题**：选手程序疯狂打印（`while(1) printf`）时，Docker 的内存限制只管容器内，主机侧读取管道会把全部 stdout 缓冲进内存，几秒就能把评测机 OOM。

**修复**：新增 `_capped_communicate()`，在读取线程里对 stdout 设硬上限（`JUDGE_OUTPUT_LIMIT_KB`，默认 64 MB），超限立即 kill 并判新状态 **OLE**（Output Limit Exceeded）；stderr 单独截断。

OLE 状态贯通 model / migration / judger / 自定义运行 / 前端徽章。

### Fix 3 — Docker 沙箱隔离加固

仅 `USE_DOCKER_SANDBOX=True` 时生效：

| 参数 | 作用 |
|------|------|
| `--cap-drop=ALL` | 丢弃所有 Linux capability |
| `--security-opt no-new-privileges` | 禁止 setuid 提权 |
| `--read-only` | 根文件系统只读 |
| `--ulimit nofile` | 限制文件描述符，防 fd 耗尽 |
| `--user nobody` | 以非 root 执行选手代码（`JUDGE_SANDBOX_RUN_USER` 可一键退回 root） |
| `--network=none` | 无外网 |
| `--pids-limit=64` | 防 fork 炸弹 |

编译阶段保持可写挂载并补可写 `/tmp`。容器内实测：`uid=65534`、`CapEff` 全 0、`NoNewPrivs=1`、根/挂载只读、外网不可达。

### Fix 4 — 容器泄漏与超时判定

**问题**：`--rm` 只在容器**自行退出**后才清理。TLE / 输出超限时我们杀掉的是 `docker run` 这个**客户端**进程，容器本身还在跑，于是每次超时都泄漏一个容器。

**修复**：超时路径显式 `docker rm -f <name>` 兜底清理。

**超时判定**：时间限制改为在容器内用 GNU `timeout` 强制执行，超时退出码 **124**，与 OOM-kill 的 **137** 不冲突，两者可以准确区分。外层再留一个 `JUDGE_DOCKER_OUTER_BUFFER` 秒的兜底超时，只用于覆盖容器启动开销与守护进程异常。

解释器 / 虚拟机的启动耗时不该算进选手的算法时间，按语言给了少量宽限（C/C++ 0.5s、Python 1.0s、Java 2.0s）。

### Fix 5 — 接口限流

原本无任何限流：登录可被爆破、AI 问答每次调用都花钱、提交与自定义运行可被脚本刷。

为"花钱的、可爆破的、可刷的"端点加作用域限流（DRF `ScopedRateThrottle`）：

| 作用域 | 额度 | 理由 |
|--------|------|------|
| `login` | 10/min | 防口令爆破 |
| `register` | 30/hour | 校园 NAT 共用出口 IP，给得较宽 |
| `submit` | 30/min | 真实执行代码 |
| `run` | 30/min | 同上 |
| `ai` | 30/hour | 每次调 LLM 都花钱 |
| 全局 `anon` | 300/min | 仅限匿名请求，防爬 |

**不设全局 user 限流**：前端提交后每 2 秒轮询一次评测结果，按用户限流会误伤。

限流计数存 Django 缓存。配置 `REDIS_URL` 后多进程共享同一份计数，限流才真正准确；留空则退回进程内存（单进程可用）。

### Fix 6 — 前端生产构建

补齐缺失的 `esbuild` 依赖，修复 `npm run build` 失败。
