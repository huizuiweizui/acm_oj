# 阶段二十一：星语"自己写代码"步骤、教师批量布置、15 道题默认版本补齐

分支：`feat/star-integration`。

起因：入门层学生之前最多只走到"把代码行排好"（Parsons 题），从没自己写过一行程序；教师布置任务要进每个学生的详情页逐个发起；
15 道入门题里只有 5 道有不经大模型的默认版本，没配大模型 key 时学生实际只能做 6 关 + 5 题。

## 一、写代码步骤（`type: "code"`）

每份分步任务固定以 **排一排（order）→ 自己写（code）** 收尾：先把参考解的代码行排好，再在起始代码上把整段程序写出来。

| 项 | 做法 |
| --- | --- |
| 内容结构 | `{"type": "code", "prompt", "starter", "hints"(3 条), "knowledge"}`；`starter` 是起始代码 |
| 校验规则 | code 恰好一个且在最后；order 恰好一个且在倒数第二步；`starter` 只能是 `#` 注释（每条按短句规则检查）和参考解里原样的代码行，且不能已经包含全部代码行 |
| 判定 | 先在进程内 `compile()` 只编译不运行：语法 / 缩进错直接返回，不占评测机名额；能编译的交给评测机跑测试数据（同排序题，占"自定义运行"那组并发名额） |
| 出错反馈 | 固定话术 + 第几行 + 一句固定中文说明（`ERROR_TEXT`：NameError → "用到了一个还没有的名字……"等），另给错误最后一行原文（不带沙箱路径）；编辑器行号栏把出错行标红 |
| 答案不对 | 给出第一组没通过的数据：输入 / 应该输出 / 你的程序输出（各截 200 字）。星语入门题的测试数据本来就简单，不算泄题 |
| 编辑器 | 普通 textarea + 行号栏，不用 Monaco（低刺激、不弹补全）。Tab 空四格；回车保持缩进，冒号结尾自动多缩进一层；按 Esc 后下一次 Tab 离开编辑框（不困住键盘）；草稿存本机 localStorage；"恢复起始代码"按钮 |
| 大模型 P2 | 规则与少样本示例同步加入 code 步骤；步骤数提示改为普通 3–5 步、细粒度 5–6 步（上限仍为 6） |

`runner.run_against_tests(..., detail=True)` 额外返回 `first_fail`；排序题与参考解校验不受影响。

## 二、15 道入门题全部有默认版本

`content/problems.py` 补写其余 10 道的 `default_steps`，原 5 道加上写代码步骤。每份 4–5 步：
具体例子（选择）→ 关键一处（填空）→ 排序 → 自己写；起始代码用注释列出每一块要做的事，第 3 条提示统一是"和上一步排好的代码一样。"
`test_all_default_steps_valid` 改为要求 15 道都有默认版本并以 order、code 收尾。

## 三、教师批量布置（`/star/teacher/assign`）

- `GET /api/star/teacher/assign/`：我创建的团队（管理员看全部）及其中填过问卷的学习者、各自已有的任务
- `POST /api/star/teacher/assign/`：`{learners, materials, approve}`，一组素材 × 一组学生
  - 只用默认版本（关卡套学生的兴趣主题包，入门题用 `default_steps`），不调大模型——批量调用要排很久；个性化改造仍在学生详情页单独发起
  - 关卡只发启蒙层、入门题只发入门层；已有同一素材（生成失败的除外）的跳过；结果按学生列出新布置 / 跳过及原因
  - `approve` 默认 true：默认版本已过全部规则校验，直接审核通过、学生立即可见；false 时进待审核
  - 学生看到的顺序 = 教师勾选的顺序（追加在已有任务后面）
- 学习者列表页加"批量布置任务"入口；审核页能显示和编辑起始代码

## 四、测试

```bash
DB_ENGINE=sqlite SECRET_KEY=test python manage.py test judge star   # 248 个，4 个跳过
```

新增：写代码判定 7 个（空代码不运行、语法错不运行且带行号、运行时错误说明、答案不对给数据、做对完成任务、格式错误）、
批量布置 6 个（团队范围、按层级分发并直接通过、不重复、草稿模式、题库缺题、越权与参数错误）、校验器 3 个。
另在本机实际跑通：教师批量布置 → 学生做完"两倍""打印星星"四步，写代码步骤的运行时错误、答案不对、做对三种反馈均经评测机实跑。
