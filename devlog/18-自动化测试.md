## 阶段十八：补自动化测试

阶段十五至十七的改动全部靠一次性脚本验证，跑完即弃——每改一次评测或权限都要重新搭一遍脚手架。这一轮把那些验证固化成 Django TestCase。

**90 个测试，2.3 秒跑完。**

### 组织方式

```
judge/tests/
├── base.py                 构造帮手（OJTestCase）
├── test_judger.py          输出归一化、得分折算、临时目录回收、ICPC/IOI 计分
├── test_permissions.py     源码可见性、赛题访问、比赛管理权限
├── test_api_security.py    接口层：源码不外泄、赛题不早泄、私有赛密码
├── test_ranking.py         IOI 榜排序与各题格，ICPC 榜回归
├── test_queue.py           自定义运行并发闸
└── test_urls.py            路由：旧站已移除、后台改址、SPA 不吞静态资源
```

`base.py` 把琐碎构造集中掉——模型字段多，且 `UserProfile` 没有 `post_save` 信号必须显式建，`submitted_at` 是 `auto_now_add` 只能建完再改。测试本身只写关心的部分。

### 覆盖重点

按"错了会出事"排的，不是按代码行数：

| 模块 | 守住什么 |
|------|---------|
| `test_api_security` | `?all=1` 曾能翻出全站源码；个人主页曾是第三个泄漏点；赛前响应不含题目标题 |
| `test_permissions` | 赛前/赛中/赛后 × 未登录/路人/已报名/出题人/教师 的完整矩阵 |
| `test_judger` | IOI 取最高分（后交低分不该拉低总分）；CE 提前 return 时临时目录仍要回收 |
| `test_ranking` | 同分按达成时刻排序；各题格记首次达到最高分的时刻而非最后一次提交 |
| `test_queue` | 并发不超上限；名额在正常退出与抛异常后都归还 |
| `test_urls` | `/` 不再解析到老模板首页；`/assets/*` 不被 SPA 兜底吞掉 |

### 两处测试自身写错了

跑起来才发现，都是我的预期写反，不是代码问题：

- ICPC 第二次 AC 后罚时应保持首次 AC 的 30 分钟，我写成了 50（误按第二次提交时刻算）
- `TemplateView.as_view()` 返回的函数名是 `view` 不是 `TemplateView`，断言改为比对模块名

### 验证测试本身有效

测试全绿不代表它在守东西。故意把 `code` 塞回 `SubmissionListSerializer`（即退回泄漏源码的旧行为），确认有 3 个测试立刻失败：

```
FAIL: test_list_never_includes_code
FAIL: test_list_body_does_not_contain_secret
FAIL: test_user_profile_recent_submissions_have_no_code
```

随后改回，`git diff` 对 `serializers.py` 为空。

### 跑法

```bash
python manage.py test judge.tests
```

反复跑用 `--keepdb` 跳过建库（快很多）；但它会把 `test_acm_oj` 留在 MySQL 里，下次不带该参数会因库已存在而中断，加 `--noinput` 即可自动重建。

`test_urls.py` 里的 SPA 兜底相关用例依赖 `frontend/dist` 存在（先 `npm run build`），未构建时自动跳过而不是误报失败。
