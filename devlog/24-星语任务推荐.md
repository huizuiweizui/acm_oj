# 阶段二十四：推荐下一项任务（大模型为主 + 规则兜底）

分支：`feat/star-integration`。

教师端学生详情页"任务"标签最上面新增"推荐下一项任务"：点"生成推荐"，给出 1–3 项还没布置过的素材和理由，
每项可直接"大模型改造"或"使用默认版本"布置。

## 一、双分支

```
候选素材（本层级、还没布置过的；生成失败的不算布置过）
   ├─ 规则分支：顺序 → 条件 → 循环，找第一类"没掌握"的知识点，从这一类按素材库顺序取前 3 项
   └─ 大模型分支（P6）：画像 + 作答统计 + 已布置任务 + 候选 + 规则建议 → 挑 1–3 项并写理由
          └ 程序校验（只能选候选里的、不重复、理由 ≤ 60 字、有 summary），不合格回填错误改一次
             仍不合格 / 接口失败 / 没配大模型 → 用规则分支的结果
```

- 掌握：这一类至少做对 3 步，且做对时平均提示等级 ≤ 1。没掌握且提示用得多时，规则分支建议"大模型改造"，否则"默认版本即可"。
- 规则建议也写进 P6 的提示词，大模型可以采纳也可以调整，调整时在理由里说明依据。
- 页面主推荐来自大模型（标"大模型推荐"），下面可展开"对照：规则推荐"；大模型没用上时标"规则推荐"并写原因。
- 画像和任务标题拼进提示词前做姓名脱敏，输出里的 `{name}` 换回昵称；每次调用写 `LLMCallLog`（用途 P6，迁移 `0004`）。
- `deepseek-flash` 是推理模型，800 token 会被推理过程用完、正文为空，`max_tokens` 给 2000（与 P2 一致）；实测一次约 6 秒。

代码：`star/services/recommend.py`，提示词 `prompts.p6_messages`，接口 `POST /api/star/teacher/learners/<uid>/recommend/`。

## 二、测试

```bash
DB_ENGINE=sqlite SECRET_KEY=test python manage.py test judge star   # 273 个，4 个跳过
```

`star/tests/test_recommend.py`（9 个）：没数据从顺序开始、顺序掌握后进入条件、提示多时同类巩固并建议改造、启蒙层推荐关卡；
大模型为主且规则结果保留、选了不存在的素材回填修复一次、两次不合格用规则、已布置的素材被拒、接口权限。

浏览器实测：演示学生阿杰（顺序、循环各 4 步 0 提示，条件没做过）大模型推荐"及格了吗""正数负数还是零"，理由引用了提示等级和兴趣。
