### 关键设计

**生成-校验-修复闭环（神经符号结合）。** 大模型只负责生成；结构、句长、答案唯一、代码行来源由规则检查，
关卡可解性由最短路搜索检查，参考解由评测机实跑检查。不合格时把错误清单原样回填给模型重写，
修复轮只带"原始请求 + 上一次输出 + 错误清单"，不累积全部历史。三次都不过就标"生成未通过"，
最后一次输出留给教师手改。每次调用一条 `LLMCallLog`，记录格式是否合格、规则是否通过、耗时和 token。

**重复卡只管下一张卡片。** 启蒙层先建立"同一件事做很多次"的概念，不引入嵌套循环体；
这也让程序保持线性——每张卡片是 (x, y, 朝向) 状态图上的一条边，最少卡片数可用最短路精确求出。
循环关卡另要求"不用重复卡放不进卡槽"，保证关卡真的在练循环。

**前后端规则一致。** 前端 `maze.js` 是 `maze.py` 的逐行翻译，用来播放动画；判定以后端为准。
`star/tests/maze_cases.json` 的 15 条用例同时喂给 Django 测试和 `frontend/scripts/check-maze.mjs`。

**排序题按运行结果判定。** 学生排好的代码行拼成完整程序，交给评测机跑测试数据，
所以互不依赖的两行交换顺序也算对。占用"自定义运行"那组并发名额，不抢比赛评测。

**同一性。** 学生端只看已审核、已锁定的任务；排序题的打乱顺序按任务 id 固定；对话温度 0.2，
同一学生在同一步骤问同一句话直接返回缓存；学生端页面固定配色（不随站点暗色模式变化）、无动画、
隐藏站点导航（不出现排行榜与计时）；首屏等路由解析完再画导航，避免导航栏闪一下。

**没有大模型也能完整演示。** 未配置 `LLM_API_KEY` 时：画像用规则生成，对话回固定的兜底回复，
报告用模板，任务用"默认版本"（模板 + 兴趣主题包 / 手写分步任务）。`seed_star` 生成的演示数据不依赖大模型。

### 隐私与边界

- 拼提示词前把用户名、昵称、真实姓名换成 `{name}`，模型输出后再换回昵称
- 对话里出现疼、害怕、被欺负等求助词时不经模型，固定回复"这件事请告诉老师"
- 提示词约束：不诊断、不评价情绪；画像中的沟通特点只是给教师的建议，由教师确认

### 运行

```bash
python manage.py migrate
python manage.py seed_star            # 15 道入门题 + 演示账号 + 已审核任务（--password 换掉默认密码）
python manage.py star_pregen --replace  # 配好大模型后：为演示学生批量生成个性化草稿，再到教师端审核
python manage.py star_eval all        # 四组消融实验，结果在 star_eval_results/
python manage.py test star            # 星语测试
node frontend/scripts/check-maze.mjs  # 前端规则一致性
```
