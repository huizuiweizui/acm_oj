## 阶段十六：安全修复三项（P0）

一轮代码审查后定级为"上线前必须堵"的三个口子，全部已修复并验证。

### P0-1 — 任何人可读任何人的源代码

**问题**：`SubmissionSerializer` 把 `code` 放进了字段列表，而 `SubmissionDetailAPIView` 是 `AllowAny` 且没有归属校验，`SubmissionListAPIView` 传 `?all=1` 时还会跳过 `filter(user=...)`。

也就是说 `GET /api/submissions/?all=1` 可以**分页翻出全站每个人的完整源码**，未登录也能翻。比赛期间等于开挂通道，平时是抄袭源头。`UserProfileAPIView` 的 `recent_submissions` 是第三个泄漏点，个人主页同样在发别人的源码。

**修复**：

- 新增 `permissions.can_view_submission_code()`：本人 / 教师 / 管理员可见，其余（含匿名）不可见
- 拆出 `SubmissionListSerializer`，**根本不含** `code` / `error_info` / `ai_feedback`——列表可以匿名翻（全站评测流、个人主页近期提交），这些字段跟着发出去就等于公开导出
- 详情用的 `SubmissionSerializer` 在 `to_representation()` 里按 `context['can_view_code']` 清空私密字段。**context 缺省时按不可见处理**，将来漏传 context 的调用点是少给数据而不是多给

`error_info` 和 `ai_feedback` 一并关掉：CE 信息里带源码片段，AI 反馈会复述实现思路，只关 `code` 堵不住。

**验证**：

```
匿名        can_view=False  code=0   error_info=0  ai_feedback=0
他人 bob    can_view=False  code=0   error_info=0  ai_feedback=0
本人 alice  can_view=True   code=47  error_info=30 ai_feedback=8
教师 wang   can_view=True   code=47  ...
```

### P0-2 — 讨论区存储型 XSS，可直接偷 JWT

**问题**：`MarkdownRenderer.vue` 把 `marked.parse()` 的结果直接 `v-html`，全项目没有任何净化。marked 自 v5 起已移除内置 `sanitize`。而 access / refresh token 存在 `localStorage`，refresh 有效期 14 天——一个帖子里塞 `<img src=x onerror=...>`，所有看帖的人（包括管理员）的账号就都归发帖人了。

**修复**（引入 `dompurify`）：

1. 数学占位符从 `\x00MATH{i}\x00` 改为纯 ASCII token（要能原样穿过 DOMPurify），并加随机后缀防止正文里恰好写了同样字面量
2. `marked.parse()` 之后、插入 KaTeX **之前**净化——KaTeX 的输出（大量 span + style + MathML）是可信的，反倒容易被净化规则误伤
3. 额外 `FORBID_TAGS: form/input/button/select/option/textarea`——DOMPurify 默认放行 `<form>`，一个伪造的登录框贴在帖子里就能钓密码
4. KaTeX 异常分支原先把原始输入直接拼进 HTML，改为转义后再拼

**验证**（真实组件渲染攻击载荷，浏览器实测）：

```
xssFired: []          ← script / img-onerror / svg-onload / iframe-js
                         / a-href-js / body-onload / css-js 全部没执行
scriptTags: 0   iframes: 0   forms: 0   inlineHandlers: 0
jsHrefs: ["https://example.com", null]   ← javascript: 被剥成 null
katexRendered: 2   tables: 1   codeBlocks: 1   ← 正常内容无损
```

### P0-3 — 生产单端口部署时首页和管理端路由是坏的

**问题**：`acm_oj/urls.py` 把老的 Django 模板站挂在 `''`，排在 SPA catch-all 前面。实测 `resolve()`：

```
/              -> judge.views.auth.index          ← 老模板首页，不是 Vue
/admin/login   -> django.contrib.admin catch_all  ← Vue 管理端登录进不去
/admin/users   -> django.contrib.admin catch_all  ← 同上
```

开发时 Vite 顶在前面所以看不出来，`npm run build` 之后按单端口跑就会暴露。同时那套老站是完全重复的第二套攻击面，且没享受到阶段十五加的限流。

**修复**：

- **删除整套旧模板站**：`judge/urls.py`、`judge/views/`（6 个模块 + `__init__`）、`judge/forms.py`、`judge/templatetags/`、`judge/templates/judge/` 下 18 个 html、`judge/static/`——共 37 个文件、15613 行
- Django 后台从 `/admin/` 移到 `/django-admin/`，把 `/admin` 让给 Vue 管理端
- SPA catch-all 排除项同步改为 `api/|django-admin/|static/|assets/`

**顺带修掉的白屏**：catch-all 原先把 `/assets/*` 也吞了，js/css 全被回成 index.html，浏览器按 MIME 拒绝加载。这个洞在原正则里就有，只是没人这样跑过。补了 assets 与 favicon 的静态路由。

> `django.views.static.serve` 只适合自用规模；正式对外应由 nginx 直接托管 `frontend/dist`，或引入 WhiteNoise。

**验证**（单端口 `runserver` 实测）：

```
/                → SPA 正常渲染（接口全通）
/assets/*.js     → 200  168534 字节（修复前是 428 字节的 index.html）
/admin/users     → SPA   ← 修复前是 Django admin 的 404
/django-admin/   → Django 后台
样式表已加载：293 条 + 112 条规则，Vue 已挂载
```
