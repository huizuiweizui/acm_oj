# 阶段二十五：完善给学生推荐题目的算法

分支：`feat/star-integration`。两处推荐：星语教师端"推荐下一项任务"的规则分支重写；OJ 首页"今日推荐"从写死的假数据换成真实接口。

## 一、星语：规则分支（`star/services/recommend.py`）

阶段二十四的规则分支只看"做对步数 ≥ 3 且平均提示等级 ≤ 1"，按素材库顺序取前 3。问题：

- 不看错误次数：不看提示但每步错很多次也算掌握；
- 早期吃力的记录一直拉高平均值，提示渐褪之后仍判为没掌握；
- 只看素材的主知识点：「偶数之和」主知识点是循环，但前两步要写条件，条件没学时也会被推荐。

现在：

```
每步得分 = (1 − 提示等级/3) × max(0.25, 0.75 ^ 做对前错的次数)    没做对的步骤 = 0
掌握度   = 按时间加权平均（最近一步权重 1，每往前一步 × 0.8）
状态     未学（无记录） / 薄弱（< 2/3） / 学习中（分数够、做对 < 3 步） / 已掌握
目标     路线（顺序 → 条件 → 循环）上第一类没掌握的
分组     目标类 → 下一类预习 → 已掌握类复习；用到没学 / 薄弱知识点的素材 = 前置不足，放最后
组内     用到几类知识点、几步，从易到难；相同时按素材库顺序
配额     学习中：目标类 2 + 预习 1；未学 / 薄弱：3 项都是目标类；全部掌握：综合题优先，再复习最弱一类
```

- 有已布置却没做完的任务时，总结里加一句提醒。
- 返回值新增 `mastery`（各类状态、掌握度、做对 / 作答步数），教师端推荐卡片上显示为一行徽标。
- P6 的作答统计里加了掌握度，候选素材加了 `uses`（各步用到的知识点），系统提示词第 2 条按此改写。
- 没作答记录时推荐结果与阶段二十四一致（`sum_two`、`double`、`minutes`）。

## 二、OJ 首页：今日推荐（`judge/services/recommend.py`）

`GET /api/recommend/?n=3`（需登录），三档依次填满：

1. **作业**：所在团队进行中的作业里还没通过的题，截止近的在前（理由："作业《第一周》里的题，还有 3 天截止"）。
2. **重做**：最近 14 天交过没通过的题，最多 1 道（"上次结果是 WA，再试一次"）。
3. **练习**：其余公开、没通过的题打分取最低：
   - 水平 = 通过 ≥ 3 道的最高难度，这一档通过满 8 道就往上挑一档；离目标难度越远扣分越多，比水平低的扣得更多；
   - 交过没通过的题按标签计数，带这些标签的题加分；没通过过的标签小幅加分；
   - 通过率高的优先（提交 < 5 次按 0.5 算）；
   - 按"用户 + 日期"定种子加一点随机：同一天结果稳定，第二天换一批。

前端 `HomeView` 登录后取 5 道，`RecommendCard` 显示类型徽标（作业 / 再试一次 / 练习），可"换一道"。接口失败时保持原来的占位数据。
