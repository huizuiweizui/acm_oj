## 一、项目背景（必读上下文)

你正在为一个已有的 Django 在线评测平台（OJ）添加功能。项目现状：

- **技术栈**：Django 4.2 + MySQL 8，前端为 Django 模板（HTML + 原生 JS），已集成 Monaco Editor、ECharts、marked.js、KaTeX，已有暗色/亮色主题切换。
- **现有用户体系**：使用 Django 内置 `User`，通过 `UserProfile`（OneToOne，`related_name='profile'`）扩展，现有字段：`avatar_url, avatar_color, role, ac_count, submit_count, rating, bio`。`role` 目前只有 `('user', '普通用户')` 和 `('admin', '管理员')` 两种。
- **核心模型**：`Problem`（含 8 级洛谷式难度 `difficulty`，多对多关联 `Tag` 标签即知识点）、`Submission`（状态含 AC/WA/TLE/MLE/RE/CE/NT，含耗时、内存、AI 反馈字段）、`Contest`、`Discussion` 等。
- **现有统计写法参考**：排行榜页面 `judge/views/user.py` 中的 `leaderboard()` 直接从 `Submission` 表实时聚合 AC 数（`values('user_id').annotate(cnt=Count('problem_id', distinct=True))`），新功能的统计必须沿用这种**实时聚合**思路，**不要依赖** `UserProfile.ac_count` 等冗余字段（存在已知的双重计数问题，数据不可信）。

**实现总约束：**

1. 不要重构现有架构、不要引入 Vue/React，全部使用现有 Django 模板风格，页面风格与现有页面保持一致（复用现有 base 模板、CSS 变量和暗/亮主题）。
2. 修改已有文件时，**只输出变更的代码片段**（标明文件路径和插入/替换位置），不要重新生成整个文件；新建文件可完整输出。
3. 所有数据库变更通过 Django migration 完成，涉及已有数据的要写数据迁移（RunPython）。
4. Excel 处理使用 `openpyxl`，不要引入 pandas。
5. 所有后端接口必须做服务端权限校验，不能只靠前端隐藏入口。

## 二、总体目标

将平台用户分为三端：**学生端、教师端、管理员端**，并实现以教师为中心的「团队（班级）」体系：教师创建团队、管理成员（审核申请 / 单个添加 / Excel 批量导入）、在一个总览页查看全班刷题情况（排名 + 各难度题数），并可下钻查看单个学生的知识点级刷题明细；队长可只读查看团队数据。

## 三、角色体系

1. 将 `UserProfile.ROLE_CHOICES` 改为：

```python
ROLE_CHOICES = [
    ('student', '学生'),
    ('teacher', '教师'),
    ('admin', '管理员'),
]
```

2. 编写数据迁移：把现有 `role='user'` 的记录全部迁移为 `'student'`。
3. 权限为包含式：admin ⊇ teacher ⊇ student。管理员可访问教师端所有功能。
4. **教师身份获得方式**：注册时不可自选教师；由管理员在管理端（Django Admin 或平台内管理页）将指定账号角色改为 `teacher`。
5. `UserProfile` 新增学籍字段：

```python
student_id = models.CharField('学号', max_length=30, blank=True, default='', db_index=True)
real_name  = models.CharField('真实姓名', max_length=50, blank=True, default='')
major      = models.CharField('专业', max_length=100, blank=True, default='')
grade      = models.CharField('年级', max_length=20, blank=True, default='')
```

6. 导航栏根据角色动态显示入口：学生看到「我的团队」；教师额外看到「教学管理」；管理员额外看到管理入口。

## 四、数据模型（新增）

新增四个模型（表名前缀沿用 `judge_`）：

### 1. Team — 团队/班级

字段：`name`（名称）、`description`（简介，可空）、`creator`（FK→User，创建教师）、`invite_code`（8 位唯一邀请码，创建时自动生成，教师可重置）、`need_review`（布尔，加入是否需审核，默认 True）、`is_active`（布尔）、`created_at`。

### 2. TeamMembership — 团队成员

字段：`team`、`user`、`role`（choices：`captain` 队长 / `member` 队员，默认 member）、`remark`（团队内备注，max_length=50）、`joined_at`。约束：`unique_together = ('team', 'user')`。

**备注显示规则（全局）**：团队相关的所有页面显示成员时，优先显示 `remark`，备注为空时退回显示 `profile.real_name`，再退回 `username`。

### 3. TeamJoinRequest — 加入申请

字段：`team`、`user`、`remark`（申请备注，**必填**，提示学生填写如「2023级 张三」）、`status`（pending/approved/rejected，默认 pending）、`reject_reason`（可空）、`reviewed_by`（FK→User，可空）、`reviewed_at`（可空）、`created_at`。

**核心业务规则**：审核通过时在**同一事务**内：① 创建 `TeamMembership`；② 将申请的 `remark` 自动写入 `membership.remark`（即"审核通过后备注自动加上"）；③ 更新申请状态与审核人。同一用户对同一团队只能有一条 pending 申请；已是成员的不能再申请。

### 4. TeamAnnouncement — 团队公告

字段：`team`、`author`、`title`、`content`（Markdown）、`created_at`。仅团队创建者可发布/删除，成员可见。

### 5. Assignment / AssignmentProblem — 作业（题单）

- `Assignment`：`team`、`title`、`description`（可空）、`start_at`、`deadline`、`created_by`、`created_at`。
- `AssignmentProblem`：`assignment`、`problem`（FK→Problem）、`sort_order`。
- 完成判定：不建冗余表，实时判定 —— 学生在 `[start_at, deadline]` 时间窗内对该题存在 `status='AC'` 的提交即视为完成；窗口外的 AC 单独标记为「补交完成」。

## 五、学生端功能

1. **我的团队**页：列出已加入的团队（显示团队名、教师、自己的团队内排名、自己的备注）。
2. **加入团队**：输入邀请码 → 显示团队名和教师确认 → 填写备注（必填）→ 提交申请；若团队 `need_review=False` 则直接入队（备注同样生效）。可查看自己的申请状态（待审核/已拒绝+理由）。
3. **团队详情**（成员视角）：团队公告、作业列表（含自己每道题的完成状态）、团队内 AC 排行榜（仅排名和 AC 数，不展示他人明细）。
4. 学生可主动退出团队（队长退出前需教师先转移队长身份）。

## 六、教师端功能

### 1. 教学管理首页

`/teach/`：我创建的团队卡片列表（成员数、待审核申请数角标），+ 创建团队按钮（填名称、简介、是否需审核，自动生成邀请码）。

### 2. 成员管理页

- 成员列表：备注、学号、姓名、加入时间、角色（队长标识）。
- 操作：移除成员、设置/取消队长（**每团队最多一名队长**）、编辑成员备注、重置邀请码。
- **申请审核**Tab：待审核列表（申请人用户名、备注、申请时间），操作：通过 / 拒绝（可填理由）。支持批量通过。

### 3. 添加学生 — 单个添加

按用户名或学号搜索已注册学生 → 直接加入团队（无需学生确认），备注默认填该生 `real_name`，教师可改。

### 4. 添加学生 — Excel 批量导入

- 提供**模板下载**（xlsx，四列：学号、姓名、专业、年级）。
- 上传后逐行处理：
  | 情况 | 处理 |
  |------|------|
  | 学号已绑定账号 | 将该账号加入团队（已在团队则跳过），并更新其专业/年级 |
  | 学号无账号 | 自动创建账号：用户名=学号，初始密码=学号，`role='student'`，写入学籍四字段，加入团队，备注=姓名 |
  | 数据不合法/学号在文件内重复 | 跳过，记入失败报告 |
- 自动创建的账号设置「首次登录强制修改密码」标记（`UserProfile` 加 `must_change_password` 布尔字段，登录后中间件/视图层拦截跳转改密页）。
- 导入结束展示结果报告：成功 N / 已存在 M / 失败 K（附行号与原因），整个导入过程对单行失败要容错，不能因一行错误整体回滚已成功的行（按行独立事务或先校验后写入）。

### 5. 团队总览页（核心页面）

`/teach/teams/<id>/dashboard/`，一个页面看到整体情况：

- **顶部汇总卡片**：成员数、团队总 AC（去重题目）、本周新增 AC、人均 AC、待审核申请数。
- **核心排名表**，默认按总 AC 降序：

  | 排名 | 备注(姓名) | 学号 | 总AC | 入门 | 普及- | 普及/提高- | 普及+/提高 | 提高+/省选- | 省选/NOI- | NOI+ | 总提交 | AC率 | 最近活跃 |

  - 各难度列 = 该生在该难度 AC 的去重题数（难度取自 `Problem.difficulty` 的 8 个等级，「暂无评定」并入一列或省略，自行合理处理）。
  - **时间范围筛选**：全部 / 本周 / 本月 / 自定义起止日期（筛选作用于提交时间）。
  - **排序切换**：总 AC、任一难度列、总提交数、AC 率。
  - 并列名次处理与现有 leaderboard 一致（同值同名次）。
  - 每行 AC 数后嵌一个迷你难度分布条（ECharts 或纯 CSS 均可）。
- **导出 Excel** 按钮：将当前筛选条件下的完整表格导出为 xlsx。
- **团队趋势图**：近 30 天每日提交数 / AC 数折线图（ECharts）。
- 点击学生行进入学生详情页。

### 6. 学生详情页（知识点下钻）

`/teach/teams/<id>/students/<user_id>/`：

- **顶部**：学生信息（备注、学号、专业年级）+ 难度分布柱状图 + 近 30 天提交热力图（GitHub 贡献图样式）。
- **主体：知识点列表**（知识点 = `Tag`），每个知识点一行，可展开：
  - 行摘要：`知识点名 ｜ AC x 题 / 尝试 y 题`（尝试 = 提交过的去重题数）。
  - 展开后列出该知识点下学生**提交过的所有题目**，每题显示：题号标题（链接）、难度、提交次数、最终状态（AC 显示「n 次提交后 AC」；未 AC 显示最近一次状态如 WA/TLE）。
  - **将「尝试但未 AC」的题目醒目标出**（如红色边框/图标），并在知识点排序上把「未 AC 比例高」的知识点排前面——这是教学上最有价值的信号。
  - 每题可点击跳转到「该学生在该题的提交记录」筛选视图。
- 一道题有多个 Tag 时在每个相关知识点下都出现（按知识点视角统计，不去重到单一知识点）。

### 7. 作业（题单）功能

- 教师在团队内创建作业：标题、说明、选题（从题库搜索添加、可排序）、起止时间。
- **作业完成矩阵**：行=学生（按完成数排序），列=题目，单元格三态：✅ 按时完成 / 🕐 补交 / ❌ 未完成（尝试中显示提交次数）。支持导出 Excel。
- 学生端作业页：题目列表 + 自己的完成状态 + 截止倒计时。

## 七、队长视角

- 队长由教师指定，每团队至多一名。
- 队长可访问：团队总览页、学生详情页、作业完成矩阵 —— **全部只读**，隐藏所有管理按钮（移除、审核、导入、编辑备注等）。
- 队长不可审核申请、不可增删成员。
- 实现上复用教师端模板，通过上下文变量 `can_manage` 控制管理控件渲染，后端接口同样校验。

## 八、权限实现要求

实现两个装饰器（或 Mixin）并应用到所有相关视图：

```python
@teacher_required      # profile.role in ('teacher', 'admin')
@team_viewer_required  # 满足其一：该团队 creator / 该团队 captain / admin
```

- 团队**管理类**接口（创建作业、导入、审核、移除、改备注、设队长、发公告）：仅 creator 或 admin。
- 团队**查看类**接口（总览、学生详情、作业矩阵、导出）：`team_viewer_required`。
- 所有接口必须校验「当前用户与该 team 的归属关系」，防止教师 A 通过改 URL 查看教师 B 的团队（水平越权）。
- 学生只能查看自己所在团队的成员视角页面。

## 九、统计查询实现要求

- 所有刷题统计**实时从 `Submission` 表聚合**，参考现有 `leaderboard()` 写法。禁止读取 `UserProfile.ac_count / submit_count` 冗余字段。
- 总览页核心查询示例（一次拿到全队 用户×难度 的去重 AC 数，避免 N+1）：

```python
Submission.objects.filter(user_id__in=member_ids, status='AC', submitted_at__range=...)
    .values('user_id', 'problem__difficulty')
    .annotate(cnt=Count('problem_id', distinct=True))
```

- 知识点统计通过 `problem__tags` 关联聚合，同样注意一次查询取回再在 Python 内组装，避免每个 Tag 一次查询。
- 为 `Submission` 补充组合索引 `(user, status, submitted_at)`（如不存在）。
- NT（无测试点）状态不计入 AC、不计入"尝试"统计中的有效结果（计入提交数即可）。

## 十、分阶段交付（每阶段单独完成并可验证）

1. **阶段1 — 角色与学籍**：ROLE_CHOICES 三角色 + 数据迁移（user→student）+ UserProfile 新字段（学籍四字段、must_change_password）+ 导航栏按角色显示 + 两个权限装饰器。
2. **阶段2 — 团队基础**：Team / TeamMembership / TeamJoinRequest 模型 + 教师创建团队 + 学生邀请码申请（含必填备注）+ 教师审核（通过时备注自动写入成员）+ 成员管理（移除/设队长/改备注）。
3. **阶段3 — 学生导入**：单个添加 + Excel 模板下载 + 批量导入（自动建号、首登改密、结果报告）。
4. **阶段4 — 团队总览页**：汇总卡片 + 排名表（难度列、时间筛选、排序切换）+ 趋势图 + Excel 导出。
5. **阶段5 — 学生详情页**：难度分布图 + 提交热力图 + 知识点下钻列表（含未 AC 标记）。
6. **阶段6 — 作业与公告**：Assignment 模型 + 创建作业 + 完成矩阵 + 学生端作业视图 + 团队公告。
7. **阶段7 — 队长只读视角**：can_manage 控制 + 后端只读校验 + 学生端「我的团队」完善。

每个阶段输出内容：① 模型/迁移变更；② 视图与 URL；③ 模板（与现有页面风格一致）；④ 一段手工验证步骤清单。
